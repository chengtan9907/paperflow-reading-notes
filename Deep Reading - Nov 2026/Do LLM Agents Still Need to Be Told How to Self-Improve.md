# Do LLM Agents Still Need to Be Told How to Self-Improve?

> ★★★★☆ 推荐阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：llm agents · self-improvement · self-regulated learning · self-generated curriculum

## 一句话总结

论文研究：在冻结 LLM、只提供基本工具、算力预算和总目标，且不预设自改进循环的条件下，能力足够强的模型能否自主构造基于文本上下文的自我学习算法，并在游戏及跨游戏、3D 导航迁移上体现效果。

## 摘要

> LLM agents increasingly drive their own learning. Self-improvement methods delegate variousNov components of model optimization to the models themselves. As models become more capable,
> this motivates a basic question: do these increasingly capable models still need us to specify
> 17 how they should self-improve? In this paper we study an autonomous paradigm in which,
> given basic primitives, resources, and a general goal for self-improvement, agents construct
> their own self-learning algorithm for context-based optimization. Using the setting of gameplay
> as a testbed, a frozen LLM agent is given a compute budget and tools for collecting experience
> and updating text documents, and allowed to freely experiment without an externally imposed
> loop or access to real-world data. We find that sufficiently capable models do self-improve[cs.LG] under these conditions, demonstrating strategies that align with classic cognitive frameworks
> for self-regulated learning and constructs from machine learning literature on self-generated
> curricula. Furthermore, we study the extent to which the learned text artifacts transfer to
> external benchmarks, observing improvement across different game horizons, mechanics, and
> 3D navigation. Project page: https://ssundaram21.github.io/self-org/.

Q1: 这篇论文试图解决什么问题？

【核心问题】
论文要解决的问题不是某个自改进方法能否提高分数，而是一个更上位的问题：当模型能力越来越强时，人类是否仍然需要规定它应该如何自改进。作者把自改进拆成一组通常由研究者设计的决策，包括收集什么经验、生成什么练习任务、如何组织课程、何时更新、更新到什么粒度、如何评估进展；然后把这些决策交给一个只有基本工具、算力预算和总目标的冻结 LLM 智能体。
【问题拆解】
1. 自主性边界：已有工作即使让模型生成数据、构造环境或改写工具，通常仍由人类规定自改进的外循环、奖励信号、更新频率或评价方式。论文要检验的是，去掉这些外部规定后，智能体能否自己形成一个可运行的学习算法。
2. 算法构造：这里的“算法”不是权重训练算法，而是基于文本上下文的优化程序，包括写游戏、试玩、记录 transcript、修改提示或策略文档、决定是否保留某次修改等。
3. 能力依赖：论文的关键限定词是“足够强”的模型。问题因此变成能力阈值问题：哪些模型在最少指导下会自改进，哪些模型不会，差异来自模型能力还是外部脚手架。
4. 迁移：在一个自生成游戏集合上学到的文本工件，是否只是对特定游戏过拟合，还是能迁移到不同游戏时长、不同机制乃至 3D 导航。
5. 安全与治理：如果模型能自主决定自改进方式，人类监督应放在目标设定、工具权限、预算约束还是过程审计上。
【与已有范式的区别】
论文 Intro 明确对比了两类设置：一类方法更新权重或 harness，并依赖外部数据，某些情况下还聚合隐藏评测的分数；本文则让模型在没有真实世界数据、没有外部 imposed loop 的条件下，从自身经验中改进文本上下文。这个对比把“自改进”从“人类设计好学习循环、模型只负责其中一步”推进到“模型自己决定学习循环长什么样”。
【隐含假设】
1. 文本上下文是足够的学习基质，冻结模型也能通过文档更新获得可测量的行为改进。
2. 游戏任务既能提供可验证的进展信号，又能代表更一般的开放式学习场景。
3. 总目标可以被智能体操作化，而不需要人类给出细粒度课程。
4. 算力预算和工具权限足以支撑有意义的自主实验。
5. 外部基准上的提升可以部分归因于学到的通用策略，而非基准污染或脚手架效应。
【评价难点】
“自改进”很容易被自生成任务难度、评估器偏差或文本工件的表面变化所混淆。论文需要用外部基准、行为指标和消融来区分真正的能力提升与自我评估幻觉。LLM judge 对 Zimmerman 自我调节学习阶段的标注也可能引入主观性，因此三组 teacher sessions 的结论应视为行为证据而非严格因果证据。
【边界与反例】
能力不足的模型可能无法形成有效课程，甚至生成过易游戏或无效更新；自生成课程可能退化；文本工件可能编码游戏特定捷径；预算消融若显示结果对预算高度敏感，则“自主性”与“资源投入”的归因需要重新权衡。当前检索片段没有给出具体数值和失败案例比例，这些边界需要回原文确认。

Q2: 有哪些相关研究？

【1. 自改进与自生成监督信号】
论文处在 LLM 自改进的大脉络中：模型生成训练数据、推理轨迹、反馈或课程，再用于改进自身。Intro 引用 Zelikman et al. 2022 等代表工作，说明这条线已经从“人类标注数据”转向“模型自生成数据并筛选回流”。本文的差异在于不预设数据生成和筛选的外循环，而是让智能体自己决定生成什么、保留什么、如何更新。
【2. 自生成环境与课程】
论文引用 Zhang et al. 2026a、Liu et al. 2026 等工作，涉及模型构造交互环境、生成任务或课程。这与本文的游戏试验台最接近：智能体不仅要玩游戏，还要写游戏、决定练习顺序。论文进一步把这种行为与机器学习中的 self-generated curricula 概念连接起来，并用行为指标观察课程是否出现。
【3. 工具与 harness 自我改写】
Intro 还提到模型重写自己的工具和 harness。Wang et al. 2022b 等被列入这一引用群。本文的工具集包括文件读写、游戏执行和 bash 等基本原语，但不把“改工具”本身作为核心，而是把工具当作智能体构造学习算法的资源。与直接改代码相比，本文更强调文本工件和上下文优化。
【4. 上下文优化与持久记忆】
虽然当前片段没有展开引用，但论文的机制显然与 prompt optimization、经验记忆、反思式文本更新、持久化文档等方向相邻。区别是：本文不让人类设计反思模板或更新规则，而是让 agent 在文件系统中自由组织提示、transcript、游戏文件和策略文档。
【5. 认知科学与自我调节学习】
论文明确使用 Zimmerman 的自我调节学习循环作为分析框架，把学习过程拆成若干子过程，并用 LLM judge 对 teacher sessions 进行标注。这条线把工程实验与认知科学概念连接起来，用“计划、监控、反思、调整”等维度解释为什么某些模型能自改进。
【6. 相邻但未充分展开的方向】
开放式智能体、autotelic agent、多智能体课程生成、安全沙箱内的自我修改、以及自改进的 scaling law，都与本文问题相邻。当前检索片段没有显示论文逐篇展开这些方向，因此这里只能作为研究定位，不能当作论文已完成的对比实验。整体上，论文的相关工作横跨自训练、环境生成、工具改写、上下文优化和认知科学，但其真正新颖处是把这些线索汇合成一个“无外部学习循环”的自主性测试。

Q3: 论文如何解决这个问题？

【总体设定】
论文让一个冻结的 LLM 智能体在文件系统中工作，给它基本工具、算力预算和一个关于自我改进的总目标，但不提供人类设计好的自改进外循环，也不提供真实世界数据。智能体可以写游戏、运行游戏、记录 transcript、修改提示或策略文档，并自行决定下一轮做什么。学习发生在文本工件中，而不是模型权重中。
【学习基质】
核心机制是 context-based optimization：智能体把经验写成可复用的文档，例如 play prompt、游戏文件、历史 transcript、策略说明或效率建议，然后在后续试玩中调用这些文档。片段中出现的 WRITE、PLAY、BASH 以及 game1.txt、game2.txt、transcript1、v15 等文件，说明智能体在维护一个持续演化的文本工作区。
【teacher-player 结构】
检索片段多次出现 teacher、teacher-player runs、teacher update budget 等词，显示论文把负责生成或更新学习材料的角色与执行游戏的 player 区分开来。合理推断：teacher 负责写游戏、组织课程、修改提示或策略文档，player 使用这些工件去玩；两者可能由同一模型的不同实例扮演。具体如何共享文件、是否始终分离，需要回 Method 确认。
【预算与消融】
片段显示默认 teacher update budget 为 20，另有 gameplay budget，并在 Appendix D.3 对二者做消融。Table 3 汇总 teacher-player runs 的设置。预算在这里不是次要工程参数，而是自主性的边界条件：更新太少可能无法形成课程，更新太多可能带来回归或资源浪费。
【评估设计】
论文先用 PuzzleScript-t20 这个包含 20 个短时域关卡的子集，检验模型在最少指导下能否自改进；然后分析 teacher 行为，包括游戏设计指标、游玩指标，以及用 LLM judge 标注的 Zimmerman 自我调节学习子过程；最后用 Claude Opus-5 等模型评估文本工件向不同游戏时长、不同机制和 3D 导航的迁移。
【分析逻辑】
论文不是只报告最终分数，而是把“是否会自改进”拆成可观察行为：是否生成有意义的练习任务、是否监控胜率、是否做小步编辑、是否进行回归测试、是否保留有效更新。这样可以把自主性与单纯的提示敏感度区分开。整体方法因此是“范式设定 + 行为刻画 + 迁移检验 + 预算消融”的组合，而不是单一算法模块。

Q4: 论文做了哪些实验？

【实验一：最少指导下的自改进】
论文在 PuzzleScript-t20 上让不同模型家族在相同基本工具和预算下自由实验，检验哪些模型能在没有外部学习循环的情况下提升自身表现。片段明确提到 Section 4.1 建立了“一类能力足够的模型可以在最少指导下自改进”的结论。
【实验二：teacher 行为与游戏设计指标】
论文算法化测量 teacher 的行为，包括游戏设计指标和游玩指标，并在 Figure 5 中比较不同模型家族。片段指出这些指标在不同模型家族间具有一致性，说明自改进行为不是某一个模型的偶然现象。
【实验三：与自我调节学习框架对齐】
论文用 LLM judge 对 Zimmerman 自我调节学习循环的子过程进行标注，每个模型平均 3 个 teacher sessions。片段显示会自改进的模型在大多数子过程上得分更高。这是一项行为相关性分析，用于解释“为什么这些模型能自改进”，而不是严格的因果干预。
【实验四：跨基准迁移】
论文使用 Claude Opus-5 评估从自学习设定到外部基准的迁移，覆盖不同游戏时长、不同游戏机制和 3D 导航。片段只给出方向性结论：观察到 improvement，但没有给出统一提升幅度，因此不能推断所有任务都同等受益。
【实验五：预算与更新粒度消融】
Table 3 汇总 teacher-player runs 的设置，Appendix D.3 对 teacher update budget 和 gameplay budget 做消融。片段还提到 Opus 和 GLM 的新版本偏好更小的上下文更新，说明更新粒度是论文关注的关键变量。
【实验六：定性 transcript 与工件演化】
片段中的 agent 会做小编辑、进行最终回归测试、尝试随机化搜索，并把内容写进文件。这些 transcript 用于展示智能体如何组织工作流，但也提醒读者：文本工件的表面变化不等于能力提升，需要结合外部评测判断。

当前检索证据没有给出主要实验的具体数值、基线列表、置信区间或完整模型清单。上述实验分类依据摘要、Intro 和 References 片段整理；具体实验规模、评价指标定义和显著性结果需要回原文核对。

Q5: 发现了什么实验现象？

1. 能力阈值现象明显。论文的核心结论不是“所有 LLM 都能自改进”，而是“足够强”的模型可以。这个限定很重要：它把问题从普遍方法主张转化为能力依赖的实证现象，也意味着弱模型失败不应被简单归因于范式无效。
2. 自改进行为与认知框架存在对齐。会自改进的模型在 Zimmerman 自我调节学习的大多数子过程上得分更高，说明它们不只是更会玩游戏，还表现出计划、监控、反思和调整等行为。但这是 LLM judge 标注的相关性证据，不能直接证明这些子过程是性能提升的因果原因。
3. 不同模型家族的行为指标具有一致性。片段指出游戏设计和游玩指标在不同模型家族间保持一致，暗示自改进策略可能收敛到某些共同模式，例如先探索、再构造练习、再小步更新。不过，这种一致性也可能来自相同的工具脚手架和预算约束。
4. 自改进模型可能倾向于重复测试同一游戏或受控变体。片段中“Models that self-improve frequently test the same game...”后续被截断，无法确认完整含义；合理推断是它们通过重复练习或系统变化来积累经验，而不是不断切换到全新任务。这个现象需要回原文确认。
5. 更新粒度出现保守化趋势。片段提到 Opus 和 GLM 的新版本偏好更小的上下文更新。一个可能解释是：小步编辑更容易做回归测试、减少性能回退；另一个解释是模型学会了更谨慎的自我修改策略。具体机制尚未在证据中展开。
6. 并非每次更新都有效。片段提到统计“至少在一个自生成游戏上提高观测胜率”的更新，说明论文把更新有效性作为指标，也暗示存在大量无效或有害编辑。这与自改进文献中的常见失败模式一致：自我评估可能高估改进，文本修改可能引入回归。
7. 迁移是正向的但边界不清楚。论文观察到跨游戏时长、机制和 3D 导航的改进，说明文本工件可能包含可迁移的策略；但片段没有给出各基准的提升幅度，不能判断迁移是普遍、局部还是仅对某些任务有效。
8. 工件演化呈现元认知特征。transcript 中出现小编辑、最终回归测试、随机化搜索等行为，说明 agent 在工作区内形成了类似“提出假设—试验—验证—保留”的循环。这些定性证据很有解释力，但也可能被挑选展示，需要结合完整日志和失败案例分析。
9. 评估存在张力。自生成游戏可以被 agent 自己调难或调易，从而制造虚假进步；外部基准是对此的必要约束。LLM judge 的标注、3 个 teacher sessions 的样本量以及模型版本差异，都会影响行为结论的稳健性。
10. 预算消融将决定解释力度。如果自改进效果对 teacher update budget 或 gameplay budget 高度敏感，那么“自主性”带来的提升就与资源投入紧密耦合；如果低预算下仍能出现稳定改进，论文的主张会更强。当前证据只显示做了消融，未给出趋势。

Q6: 有什么可以进一步探索的点？

1. 能力阈值与 scaling 规律。论文只给出“足够强”的定性门槛，后续可以系统扫描模型规模、推理能力、上下文长度、工具使用能力与自改进成功率的关系，建立自主自改进的 scaling curve，并区分“会玩”与“会设计学习算法”两种能力。
2. 拆解自主性与脚手架。当前智能体仍有文件系统、bash、play 工具和预算约束。未来可以通过逐步移除工具、改变文件结构、限制可见历史、替换总目标表述，来判断性能提升来自模型自主构造还是来自人类设计的脚手架。
3. 从游戏走向可验证的真实任务。游戏提供廉价、可重复的反馈，但外部效度有限。可以把范式迁移到代码修复、数据科学、科学假设生成、实验设计或机器人任务，但需要解决奖励验证、环境安全和长时程信用分配问题。
4. 上下文优化与权重更新的结合。本文的冻结模型只在文本工件中学习，未来可以研究 agent 自主决定何时写文档、何时触发微调、何时调用外部工具，形成“上下文学习 + 参数学习”的混合自改进算法。
5. 自生成课程的退化与对抗。需要研究 agent 是否会生成过易、重复或奖励可被利用的课程，以及如何用外部验证集、课程多样性指标和对抗评估防止自我欺骗。论文的 self-generated curricula 视角可以进一步形式化为课程质量度量。
6. 迁移的机制与评测。文本工件中到底哪些内容迁移了：是通用的搜索策略、游戏机制知识、还是提示格式？未来可以做工件消融、跨任务检索、污染检测和细粒度误差分析，区分真正的策略迁移与基准记忆。
7. 安全、监督与权限设计。自主自改进带来奖励黑客、工具滥用、隐藏目标漂移和不可审计修改等风险。可以研究沙箱权限、预算上限、过程日志审计、人类审批节点和多模型交叉监督，把“是否还需要人类规定”转化为“人类应在哪些层面保留控制权”。
8. 多智能体共同演化。teacher-player 结构可以扩展为多教师、多玩家、竞争与合作课程生成，研究社会性学习、知识蒸馏和角色分工是否比单 agent 更有效，以及多 agent 是否会放大错误课程或评估偏差。
9. 计算分配与停止规则。agent 需要决定何时探索新游戏、何时重复练习、何时更新文档、何时停止。未来可以把预算分配建模为元学习或最优停止问题，研究不同停止规则对自改进效率和稳定性的影响。

Q7: 总结一下论文的主要内容

【研究问题】
论文从一个简单但尖锐的问题出发：当 LLM 能力越来越强时，自改进是否仍然需要人类规定学习算法。现有自改进工作通常让模型生成数据、构造环境或改写工具，但外部的学习循环、课程结构、更新规则或评价方式仍由人类设计。作者追问：如果只给智能体基本工具、算力预算和一个总目标，它能否自己构造出基于上下文的自我学习算法。
【设定与方法】
论文使用冻结的 LLM 智能体，在文件系统中提供 WRITE、PLAY、BASH 等基本工具，让它自己写游戏、试玩、记录 transcript、修改提示和策略文档。智能体没有外部 imposed loop，也不能访问真实世界数据；学习发生在文本工件中，而不是权重更新中。检索片段显示论文区分 teacher 与 player 角色，并有 teacher update budget、gameplay budget 等预算参数；默认 teacher update budget 为 20，具体配置汇总在 Table 3，消融在 Appendix D.3。
【实验主线】
第一，论文在 PuzzleScript-t20 上检验不同模型能否在最少指导下自改进。第二，论文算法化测量 teacher 的游戏设计和游玩行为，比较不同模型家族。第三，论文用 LLM judge 对 Zimmerman 自我调节学习循环的子过程进行标注，每个模型平均 3 个 teacher sessions，分析自改进模型的行为特征。第四，论文用 Claude Opus-5 评估文本工件向不同游戏时长、不同机制和 3D 导航的迁移。第五，论文通过预算消融、更新粒度和模型版本比较，刻画自改进的条件与边界。
【主要发现】
论文发现，能力足够强的模型可以在这种自主设定下实现自我改进，其策略与经典自我调节学习框架和机器学习中的自生成课程概念相吻合。会自改进的模型在大多数自我调节子过程上得分更高，游戏设计和游玩指标在不同模型家族间具有一致性。文本工件还能在一定程度上迁移到不同游戏时长、机制和 3D 导航。片段还显示，Opus 和 GLM 的新版本偏好更小的上下文更新，说明更新粒度是重要变量；论文也统计了真正提高至少一个自生成游戏胜率的更新，暗示并非每次编辑都有效。
【论证贡献】
论文的贡献主要不是提出一个固定算法，而是建立一个自主性测试范式：把“如何自改进”从人类设计中移除，观察模型能否自己形成课程、监控进展、编辑工件并保留有效经验。它把工程实验与认知科学的自我调节学习框架连接起来，并用外部基准检验文本工件的迁移。这使得论文同时具有方法探索、行为分析和评测框架三重意义。
【边界与待核实】
论文的试验台仍是游戏，外部效度有限；“足够强”的能力阈值需要更细的模型扫描；LLM judge 标注和 3 个 teacher sessions 的样本量可能影响行为结论；迁移的幅度、失败案例比例、预算消融趋势和基线设置在当前检索片段中不完整。总体而言，论文给出的是一条强问题意识和初步实证证据，而不是已经解决自主自改进所有问题的终局答案。
