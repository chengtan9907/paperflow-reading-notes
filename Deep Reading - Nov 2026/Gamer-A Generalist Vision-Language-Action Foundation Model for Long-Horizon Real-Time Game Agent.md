# Gamer: A Generalist Vision-Language-Action Foundation Model for Long-Horizon Real-Time Game Agent

> ★★★★☆ 推荐阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：vision-language-action · game agent · long-horizon interaction · multi-turn reinforcement learning

## 一句话总结

Gamer 是一个面向长程实时游戏任务的通用视觉-语言-动作基础模型，它把大规模设备级键鼠轨迹继续预训练、稀疏思考指令微调、稳定的多轮强化学习与云边流式推理整合为统一框架，并在多种 2D/3D 游戏中验证跨游戏控制与长程任务执行能力。

## 摘要

> 一、目标
> Gamer 面向复杂交互环境中的长程任务，目标是构建一个可同时处理传统 2D 图形界面与复杂 3D 模拟世界的通用智能体，而不是为每个游戏写专用脚本。
> 二、架构
> 其端到端架构把感知、记忆管理和多步推理耦合在同一个策略回路中，并以共享的训练/部署管线支持两类环境。
> 三、训练分三段
> 1. 大规模继续预训练：数据来自数万小时的设备级键盘鼠标交互轨迹，覆盖模拟游戏与具身环境，使模型学习跨物理/虚拟域的环境动态。
> 2. 稀疏思考指令微调：在保留复杂决策所需推理的同时，压缩冗余计算。
> 3. 稳定的多轮强化学习：针对有限上下文窗口、rollout 误差累积和稀疏奖励优化长程交互。
> 四、部署
> 论文提出云边推理引擎与 Streaming-vLLM，支持大量模拟环境并发、无界上下文执行和低延迟在线推理。
> 五、结果
> Gamer 在多个高难度 3D 开放世界游戏中展现出与熟练玩家可比的操作效率与泛化能力，并在一系列传统 2D 游戏基准上取得有竞争力结果。作者据此主张：即使是看似重复的键鼠轨迹，在数据与算法 scaling 下也能带来显著能力增益，并可作为连接数字世界与物理世界的通用 agent 训练路径。

Q1: 这篇论文试图解决什么问题？

一、核心问题
Gamer 试图解决的是：如何用一个通用的视觉-语言-动作（VLA）基础模型，在复杂、长程、实时的交互环境中完成多阶段任务，而不是为每个游戏或每个任务写专用脚本。论文把“复杂交互环境”具体化为两类：传统 2D 图形界面与复杂 3D 模拟世界；把“长程”具体化为需要跨场景切换、对话、战斗、UI 操作和多里程碑推进的支线任务；把“实时”具体化为在线推理延迟、并发环境服务与在线 rollout。

二、为什么这个问题难
1. 感知到动作的 grounded 映射：模型只看到像素，输出设备级键盘/鼠标动作，不能读取游戏内部状态，也不能改游戏引擎；跨游戏还存在键位映射、镜头控制、UI 布局和动作时序差异。
2. 长程记忆与上下文管理：任务跨度远超有限上下文窗口，早期对话、任务阶段、已完成子目标必须被压缩/写入长期记忆，否则会出现“忘记目标”“重复已完成步骤”。
3. 多步推理与实时性的矛盾：复杂决策需要推理，但每一步都生成长链思考会拖垮实时交互；论文用 sparse-thinking 指令微调来压缩冗余计算。
4. 长程 RL 的信用分配：奖励稀疏，成功往往在数百/数千步后才出现；多轮 rollout 会累积误差，有限上下文会截断历史，策略容易学到短视或投机行为。
5. 系统工程：大量模拟环境并发、无界上下文执行、云边协同和低延迟，这些不是纯算法问题，但会反过来影响训练数据分布和 RL 偏差。
6. 评价：跨游戏迁移有不同距离，in-domain 基准高分不等于开放世界泛化；长程任务成功率高也不代表子能力均衡。

三、现有研究的缺口
多模态大模型多数仍是静态输入处理器；VLA 工作多集中在机器人操作/导航，动作空间和任务时长有限；游戏 agent 往往依赖特权状态、游戏 API 或专用奖励，难以跨游戏；现有基准要么偏 2D/简化模拟器，要么只测短程控制。论文试图用统一设备级接口、大规模键鼠轨迹预训练、长程记忆、多轮 RL 和实时 serving 把这些缺口串起来。

四、隐含假设与边界
论文隐含假设包括：游戏是可控制、可重复、足够复杂的 agent testbed；键鼠轨迹虽低层重复，但蕴含可迁移的环境动态与控制先验；环境侧任务验证可用于 RL 奖励；云边架构的延迟可接受。需要特别注意：长程评测虽然排除了具体评测目标，但仍发生在“熟悉的游戏”内，不是零样本迁移到完全未见过的游戏；物理世界迁移也未被系统评测。

五、评价设计上的难点
长程任务成功的判定需要里程碑级验证；重复三次取平均只能部分缓解方差；与通用大模型比较时，后者并非游戏专用，比较是“通用能力 vs 专用训练”的对照，不能直接推导模型架构优劣。

Q2: 有哪些相关研究？

一、多模态大模型与交互式 agent
论文把 MLLM 的发展概括为从静态输入处理器走向可操作数字/物理环境的交互式 agent（引言引用 [2,6,7,13,25,45]）。这一脉络的核心问题是：视觉-语言理解如何落到动作上，以及如何在多轮交互中保持目标、记忆和推理一致性。Gamer 的差异在于把动作空间压到设备级键鼠，而不是只做问答或 API 调用。

二、VLA 与具身智能
VLA 模型（引用 [24,28,46,58]）把视觉观测、语言指令和动作统一到一个策略中，是通往具身 AGI 的候选路径。既有工作多在机器人操作、导航或简化仿真中验证，动作空间通常是关节/末端执行器/离散技能；Gamer 把 VLA 扩展到 2D GUI 与 3D 游戏，动作是键盘鼠标，且强调长程任务与实时部署。

三、游戏智能体与基准
现代大型游戏（引用 [4,11,32,47,59–61]）提供比传统 2D 游戏、网页界面和简化模拟器更复杂的感知、3D 布局和多阶段任务。论文使用 MCU [63]、ViZDoom [52]、OmniGameArena [23]、GameWorld [32] 等公开基准，并保留各基准原生指标。这些基准的迁移距离不同：MCU/ViZDoom 更接近 CPT 覆盖的游戏域，OmniGameArena 测未见过但语义相关的 3D 游戏，GameWorld 的视觉、控制机制和任务结构偏移更大。

四、长程记忆与 LLM agent 强化学习
长程 agent 的常见路线包括上下文压缩、外部记忆、层次化规划、工具调用和多轮 RL。Gamer 的记忆更新由任务阶段变化、子目标完成、旧交互即将离开上下文触发；RL 侧则要处理有限上下文、rollout 误差累积和稀疏奖励。检索片段没有展开具体对比工作，因此这里只能按问题脉络归纳，不能逐篇断言差异。

五、实时推理与服务系统
实时 agent 需要低延迟、高并发和流式输出。Streaming-vLLM 及云边推理引擎属于“推理系统与 agent 算法协同”的路线：服务延迟不仅影响用户体验，还会改变在线 rollout 的分布，进而给 RL 引入偏差。

六、agent scaling 研究
论文的 GameScaling 用 120 个 CPT 配置研究模型规模、gameplay budget 和数据组成，并在 Dense/MoE 骨干上评估可执行跨游戏性能。这与只报单一配置的工作不同，更接近系统性 scaling 研究。

七、与 Gamer 的定位差异
Gamer 把“统一设备级接口、2D/3D 环境、长程记忆、多轮 RL、实时 serving、跨游戏 scaling”放在一个框架里；其卖点不是单一游戏刷分，而是通用性与可部署性。代价是系统复杂、数据与算力成本高，且跨游戏零样本与物理迁移仍需进一步验证。

Q3: 论文如何解决这个问题？

一、总体架构
Gamer 是一个端到端 VLA 策略：输入视觉观测与任务指令，内部维护记忆和多步推理状态，输出设备级键盘/鼠标动作。论文强调同一套训练与部署管线同时支持传统 2D 图形界面和复杂 3D 模拟世界，而不是为每类环境维护独立 agent。

二、统一动作接口与跨游戏控制
动作空间是键盘和鼠标，模型不读取特权游戏状态，也不修改游戏引擎。为降低跨游戏键位差异，论文把语义动作（如左右移动）映射到共享动作表示，并采用随机键位重映射，让模型不依赖某个具体按键的身份。另一个细节是 repeat-aware loss decay：对时间上持续/重复的动作降权，避免大量重复按键或空操作主导损失（“避免主导”是合理推断，原文只明确说 reweights temporally persistent actions）。

三、大规模继续预训练（CPT）
训练数据是数万小时的设备级键鼠交互轨迹，覆盖模拟游戏与具身环境，使模型学习跨物理/虚拟域的环境动态。论文没有在片段中给出精确小时数、游戏清单和数据配比，只说明规模是“tens of thousands of hours”。CPT 在 Dense 与 MoE 骨干上评估；表 6 把 Qwen3-VL-8B (Base) 与 Gamer-CPT 并列，合理推断至少有一个 8B dense 版本以其为初始化，但完整模型矩阵需查原文。

四、长程记忆管理
系统维护长期记忆 Mt，并在三种时机更新：任务阶段变化、子目标完成、旧交互即将离开活跃上下文。这样可以把跨场景的对话、任务状态和已完成步骤压缩到上下文之外，支撑“无界上下文”执行。片段没有说明记忆的表示形式、检索方式和压缩率，这是需要回原文核对的关键实现细节。

五、稀疏思考指令微调
SFT 采用多级指令：同一动作策略要跟随局部操作、中间子目标和更长任务序列。sparse-thinking instruction tuning 的目标是减少冗余推理计算，同时在复杂决策处保留必要推理。它区别于“完全不做推理”的纯反应式策略，也不是简单的输出 token 剪枝；具体触发条件、思考预算和训练信号在片段中未展开。

六、稳定的多轮强化学习
RL 阶段针对三个问题：有限上下文窗口、rollout 误差累积、稀疏奖励。训练时从实时环境收集在线 rollout，并用环境侧任务验证提供奖励；推理时则不依赖特权状态。Streaming-vLLM 在这里不仅是部署工具，还通过降低在线推理延迟减少 latency-induced bias。具体优势估计、奖励塑形、上下文截断策略和稳定性技巧未在片段中给出。

七、云边推理引擎
部署侧支持大量模拟游戏环境并发、无界上下文执行和低延迟在线推理。云边分工的具体边界（哪些层在云、哪些在边缘、如何调度）片段未说明，但可以确认它服务于训练期 rollout 和部署期交互两条链路。

八、证据缺口
精确模型规模、CPT 数据配方、记忆读写算法、sparse-thinking 的门控机制、RL 目标函数与奖励设计、并发/延迟指标，均未在检索片段中完整出现；这些是实现复现和判断泛化性的关键，阅读原文时应优先核对。

Q4: 论文做了哪些实验？

一、实验组织
论文把评测分成三条互补问题：第一，GameScaling 用 120 个 CPT 配置刻画模型规模、gameplay budget 和数据组成的影响；第二，评估 Dense/MoE 骨干上 CPT 策略的可执行跨游戏性能；第三，在单独训练的 HSR-augmented Gamer-CPT 及其 SFT/RL 后继上评估 HSR 支线任务与小游戏，把“广泛交互技能”和“长程任务执行”分开；第四，测试实时 rollout 是否支持在线学习，以及 Streaming-vLLM 是否达到持续交互所需的准确率与延迟。

二、GameScaling
这是论文最有系统性的实验设计之一：120 个 CPT 配置，变量包括模型规模、gameplay budget、数据组成；骨干覆盖 Dense 与 MoE。检索片段没有给出 scaling 曲线和具体结论，因此不能编造“规模越大越好”或“数据配比如何最优”的细节；但可以确认论文把“数据规模/模型规模/数据组成”作为独立维度来研究，而不是只报一个最终模型。

三、公开游戏基准
使用 MCU、ViZDoom、OmniGameArena、GameWorld。论文保留各基准的任务定义、环境设置和原生评分协议。四者的迁移距离被明确区分：MCU 与 ViZDoom 覆盖 CPT 中出现过的游戏域，主要测控制学习；OmniGameArena 测未见过但交互语义相关的 3D 游戏；GameWorld 的视觉外观、控制机制和任务结构偏移更大，是更远的跨游戏迁移。这个设计比单一 in-domain 分数更能说明泛化边界。

四、HSR 长程支线任务
Table 6 评估两个支线：Opportunity Makes the Thief (Part I) 与 Bestial Ferocity，分别含 30 和 55 个 milestone。每个任务重复 3 次，报告平均成功率，总体 Acc 用成功任务执行数除以所有评测执行数，并跨重复尝试汇总。表中总体 Acc：Qwen3-VL-8B (Base) 13.9%，Gamer-CPT 47.9%，Gamer-SFT 69.1%，Gamer-RL 83.6%；通用模型 Gemini-3.8-Flash 45.5%，GPT-5.6-Sol 41.8%，Claude-Opus-5.0 29.1%，DeepSeek-V4-Flash-Vision 27.3%，GPT-5.6-Luna 23.6%，GLM-5.3-Flash 23.6%。SFT 显著提升长程执行，片段还明确提到某支线 overall accuracy 从 0.0% 开始提升（终点被截断）。

五、HSR 小游戏
小游戏评估包括七类：Magflow Link (ML)、Navigation Compass (NC)、Abacus Circuitry (AC)、Hexanexus (HX)、Janus’s Hidden Passage (JHP)、Golden Scapegoat (GS)、Janus’s Maze (JM)。表中逐项报告 Acc，用于区分广泛交互技能与长程任务执行；Online RL 进一步提升长程执行。具体每类分数在片段中只露出表头，未完整列出，不能编造。

六、实时在线学习与推理服务
论文测试实时 rollout 收集是否支持在线学习，以及 Streaming-vLLM 是否提供持续交互所需的准确率与延迟。结论部分明确说 Streaming-vLLM 支持训练和部署、实现在线 rollout，并减少 latency-induced bias。片段没有给出吞吐、P99 延迟、并发环境数等具体指标，需要查原文。

七、2D/3D 综合表现
摘要称在多个挑战性 3D 开放世界游戏中表现出与熟练玩家可比的操作效率与泛化，并在一系列传统 2D 游戏基准上取得有竞争力结果。图示覆盖开放世界 RPG、回合制 RPG、动作 RPG、吃鸡、MOBA、沙盒生存等类型，并点名 Genshin Impact、Honkai: Star Rail、Zenless Zone Zero、PUBG、Dota 2、Minecraft、Terraria、Palworld 等；但这些是任务覆盖面示意，不等于全部做了等量定量评测。

CPT→SFT→RL 的三段式比较本身构成训练阶段消融；但 sparse-thinking、记忆更新、随机键位重映射、repeat-aware loss decay 的独立消融在片段中未完整出现。论文还缺少可见的人类基线细节、统计显著性检验和所有基准的逐项分数。阅读原文时应重点核对：Table 6 的完整表头、GameScaling 的 scaling 曲线、OmniGameArena/GameWorld 的具体迁移跌幅、以及实时系统的延迟指标。

Q5: 发现了什么实验现象？

一、三阶段训练呈阶梯式提升，且每一段都有独立贡献
Table 6 的总体 Acc 从 Qwen3-VL-8B Base 的 13.9% 提升到 Gamer-CPT 的 47.9%，再到 Gamer-SFT 的 69.1%，最后到 Gamer-RL 的 83.6%。按表中数值粗算，CPT 带来约 34.0 个百分点，SFT 约 21.2 个百分点，RL 约 14.5 个百分点。这说明大规模键鼠轨迹预训练不是“可有可无的热身”，而是把通用 VLM 拉到游戏控制分布上的关键一步；SFT 与 RL 则分别补长程任务执行和多轮优化。

二、SFT 是长程任务的关键拐点
论文明确说 SFT substantially improves long-horizon task execution，并提到 Opportunity Makes the Thief (Part I) 的 overall accuracy 从 0.0% 开始提升（片段截断，终点未显示）。这与表中的趋势一致：CPT 已经能在某些控制维度拿到很高分（例如 Combat 列出现 100.0），但总体仍只有 47.9%，说明“会按键/会战斗”不等于“能按里程碑推进多阶段任务”。SFT 的多级指令（局部操作、中间子目标、长任务序列）更像是在教模型把控制原语组合成任务语义。

三、RL 主要增强长程执行，但并非全面均衡
Gamer-RL 总体达到 83.6%，高于 SFT 的 69.1%；结论也说 Online RL further strengthens long-horizon execution。但表中 Gamer-RL 仍有一个子项只有 11.1%，与 83.6% 的总体形成明显张力。由于检索片段把表头截断，无法确认该列是 UI、某一支线还是某一交互类型；如果是 UI/特定界面操作，则说明高分主要来自导航、对话、战斗等强项，UI 或长尾交互仍是瓶颈。这个“总体高、子项低”的现象比单一总分更值得关注。

四、CPT 的“控制强、组合弱”现象
Gamer-CPT 在部分交互维度上已经很强（表中可见 100.0），但总体只有 47.9%；SFT 才把总体推到 69.1%。这揭示了一个有价值的现象：大规模轨迹预训练可以学到跨游戏的视觉-动作先验和底层控制，但长程任务需要任务条件化、记忆和层次化指令来把先验组织起来。换言之，CPT 解决“怎么动”，SFT/RL 解决“为什么动、下一步做什么”。

五、跨游戏迁移被设计成梯度，而非二值判断
MCU/ViZDoom 是 CPT 覆盖域，OmniGameArena 是未见过的 3D 游戏但交互语义相关，GameWorld 是更远的跨游戏迁移。这个设计本身揭示了一个重要评价现象：in-domain 高分不能代表开放世界泛化；随着视觉外观、控制机制和任务结构偏移增大，性能大概率下降（合理推断，片段未给具体跌幅）。论文没有把“跨游戏”简单说成通过/不通过，而是拆成迁移距离，这是比较扎实的实验设计。

六、熟悉游戏内的长程泛化，而非零样本新游戏
片段明确说：任务条件化推理和记忆可以支持这种行为“in a familiar game, even when the specific evaluation objectives were excluded from training”，并紧接着限定“rather than zero-shot transfer to an unseen game”。这是一个关键的正面现象：模型不是靠背评测轨迹，而是能在同一游戏内组合已有技能完成未训练过的目标；但边界也很清楚——它还不是任意新游戏的零样本 agent。

七、推理延迟会变成 RL 偏差，系统与算法必须协同
结论把 Streaming-vLLM 的作用写成“支持实时交互和高效在线 rollout，同时减少 latency-induced bias in reinforcement learning”。这揭示了一个反直觉但重要的现象：在线 RL 中，推理延迟不是纯工程指标，它会改变 rollout 的时间结构、动作后果和奖励分布，从而影响学习。把 serving 放进算法闭环，是这篇论文比较有辨识度的系统观察。

八、稀疏思考的效率主张仍需量化
论文声称 sparse-thinking instruction tuning 显著减少冗余计算，同时保留复杂决策所需推理。但片段没有给出 token 节省比例、延迟下降、准确率损失或“何时该思考”的触发曲线。因此目前只能把它视为一个合理但未量化的效率叙事；阅读原文应重点看它是否在长程任务上真的做到“省算力不掉点”。

九、通用大模型在游戏控制上明显吃亏
表中 Gemini-3.8-Flash 45.5%、GPT-5.6-Sol 41.8%、Claude-Opus-5.0 29.1%、DeepSeek-V4-Flash-Vision 27.3%，都低于 Gamer-SFT/RL。Gamer-CPT 47.9% 也已经略高于 Gemini-3.8-Flash。这提示通用视觉语言能力不等于设备级闭环控制能力；但比较要注意：这些通用模型并非为游戏控制专门训练，Gamer 使用了数万小时游戏轨迹，二者不是同预算对照。

十、数据 scaling 的经验主张
摘要说“even repetitive keyboard and mouse trajectories can support substantial gains from scaling data and learning algorithms”，并强调在物理/数字双重属性环境中更稳定地学复杂技能。这挑战了“键鼠轨迹太重复、缺乏语义、难以 scaling”的直觉。但片段没有给出数据量-性能曲线，也没有分离数据规模与数据多样性的贡献；这属于作者的核心经验主张，仍需 GameScaling 的完整结果支撑。

Q6: 有什么可以进一步探索的点？

一、把评测从“熟悉游戏内的长程任务”推进到真正的零样本跨游戏
当前最有说服力的长程结果仍发生在熟悉游戏内，评测目标被排除但游戏本身见过。下一步可以系统构造未见过的游戏、未见过的 UI 布局、未见过的控制机制，测 zero-shot 迁移；同时报告 in-domain、near-transfer、far-transfer 的分层结果，而不是只给一个总分。还需要人类基线、置信区间和统计显著性，避免小样本长程任务的方差被误读。

二、记忆机制从“触发式写入”走向可学习、可验证
现有记忆更新由任务阶段变化、子目标完成、上下文驱逐触发，属于比较手工的启发式。可以探索：可学习的记忆检索/压缩/遗忘；层次化记忆（情节记忆、语义记忆、任务图）；记忆忠实性评估（记住的是否真的是关键证据）；以及记忆错误如何传播到长程决策。对长程 agent 来说，记忆的“写什么、何时写、如何读”可能比模型规模更关键。

三、多轮 RL 的信用分配与奖励验证
长程 RL 仍受稀疏奖励、有限上下文、rollout 误差累积困扰。可探索更稳的多轮优势估计、分层 RL、课程学习、离线到在线混合、过程奖励与结果奖励结合、以及 reward hacking 检测。环境侧任务验证是 Gamer 的关键支撑，但在开放世界/真实环境中验证器本身难以扩展；如何用模型自验证、形式化里程碑、人类稀疏反馈替代，是重要的下一步。

四、实时系统的延迟-准确率-成本三角
Streaming-vLLM 与云边引擎解决了并发和低延迟的一部分问题，但仍有大量空间：异步推理、speculative decoding、动态思考预算、边缘缓存、模型分层部署、网络抖动下的 rollout 一致性。尤其要研究延迟如何影响 RL 的最优策略，而不仅把延迟当作工程指标。无界上下文执行也需要成本模型：记忆越长，检索和推理越贵，何时压缩/丢弃要有原则。

五、数据 scaling 与数据配方
论文用数万小时键鼠轨迹和 120 个 CPT 配置研究规模、gameplay budget、数据组成。后续可以进一步分离：数据量、游戏多样性、任务多样性、人类演示质量、合成数据比例各自贡献多少；是否存在“重复轨迹的收益递减”；哪些数据最适合迁移到新游戏/新界面。数据效率也很重要：能否用更少的小时数达到同样控制先验。

六、动作接口的通用化
当前是键盘鼠标，未来可以扩展到手柄、触屏、VR 控制器、机器人末端执行器，以及 GUI/API 混合动作。统一动作表示、随机键位重映射、repeat-aware loss decay 在更异构的动作空间是否仍有效，值得验证。若能把这些接口统一，游戏 agent 与办公自动化、科学软件操作、实验室自动化之间的迁移会更自然。

七、从游戏走向物理世界与科学应用
论文的数据包含具身环境，但主要评测仍在游戏。下一步应在真实机器人、实验室仪器、GUI 化科学软件上验证：感知噪声、动作延迟、不可逆操作、安全约束都比游戏更强。科学应用还需要可审计的验证器和人类监督，不能只靠环境侧奖励。游戏作为高保真、可重复的 testbed，可以先行验证长程记忆和多轮 RL，再迁移到物理世界。

八、安全、公平与对齐
游戏 agent 涉及账号安全、竞技公平、真实货币交易、聊天内容安全等问题。需要研究：动作级安全约束、权限隔离、异常行为检测、对手感知的公平性、以及多智能体环境中的欺骗/合谋。若 agent 能自动玩在线游戏，还需要明确使用边界，避免破坏其他玩家体验。

九、可解释性与失败归因
长程失败往往由感知错误、记忆错误、推理错误、控制误差或延迟累积共同导致。可以开发按模块的失败归因、记忆回溯、注意力/显著性可视化、反事实 rollout，帮助判断模型是“没看见”“忘了”“想错了”还是“手抖了”。这对 debug 和提升长程稳定性都很关键。

十、世界模型与 model-based RL
论文用大量轨迹学习环境动态，但策略仍主要是 model-free 的多轮 RL。未来可以把学到的环境动态显式化为世界模型，用于想象 rollout、反事实规划、分层子目标搜索，减少真实环境交互成本。风险是模型误差在长程中被放大，需要与不确定性估计和安全回退结合。

Q7: 总结一下论文的主要内容

一、论文定位
Gamer 是一篇系统性的 agent 论文，而不是单点算法论文。它要回答的问题是：能否用同一个 VLA 基础模型，在 2D 图形界面和复杂 3D 游戏里完成长程、实时、多阶段的任务？论文的答案是把“数据—预训练—指令微调—多轮 RL—推理服务”做成一条完整管线，并用跨游戏基准和 HSR 长程任务来验证。

二、问题背景
多模态大模型正在从静态输入处理器变成交互式 agent；VLA 被视为通往具身智能的路径。但真实物理世界的试错成本高、环境不可控，难以大规模 scaling。现代大型游戏提供了折中：既有复杂视觉、3D 布局和多阶段任务，又有可重复、可验证的环境。论文因此把游戏作为通用 agent 的 testbed，并强调设备级键鼠接口、无特权状态、无游戏引擎修改。

三、技术路线
Gamer 的端到端架构把感知、记忆管理和多步推理耦合起来。动作空间是键盘鼠标；为跨游戏复用，论文把语义动作映射到共享表示，使用随机键位重映射降低对具体按键的依赖，并用 repeat-aware loss decay 对时间上持续/重复的动作降权。训练分三段：
1. 大规模继续预训练（CPT）：数万小时设备级键鼠轨迹，覆盖模拟游戏与具身环境，学习跨物理/虚拟域的环境动态；在 Dense 与 MoE 骨干上评估，并用 120 个配置做 GameScaling。
2. 稀疏思考指令微调（SFT）：多级指令覆盖局部操作、中间子目标和长任务序列；sparse-thinking 减少冗余推理计算，同时保留复杂决策所需推理。
3. 稳定的多轮强化学习（RL）：针对有限上下文窗口、rollout 误差累积和稀疏奖励；用环境侧任务验证提供奖励，并从实时环境收集在线 rollout。
记忆方面，系统维护长期记忆 Mt，在任务阶段变化、子目标完成、旧交互即将离开活跃上下文时更新，以支撑无界上下文执行。部署方面，云边推理引擎与 Streaming-vLLM 支持大量模拟环境并发、低延迟在线推理，并减少延迟对 RL 的偏差。

四、实验主线
论文的评测分三层：
1. GameScaling：120 个 CPT 配置，研究模型规模、gameplay budget、数据组成；Dense/MoE 骨干。
2. 公开基准：MCU、ViZDoom、OmniGameArena、GameWorld，分别对应 in-domain、近迁移、远迁移；保留原生指标。
3. HSR 长程任务：两个支线（30/55 个 milestone，重复 3 次）和七类小游戏（ML、NC、AC、HX、JHP、GS、JM），比较 Gamer-CPT/SFT/RL 与通用大模型。
此外还测试实时 rollout 是否支持在线学习，以及 Streaming-vLLM 的准确率/延迟。

五、关键结果
Table 6 的总体 Acc 显示清晰阶梯：Qwen3-VL-8B Base 13.9%，Gamer-CPT 47.9%，Gamer-SFT 69.1%，Gamer-RL 83.6%。通用模型中 Gemini-3.8-Flash 45.5%，GPT-5.6-Sol 41.8%，Claude-Opus-5.0 29.1%，DeepSeek-V4-Flash-Vision 27.3%，GPT-5.6-Luna 与 GLM-5.3-Flash 均为 23.6%。SFT 显著提升长程任务执行，片段提到某支线 overall accuracy 从 0.0% 开始提升；RL 进一步提升长程执行。摘要还声称在多个 3D 开放世界游戏中操作效率与熟练玩家可比，并在传统 2D 游戏基准上有竞争力。

六、论文揭示的现象
最有价值的不是单一总分，而是几个结构性现象：
1. CPT 让模型“会动”，SFT/RL 让模型“会做任务”；CPT 在某些控制维度已能到 100，但总体只有 47.9%。
2. 长程能力在熟悉游戏内可以泛化到未训练过的评测目标，但不是零样本新游戏；论文自己做了这个边界限定。
3. 总体 83.6% 与某个子项 11.1% 并存，说明子能力不均衡，UI/长尾交互可能是瓶颈（表头截断，具体列需核对）。
4. 推理延迟会改变在线 RL 的分布，serving 不是纯工程问题。
5. 看似重复的键鼠轨迹在数据与算法 scaling 下仍有显著收益，这是对“低层动作数据缺乏语义”直觉的反驳。

七、边界与意义
Gamer 的意义在于展示了一条可复制的通用 agent 工程路线：统一设备级接口、大规模轨迹预训练、任务条件化 SFT、多轮 RL、实时 serving。它的边界也很明显：评测仍以游戏为主，跨游戏零样本和物理世界迁移未充分验证；RL 依赖环境侧验证器；数据与算力成本高；安全/公平问题未展开。对做 agent、长程记忆、多轮 RL、实时推理系统的读者，这篇论文的架构与实验组织比单个指标更值得读。
