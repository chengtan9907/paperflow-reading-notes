# ForecastGym: A Live, Controlled, and Replayable Benchmark for Forecasting Agents

> ★★★★☆ 推荐阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：llm forecasting agents · benchmark · web search · temporal leakage

## 一句话总结

ForecastGym 是一个“实时采集—受控回放—来源感知”的 LLM 预测智能体基准：它每两天抓取四个商业搜索 API 对公开预测市场问题的证据，冻结为可重放的状态序列，在结果揭晓后离线比较模型、记忆策略与搜索源，并揭示日期过滤并不能阻止结算后检索泄漏，最高可达 92% 的问题会被几乎直接暴露答案。

## 摘要

> 1. 论文关注的不是单一预测模型，而是如何评估“会搜索网页并基于检索证据做概率预测”的 LLM 智能体。预测表现同时取决于模型能力与检索到的证据，因此若每个系统在评测时自行实时搜索，模型差异、检索差异和记忆差异会混在一起。
> 2. 回溯式评测同样不可靠：日期过滤可能放入在目标时刻之后才更新的内容；历史网页快照也可能因今天的搜索索引和排序而被选择或排序，从而把未来信息泄漏进“过去”的证据。
> 3. ForecastGym 的设计原则是 Live、Controlled、Replayable、Source-Aware：问题在结果揭晓前处于开放状态；采集时固定查询计划与证据获取策略；每个时间状态都被冻结并可离线重放；每条证据保留搜索来源，便于按 provider 做对照。
> 4. 首版覆盖 150 个预测市场问题、614 个证据状态（每个问题在每个采集时点一个状态）和约 131k 条搜索结果；数据来自公开预测市场问题，采集对象包括四个商业网页搜索 API，采集节奏为每两天一次。
> 5. 论文做了结算后重查审计：用相同查询在结果已知后再次检索，即使施加其测试的日期过滤，仍有高达 92% 的问题返回几乎直接陈述结果的内容；日期过滤能降低泄漏，但不能消除泄漏，且不同 provider 均存在该问题。
> 6. 在冻结证据上重放时，所有被测 LLM 的预测准确率都落后于市场基准；但条件分析显示，当证据明确指向结果时，模型可以接近甚至超过市场。摘要将诊断指向“missed public …”，该句在提供的文本中被截断，合理推断是：差距更多来自公开证据的漏检、覆盖不足或证据到达/解释问题，而非单纯的推理能力不足，但完整结论仍需回原文核对。
> 7. 记忆与搜索源也是核心变量：片段显示记忆可能把模型锚定在错误读数上，而不使用记忆时预测会随状态剧烈跳动；不同搜索源在覆盖率、相关性、日期元数据和价格上存在明显差异，说明“来源”本身是评测维度，而不是可忽略的实现细节。

Q1: 这篇论文试图解决什么问题？

一、论文试图解决的核心问题
这篇论文要解决的是“如何可信地评估会使用网页搜索的 LLM 预测智能体”，而不是再训练一个更强的预测模型。用预测市场的公开问题做真实事件预测，天然具有时间性：在时刻 t 只能使用 t 之前可获得的证据，结果要到之后才揭晓。若评测把“模型能力”和“检索到的证据”混在一起，就无法判断一个系统变好是因为模型更强、搜索更广、记忆更好，还是仅仅因为它在评测时搜到了更多未来信息。

二、四类效度威胁
1. 泄漏式重建（leaky reconstruction）。回溯式检索看似可以用日期过滤恢复历史证据，但网页内容可能在 t 之后被更新，日期过滤只能约束“发布日期”而不能约束正文修订；更隐蔽的是，历史页面可能因今天的索引、链接关系和排序模型而被选中。即使保存了旧内容，也不能保证其当时可见、当时可检索、当时排序相同。
2. 实时评测的混淆。若每个智能体在评测时自行搜索，不同系统会看到不同证据集，模型比较就变成了“模型加检索策略”的联合比较；搜索源、查询计划、缓存、API 排序变化都会成为未控制变量。
3. 缺少时间演化记录。预测智能体的记忆策略需要在多个证据状态之间更新信念；只给最终快照无法评估“何时看到什么、如何随证据修正、是否被旧证据锚定”。预测市场问题在 resolution 之前证据会不断出现，静态数据集无法覆盖这一过程。
4. 来源不可比。不同商业搜索 API 在覆盖率、相关性、日期元数据、价格和排序上不同；若不固定查询与证据，只比较最终准确率，就无法把“搜索源质量”从“模型能力”中分离出来。

三、为什么现有评测范式不够
静态问答 benchmark 没有真实时间推进；纯 live benchmark 可复现性弱且容易混入检索差异；纯 retrospective benchmark 又容易泄漏。论文的立场是：需要同时具备 fixed evidence 与 evidence evolution record，即在结果未知时向前采集，在结果已知后冻结回放。这样既能保留真实时间顺序，又能让所有模型面对同一证据状态。

四、可推断的研究问题
从摘要和片段看，论文至少围绕四类问题展开：泄漏在日期过滤后还剩多少；冻结证据上 LLM 与市场基准谁更强；记忆策略是否帮助跨状态更新；搜索源对预测表现和证据质量有多大影响。片段中明确出现“RQ4: How much does the search source matter?”，因此 RQ4 是来源维度；其余 RQ 的具体编号与表述需回原文确认。

五、问题的难点与边界
难点在于：问题必须在结果揭晓前选定并持续采集；采集成本高；不同问题的 resolution 时间不同；API 行为会漂移；市场基准本身不是“真值”，而是集体信念与流动性、费用、信息效率的混合。论文的贡献是把评测装置做成可重放的证据状态机，而不是宣称解决了预测市场有效性或通用智能问题。由于提供的全文片段主要来自摘要、图表和局部实验段落，论文是否给出形式化定义、估计量或误差界，现有证据不足，不能代为断言。

Q2: 有哪些相关研究？

以下按问题域重建论文的相关研究位置；检索片段没有包含完整的 Related Work 章节，因此不把具体文献归属说死，只保留可由摘要和片段支持的线索。

一、LLM 事件预测与“超级预测者”智能体
一条主线是让 LLM 通过检索网页、阅读新闻和推理来做真实世界事件预测，并以概率或排序形式输出判断。相关研究通常关注：检索增强生成、工具调用、多步搜索、证据聚合、校准与 Brier 类评分。ForecastGym 与这类工作的区别是，它不主张某个新 agent 架构，而是提供一个让不同 agent 在同一证据序列上比较的评测环境。

二、Live benchmark 与 retrospective benchmark 的争论
live evaluation 的优点是时间上真实，缺点是难复现、不同系统检索路径不同，且历史结果会随时间变化。retrospective evaluation 的优点是便宜、可重复，缺点是有泄漏风险。摘要明确提到两类泄漏机制：日期过滤不能阻止 t 之后更新的内容进入；历史页面快照可能被今天的搜索索引选择和排序。引文编号 [8,22] 被用来说明日期过滤检索的泄漏，[24,34] 被用来说明历史快照受今日索引/排序影响；具体作者与论文题名在现有片段中不可见。

三、检索增强智能体的“检索 vs 推理”分解
RAG 与 tool-use 文献通常把最终表现拆成检索质量、证据选择和推理能力。ForecastGym 的受控回放正是为了做这种分解：固定 evidence-acquisition policy，让不同模型读同一批证据；再通过记忆消融和来源消融观察性能变化。它更接近“评测科学”而不是“新模型”，这与用户偏好系统性工作而非增量模型的方向吻合。

四、预测市场作为基准
论文使用 Polymarket 与 Kalshi 的公开可交易问题来落地真实预测市场。预测市场提供连续价格，可作为“市场基准”，但市场价不是客观真值：它受流动性、费用、参与者结构和信息效率影响。相关研究常把市场价当作强 baseline，并用 Brier score、log score、校准曲线比较人、模型与市场。ForecastGym 的“LLM 落后市场”应理解为在该基准与样本上的经验结果，而不是“LLM 永远不如市场”的普遍结论。

五、搜索 API 与来源感知评测
商业搜索 API 的覆盖、排序、日期字段、摘要质量和价格差异很大。传统 IR 评测关注 test collection、qrels 和 ranking metrics；ForecastGym 把 provider 作为显式维度，记录每个来源返回的内容，并允许在回放时按 provider 替换证据。这连接了 IR 评测、RAG 证据质量与 agent 预测三个通常分离的社区。

六、智能体记忆与信念更新
记忆策略研究关注：保留哪些历史证据、如何压缩、何时遗忘、如何处理矛盾。ForecastGym 的多状态序列使记忆可以被实验操控：同一问题在 t1、t2、t3…的证据逐步进入上下文，观察预测是否稳定、是否被旧证据锚定、是否能响应新信息。片段显示“记忆把模型固定在错误读数上，而市场继续上涨”，以及“无记忆时预测在状态间跳动”，这说明记忆的稳定性收益与响应性代价存在张力。

七、研究缺口
综合看，已有工作分别覆盖了 LLM 预测、live/retrospective 评测、RAG、搜索源比较或记忆机制，但缺少一个同时满足 live、controlled、replayable、source-aware 的公开基准。ForecastGym 的定位就是填补这一评测基础设施缺口：不是证明某个模型最强，而是让“模型、记忆、来源”在固定证据下可比较。

Q3: 论文如何解决这个问题？

一、总体思路：把评测做成“证据状态机”
ForecastGym 的核心不是提出新的预测网络，而是把预测任务拆成按时间推进的证据状态。对每个公开预测市场问题，在结果揭晓前每两天采集一次搜索 API 返回；每条返回保留查询、来源、时间、标题/摘要/正文片段等可回放信息。结果揭晓后，所有模型都在同一批冻结状态上离线运行，从而把“检索”从在线推理中剥离出来。

二、四条设计原则
1. Live：问题在采集时仍然开放，结果未知；避免用已经 resolved 的问题反向构造“预测”。
2. Controlled：采集时固定查询计划与证据获取策略；回放时所有被测系统面对相同证据，避免各自实时搜索造成混淆。
3. Replayable：每个问题在每个采集时点形成一个 evidence state；状态序列可重复回放，支持同一模型在不同记忆/来源条件下重跑。
4. Source-Aware：每条证据保留商业搜索 API 来源；可以按 provider 替换或分组，比较 Tavily、Exa、Serper 等来源的覆盖、相关性和时效差异。摘要明确说有四个商业 API；片段可辨认 Tavily、Exa、Serper，并出现 Parallel 字样，但第四个 provider 的身份与表头在抽取文本中不完整，需回原文确认。

三、数据与采集协议
首版包含 150 个问题、614 个证据状态、约 131k 条搜索结果。状态定义为“一个问题在一个采集时点”的证据集合；采集节奏为每两天一次，因此不同问题的状态数取决于其开放时长与采集窗口。问题来自 Polymarket 与 Kalshi 的公开可交易问题，论文片段提到问题选择在结果之前完成，且部分属性在不看结果的情况下测量，目的是减少事后挑题偏差。

四、查询计划与主 provider
采集阶段使用 query-planning LLM 生成查询与后续追问；片段提到 coverage rating 是查询规划 LLM 在追问之后对“证据覆盖问题程度”的评分，并据此选择 Tavily 作为主 provider。Provider 统计片段可读出：Tavily coverage 0.68、relevant 66%、dated 0%、价格 $16/千次请求；Exa coverage 0.64、relevant 51%、dated 39%、价格 $15/千次请求。Serper 与第四家 provider 的完整行在片段中不完整，不能安全补全。

五、回放与比较矩阵
回放时，模型按状态顺序读取证据，可选择是否使用记忆；评测者可以固定模型比较来源，固定来源比较模型，固定证据比较记忆策略。片段提到“每次只改一个条件、其余保持主条件不变”的消融逻辑，说明论文把模型、记忆、来源作为可分离因素处理。

六、评价指标
论文使用预测准确率与 Brier 类概率评分；片段出现 Brier、ΔLast（last-state Brier）、TBS 等缩写，但完整定义在抽取文本中缺失，不能凭缩写臆造公式。论文还将 LLM 预测与市场基准比较，并在部分表格中使用 LLM judge 的标签来判定证据/结果方向；这意味着评测既包含数值评分，也包含对证据是否支持结果的语义判断，具体 judge 协议需核对原文。

七、泄漏审计
除主实验外，论文做了一个关键审计：在结果结算后，用原来的查询再次检索，并测试日期过滤能否阻止“答案泄漏”。这不是主预测实验，而是对回溯式评测有效性的压力测试。片段明确说日期过滤降低泄漏但不消除，且每个 provider 都仍有泄漏。

八、方法边界
ForecastGym 固定的是“证据获取策略”，不是“所有可能的检索行为”。它不能完全代表一个允许自适应搜索、点击、翻页、调用多个工具的在线 agent；它评估的是在给定证据流上的预测、记忆与来源利用能力。这个边界是理解论文结论的关键。

Q4: 论文做了哪些实验？

一、数据与 provider 表征
论文首版报告 150 个问题、614 个证据状态、131k 条搜索结果，覆盖四个商业搜索 API，采集间隔两天。片段给出 provider 级统计：Tavily 的 coverage 为 0.68、relevant 为 66%、dated 为 0%、价格为 $16/千次请求；Exa 的 coverage 为 0.64、relevant 为 51%、dated 为 39%、价格为 $15/千次请求。这里的 coverage 被描述为查询规划 LLM 在追问后对证据覆盖度的评分，而不是传统 IR 的 recall；relevant 与 dated 的具体判定口径需回原文核对。

二、泄漏审计实验
核心实验之一是在结果揭晓后重跑相同查询，比较返回内容是否直接暴露结果，并测试日期过滤的作用。摘要报告：即使使用其测试的日期过滤，仍有高达 92% 的问题返回“几乎直接陈述结果”的内容；片段进一步说日期过滤减少泄漏但不能阻止，Table 3 显示每个 provider 的日期过滤证据仍然泄漏。这个实验直接挑战“只要加日期过滤就能做历史回测”的常见做法。

三、冻结证据上的预测实验
主实验让被测 LLM 在冻结证据状态上做预测，并与预测市场基准比较。摘要明确：在冻结证据上，所有被测 LLM 的预测准确率都落后于市场。片段还出现 closed-book 虚线、last-state Brier、ΔLast 等元素，说明论文比较了闭卷与检索条件、最后状态与跨状态表现；但完整模型清单和数值表在提供的文本中不完整。片段出现 Gemini 3.8 Flash、Parallel 等行名，可能是模型/模式/OCR 噪声，不能据此断言完整实验矩阵。

四、记忆消融
论文比较有记忆与无记忆的策略。片段显示：没有记忆时，预测会从一个状态跳到另一个状态；有记忆时，记忆可能把模型固定在错误读数上，而市场继续朝相反方向移动。实验还按“落后市场超过 0.1”的状态做诊断，图注片段提到 111 个状态、来自 49 个问题；这像是错误分析子集，而非全量统计单元。

五、搜索源消融
RQ4 明确问“搜索源有多重要”。论文在冻结证据上按 provider 重放，比较不同来源的预测表现。片段出现 Exa 与 Serper 的多列数字，例如一行可见 31%、27%、90%、92%、0.080*，另一行可见 32%、17%、73%、43%、0.194；由于表头在 PDF 抽取中丢失，不能安全地把每一列映射为准确率、覆盖率、泄漏率或 Brier。只能确认：来源间存在明显差异，且 provider 的覆盖、相关性、日期元数据与价格并不一致。

六、诊断性条件分析
论文不只报告总体落后，还做条件切片：当证据明确指向结果时，模型的表现可以接近市场甚至更好；差距更多出现在证据不足、证据到达较晚或模型没有抓住公开信息的切片。摘要最后一句“Our diagnostic analysis suggests that missed public…”被截断，无法确认完整结论；结合片段只能合理推断其方向是“漏掉的公开信息/证据覆盖”而非单纯推理失败。

Q6: 有什么可以进一步探索的点？

1. 扩大样本与统计功效。首版 150 个问题、614 个状态适合做方法验证，但对子组分析、模型排名和交互效应仍偏小；后续可扩展到更多平台、更多领域、更长开放窗口和更多采集频率，并预注册主要比较。
2. 强化时间溯源。每条证据应记录发布时间、抓取时间、最后更新时间、内容哈希、历史快照和排序上下文；对“t 时是否可见”建立更严格的可审计证据链，而不仅是日期过滤。
3. 研究自适应证据获取。ForecastGym 固定了采集策略；未来可以比较主动搜索、追问、翻页、多源路由、预算约束下的查询规划，但必须保留固定证据回放作为对照，否则又会回到检索与推理混淆。
4. 记忆与信念更新。可探索校准的记忆压缩、矛盾证据处理、遗忘机制、置信度传播、状态空间滤波和“记忆何时有害”的触发条件；重点不是记忆长度，而是记忆是否改善跨状态校准。

6. 来源路由与成本优化。不同 API 的覆盖、时效、价格不同，可研究按问题类型、时间窗口和预算动态选择 provider；同时报告成本—准确性前沿，而不是只报最高分。
7. 评价指标与市场基准。可比较 Brier、log score、校准误差、分辨率、AUC 类排序指标和决策收益；对市场基准应控制流动性、费用和长尾问题，并报告配对置信区间。
