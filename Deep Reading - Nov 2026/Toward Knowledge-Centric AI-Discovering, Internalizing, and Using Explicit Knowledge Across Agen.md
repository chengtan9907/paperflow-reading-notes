# Toward Knowledge-Centric AI: Discovering, Internalizing, and Using Explicit Knowledge Across Agents and Generations

> ★★★★☆ 推荐阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：knowledge-centric ai · agent memory · knowledge internalization · explicit knowledge representation

## 一句话总结

这是一篇 position paper：作者主张下一代 AI 应当以知识为中心，在模型与 harness 之外建立一个独立于任何单一智能体、可持续演化的显式知识层，并通过“智能体从环境与轨迹中发现知识 → 知识层把碎片化记录与经验内化为可组合、可修订的理解 → 跨系统、跨代际的智能体使用该知识并回传新结果供修订”这一闭环，让知识不再被困在模型参数、临时上下文窗口或系统私有的记忆库中。

## 摘要

> 元数据里的 abstract 字段是明显的 PDF 双栏错位加断行噪声（句子被拦腰截断、参考文献编号插入句中），下面的复述是在清洗这些噪声后重建的摘要主线，凡属重建而非字面直读的地方都做了标注。
> 一、出发点（字面可读部分）。知识是人类理解得以跨人、跨代累积的方式：它是比其生产者更长寿的耐久记录，他人可以核查、组合、教授与纠正。AI 智能体如今由许多彼此独立的用户与组织构建和运行，每个智能体在数月内就被升级、替换或退役；然而智能体所学到的东西仍被困在模型参数、瞬时的上下文窗口，或一个系统私有的记忆库里——后者只是被追加和检索，而不是被加工处理（原文：appended to and retrieved from rather than processed，字面可读）。
> 二、核心主张。作者认为下一代 AI 应当是 knowledge-centric 的：围绕一个显式的、持续演化的、独立于任何单一智能体的知识层来构建。
> 三、闭环三阶段（摘要明确给出）。
> 1. discover：智能体从环境与自身轨迹中发现知识；
> 2. internalize：知识层把碎片化、异构的记录与经验转成可组合、可修订的理解；
> 3. use：跨系统、跨代际的智能体使用该结果，并把新的产出回传以供修订。
> 四、摘要中的组织类比与“共享缺失”论证。摘要提到组织理论描述了企业内部的同一过程：隐性 know-how 被外化、与其他显式知识组合、再被新成员重新内化（引 [85]）。摘要还指出，不同用户、团队、组织各自运行自己的智能体或多智能体系统，模型、工具、目标、权限与知识表示各不相同，它们不共享上下文也不共享控制器，然而一个系统的发现本可以给另一个系统提供信息——元数据摘要在“one system's finding could inform…”处被截断，后续论证需回原文补读。
> 五、摘要可读片段中的其他线索（片段级，需核对）。包括：对知识给出“三部分”的工作定义（知识是 (i) 被组织起来因而能与其他知识关联、(ii) 可超出原始语境复用的信息，第 (iii) 条在片段中被截断）；明确区分 records / experience / knowledge 三者；把“自动化的知识”与“把知识库从语言模型中解耦出来”列为关键挑战（引 [20]）；并提出“框架性目标 + 瓶颈假设”的写法（见 §6.4）。

Q1: 这篇论文试图解决什么问题？

一、论文试图解决的问题（按论证层次拆）

1. 表层问题：智能体学到的知识不可累积、不可迁移。作者把知识当前的三种“存放地”逐一点名为失败模式：
 · 模型参数——学习结果被封进权重，不可检视、不可组合、不可局部纠正；智能体被替换或升级，学到的内容随之消失。
 · 上下文窗口——昂贵、在长输入上被不均匀地利用（引 [76]）、会话结束即丢失。
 · 系统私有记忆库——关键指控是它“被追加和检索，而不是被加工”（appended to and retrieved from rather than processed），也就是只有存取没有整合、没有冲突消解、没有修订。

2. 中层问题：多智能体并存的异构性。不同用户、团队、组织各自运行自己的智能体或多智能体系统，模型、工具、目标、权限、知识表示都不同，彼此不共享上下文也不共享控制器；因此一个系统的发现无法系统性地进入另一个系统。这是“知识无法跨系统”的问题，而非单纯的“单个智能体记不住”的问题。

3. 代际问题：智能体生命周期以月计，被升级、替换、退役；人类的知识靠耐久记录跨越代际，智能体却没有等价物。作者要求知识层必须独立于任何单一智能体，正是为了让知识比它的生产者活得更久。

4. 概念问题（这是本文真正的主战场，合理推断）：现有工作把 record（原始日志）、experience（轨迹被读成“试了什么、随后发生了什么”）、knowledge（可迁移的断言）混为一谈，把“向量库 + 检索”直接等同于知识。论文专设 “2. WHAT IS KNOWLEDGE?” 一节并给出三条件工作定义，说明作者认为概念混淆本身是阻碍领域进展的瓶颈。

5. 结构问题：知识库与语言模型的纠缠。片段中出现“把知识库从语言模型中解耦（disentangling knowledge bases from language models）作为关键挑战 [20]”，指向“知识应当外置为可检视对象，而不是溶进模型”的立场。

二、论文隐含的假设与我对其强度的判断

1. “社区判定值得保留”这一选择机制被默认为存在且可用（摘要原句：what is written down is what a community judged worth keeping）。跨组织场景下由谁判定、如何防止知识污染与激励错配，摘要层面没有回答——这是薄弱处。
2. 假设显式记录优于隐式参数。但论文同时主张 P2 “active, evidence-grounded internalization”，即仍要把外部知识内化为神经能力；这与“参数是牢笼”的批判构成张力（合理推断，需回原文看作者如何自洽）。
3. 假设存在可跨异构系统交换的知识表示。κ=(c,f,C,π) 这一形式化是为该假设服务的，但其表达力与可操作性需要原文与后续工作验证。
4. 假设“知识层”的维护成本可被摊薄。文中批评上下文窗口“昂贵”，但显式知识层的写入、验证、版本化、冲突消解同样有成本，摘要未做对称讨论。

Q2: 有哪些相关研究？

一、组织理论与知识管理（论文显式引用，[85]）
论文用组织理论做整篇的类比骨架：企业内部的隐性 know-how 先被外化（externalized），再与其他显式知识组合（combined），最后由新成员重新内化（internalized）。这对应知识管理里经典的 tacit↔explicit 转换循环。论文的创新点不是提出该循环，而是主张把它从“组织内、人之间”迁移到“智能体间、代际间”，并指出 AI 目前只做了“存储”，没做“外化—组合—内化”。

二、智能体系统架构（显式引用，[132; 99; 113; 42]）
论文采用“agent = model + harness”的分解，harness 指模型周围的 prompt、工具、记忆与控制循环。这一分解的作用是把“记忆”降格为 harness 的一个组件，从而为“记忆 ≠ 知识层”的论断腾出空间。邻近脉络（推断）：ReAct 式工具调用智能体、AutoGPT 类长程智能体、多智能体框架与 agent OS / agent runtime 一类系统工作。

三、记忆与上下文工程（显式引用，[76] 长上下文利用不均）
论文点名的失败模式直接对标三类工作：长上下文窗口、外部记忆库（append + retrieve 式向量记忆）、会话级 context 管理。其批评点是这些机制只做存取不做加工，缺少整合、抽象与修订。邻近脉络（推断）：RAG、记忆增强智能体、经验回放/技能库、context engineering。

四、知识库与语言模型的解耦（显式引用，[20]）
片段明确把“disentangling knowledge bases from language models”列为 key challenge，并提到“a recent large knowledge …”（被截断，合理推断为 large knowledge model / knowledge foundation model 一类提法）。邻近脉络（推断）：知识图谱与 LLM 结合、KB-grounded 生成、structured knowledge injection、知识编辑与模型编辑（把知识写进参数的另一条路线，与本文立场相对）。

五、知识内化（knowledge internalization）与 knowledge foundation models
这是论文自报的第二项贡献：对“知识内化”和“知识基础模型”做 systematization of knowledge（SoK 式梳理）。也就是把蒸馏、continual learning、记忆 consolidation、技能内化等分散路线收拢到同一坐标系下。具体覆盖哪些方法，检索片段未给出，需回原文。

六、与本文构成竞争范式的路线（推断，用于定位）
1. 纯 scaling + 长上下文路线：认为窗口足够长即可，本文明确反对（贵、利用不均、会话即失）。
2. 纯参数化路线：知识编辑 / 持续预训练，本文视之为“牢笼”。
3. 纯检索路线：RAG / 向量库，本文视之为“只追加不加工”。
4. 本文路线：显式知识层 + 内化闭环，试图同时拿到可检视性与神经效率。

Q3: 论文如何解决这个问题？

一、总体方案形态：不是系统实现，而是一份“定义 + 原则 + 形式化 + 路线图”的位置论文
论文没有提出可运行系统，而是给出四个层次的东西：(1) 一个可用的知识定义；(2) 三个阶段的循环原则（discover / internalize / use）；(3) 一个显式知识单元的形式化 κ=(c,f,C,π)；(4) 一份关于知识内化与知识基础模型的系统化梳理，外加一个“框架性目标 + 瓶颈假设”。

二、第一层：知识的三条件工作定义（片段可读，第三条被截断）
知识是满足以下条件的信息：
(i) 被组织起来，因而能与其他知识建立关联（organized so that it can be related to other knowledge）——这一条把“孤立的事实”排除在外，强调关系结构；
(ii) 可超出其原始语境复用（reusable beyond …，片段截断，合理推断为 beyond its original context）——这一条把“一次性观察”排除在外；
(iii) 第三条在检索片段中被截断。合理推断为“可被核查/有证据支撑”一类条件（因为论文另一处反复强调 evidence-grounded），但必须回原文核对，不能当作已知。

三、第二层：records / experience / knowledge 的三级区分（片段可读，是全文最锋利的分析工具）
论文给出的例子链是：智能体每一步动作的原始日志（log）是 record；把这条轨迹读成“试了什么、随后发生了什么”，是 experience；从一次具体观察中抽出可迁移的断言，才是 knowledge。这三者不是同义词，而是抽象阶梯上的三级；当前系统的核心缺陷正是把 record 当成 knowledge 直接塞进检索库。

四、第三层：三条原则（P1/P2/P3，与三阶段对应；名称部分可读）
P2 在片段中可读为 “Active, evidence-grounded internalization”：内化必须是主动的、有证据支撑的，而不是把原始记录原样传递下去（Rather than pas…，被截断，合理推断为 rather than passing raw records through）。P1 与 P3 的名称在检索片段中未出现，按摘要的三阶段结构合理推断分别对应“发现”与“使用/回传”，需回原文核对。

五、第四层：显式知识单元的形式化
论文把一个显式知识单元表示为 κ = (c, f, C, π)（片段到此截断）。逐项判断：c 对应 condition（条件），这一点有 “condition-preserving conceptualization” 的说法作支撑，可信度较高；f 合理推断为 fact / 断言本体；C 与 π 的具体语义在片段中缺失，合理推断为语境/适用范围与出处或置信（provenance / confidence），但属于推测，必须核对原文。与形式化配套的还有两项设计：condition-preserving conceptualization（概念化时必须保留适用条件，即不允许把有条件的知识写成无条件断言），以及三种推理形式（three forms of reasoning）——合理推断为演绎、归纳、溯因（或含类比），需核对。

六、第五层：知识层与智能体的关系设计
知识层独立于任何单一智能体，智能体只是读写方：发现阶段写入原始记录与经验，内化阶段由知识层完成整合与修订，使用阶段跨系统跨代际读取并回传结果。这一“层在系统之外、跨代际存活”的架构选择，是本文与所有“给智能体加记忆模块”的工作最本质的区别。

七、第六层：系统化梳理与瓶颈假设
论文自报的第二项贡献是对 knowledge internalization 与 knowledge foundation models 做 systematization；第三项贡献是把“知识库与语言模型解耦”确立为关键挑战。另有一个“framing objective + bottleneck hypothesis”的组合（§6.4），即先给出目标函数式的表述，再指出当前真正的瓶颈在哪一环——这是位置论文常见的写法，作用是把“该往哪投入”变成可争论的命题。

Q5: 发现了什么实验现象？

一、先校准：本文没有实验现象可报告
没有数据集、没有 baseline、没有数值趋势，因此不存在“消融趋势 / scaling trend / 负结果”意义上的实验观察。下面记录的是论文在论证过程中揭示的“现象级判断”与“概念张力”，这是位置论文里等价于发现的东西。

二、被点名的三类失效现象（论文的核心经验主张，均为文献论证而非自测）
1. 上下文窗口的三重失效同时成立：贵（expensive）、在长输入上被不均匀利用（引 [76]）、会话结束即丢失。三者叠加意味着“把窗口开大”不是解法——这是对长上下文路线的直接反驳，也是全文最容易被检验、因而最该被后续工作检验的一条。
2. 记忆库的“只追加不加工”：appended to and retrieved from rather than processed。这个措辞的价值在于它给了一个可操作的判据——看一个记忆系统是否有“加工”环节（整合、抽象、冲突消解、修订），而不只看召回率。
3. 参数化知识的不可检视：不可检查、不可组合、不可局部纠正，且随智能体退役而消失。

三、抽象阶梯现象（records → experience → knowledge）
同一份原始日志，在不同读法下是三种不同对象：原样保留是 record；读成“试了什么、随后发生了什么”是 experience；抽成可迁移断言才是 knowledge。这个阶梯解释了一个反直觉现象：检索系统召回率越高，并不代表知识越多，因为它搬运的往往仍是 record 层的对象。这是全文最值得带走的判据。

四、组织类比的推论现象

二、论证主线（作者如何从现状推到主张）
第一步，确立“知识是人类跨代累积的机制”：知识是比其生产者更长寿的耐久记录，可被他人核查、组合、教授与纠正；它既是选择性的（写下来的只是社群认为值得保留的），也是可检视、可组合的。
第二步，指出 AI 目前完全没有等价物，并给出三重失败：知识被困在模型参数里（不可检视、不可组合、随智能体退役而消失）、被困在上下文窗口里（昂贵、长输入下利用不均 [76]、会话结束即失）、被困在系统私有记忆库里（只被追加与检索，而不被加工）。
第三步，指出问题的规模效应：智能体由大量彼此独立的用户与组织构建，模型、工具、目标、权限与知识表示各异，不共享上下文也不共享控制器，而每个智能体在数月内就被升级、替换或退役——因此“单系统内部改进记忆”根本无法解决问题，必须是跨系统、跨代际的知识层。
第四步，给出解法形态：一个三阶段闭环。智能体从环境与轨迹中发现知识（discover）；知识层把碎片化的异构记录与经验内化为可组合、可修订的理解（internalize）；跨系统跨代际的智能体使用该结果并回传新产出供修订（use）。
