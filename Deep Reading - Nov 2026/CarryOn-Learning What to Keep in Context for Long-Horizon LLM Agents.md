# CarryOn: Learning What to Keep in Context for Long-Horizon LLM Agents

> ★★★★☆ 推荐阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：long-horizon agents · context management · memory selection · tool-use agents

## 一句话总结

CarryOn 是一种外置、轻量的长程 LLM Agent 上下文管理器：它把任务进度压缩成紧凑控制状态，并用可学习的细粒度选择器从原始交互中保留带源链接的证据、支持被省略证据的临时回召，从而在降低上下文成本的同时避免摘要丢失后续动作所需的精确细节。

## 摘要

> 论文关注长程 LLM Agent 的上下文管理问题。随着工具调用和多步交互推进，观察结果与中间结果不断累积，重复处理历史会显著增加成本；但简单压缩并不必然改善决策，摘要可能丢掉后续动作所需的精确细节（如金额、账号、参数），而保留全部历史又引入大量无关信息。CarryOn 的核心是“携带重要内容”：Actor 维护一个紧凑的执行状态，记录进度与下一步；独立证据管理器从原始观察中抽取细粒度证据单元并保留来源引用；学习到的选择器和自适应保留策略决定每一步 Actor 看到哪些证据，并允许早先被省略的证据在需要时重新进入上下文。论文还提出两个互补指标：Sα 在优先任务成功的同时计入资源使用，NCS 衡量每次成功所消耗的归一化成本。实验覆盖三个基准和三个 Actor，报告平均任务成功率 75.7%，比最强基线高 6.7 个百分点，并在平均 S0.8 与 NCS 上领先；但摘要片段在 NCS 定义处被截断，完整公式需查原文。

Q1: 这篇论文试图解决什么问题？

1. 核心问题是如何在有限上下文与成本下，让 Agent 在长程任务中持续获得与当前决策相关、且足够精确的信息，并非单纯把上下文压短。长程 Agent 需要把目标分解为多步工具调用，并在每一步根据环境反馈调整。以 Figure 1 的 Venmo 任务为例，Agent 要先找到同事、检查并充值余额、再逐个转账并填写备注；第 9 步获得的同事记录可能到第 33 步才被使用。若把全部历史反复送入 Actor，输入成本随步数增长；若用摘要或剪枝，则“7 个同事”“余额 140 美元”“备注 For Lunch”这类精确字段可能在压缩时丢失，导致后续动作无法执行。论文把这一张力概括为：更短的上下文不一定支持更好的决策。
2. 现有方法的不足：摘要式压缩是有损且往往不可逆的，丢失的细节无法在需要时恢复；剪枝或选择若只依据最近性，会漏掉很久以前但突然相关的证据；保留全历史则让大量无关观察稀释注意力并推高成本。论文还指出，现有外部管理器常把“压缩”当作一次性操作，缺少源级引用和回召机制。
3. 评价问题：只用成功率会忽略资源消耗；只统计成功轨迹上的成本又会掩盖失败轨迹的资源浪费。论文因此需要同时衡量成功与成本，并把失败成本纳入比较。
4. 隐含假设：证据相关性可以从当前状态或下一动作预测；紧凑状态足以承载任务进度；用后续 API 调用复用作为证据效用标签是有效代理；源链接能让 Actor 验证证据。论文的实验设计基本围绕这些假设展开。
5. 边界：论文不是研究如何提升 Actor 的基础推理能力，也不是训练一个更大的记忆模型，而是研究外置、Actor 无关的上下文管理；因此其收益应理解为在给定 Actor 上改善信息可用性与成本，而非替代模型能力。

Q2: 有哪些相关研究？

1. 长程 LLM Agent：以 ReAct 为代表的工作让模型交错推理与动作，通过环境反馈完成多步任务；应用覆盖日常数字任务、办公工作流、客服等。长程化带来的直接问题是交互历史线性增长，Actor 每一步都要重复处理历史。
2. 让 Actor 自己管理记忆：一类方法微调执行模型，使其在任务执行中学会写入、更新、遗忘记忆（Zhou et al., 2026; Jiang et al., 2026; Wang et al., 2026b）。优点是记忆与策略耦合、可能更 task-aware；缺点是 Actor 相关、训练成本高，且可能改变原有能力。
3. 外置上下文管理器：另一类方法不改 Actor，而是在外部对历史做摘要、剪枝、选择或结构化记忆（Kang et al., 2025; Pan et al., 2024; Zhang and Sun, 2026）。Prompt compression 去除信息量低的内容；structured memory 把历史组织成可查询结构。论文认为这些方法的核心风险是：压缩后上下文更短，但后续动作需要的精确证据可能被不可逆地丢掉；保留全部历史则成本高且噪声大。
4. 检索与证据选择：CarryOn 与 RAG 或记忆检索相邻，但证据来自 Agent 自身交互历史，强调细粒度单元、源引用和任务状态条件化选择；它不是从外部知识库检索，也不是简单按相似度取 top-k。
5. 评测：长程 Agent 常用成功率、token 成本、调用次数等指标。论文指出 success-only 与仅统计成功轨迹成本各有偏差，因此提出 Sα 与 NCS。相关基准包括 AppWorld、Tau2 等；片段还提到办公工作流类应用，但第三个基准名称未在可用证据中明确出现。
6. 定位差异：CarryOn 的差异点不是“更强的压缩器”，而是把紧凑状态与可回召的细粒度证据分开，并用学习选择器与自适应保留策略在预算内组装 Actor 输入；其外置设计也支持跨 Actor 迁移。

Q3: 论文如何解决这个问题？

1. 总体架构：CarryOn 把 Actor 与上下文管理器分开。片段给出的输入组装式为 X_t = Compose(q, m_t, W_t, R_t)：q 是任务查询，m_t 是紧凑控制状态，W_t 是当前工作证据集，R_t 是被回召或检索的证据集；各符号的完整定义在片段中未展开，但这一分解体现了“状态 + 证据”的双通道设计。Actor 只看到组装后的有界上下文，原始交互历史留在外部证据池。
2. 紧凑控制状态：Actor 在每一步记录任务进度、待办子目标、关键变量和下一步动作，例如“已找到 7 位同事”“余额=140”“下一步逐个支付 20 美元”。状态是有界的，不随步数线性增长；它相当于可执行的执行状态或任务骨架，并非历史摘要。
3. 细粒度源链接证据：证据管理器从原始观察和工具输出中抽取细粒度单元（如一条同事记录、一个余额字段、一段 API 返回），每个单元保留来源引用（来自哪一步、哪个工具调用、哪段观察）。与摘要不同，证据单元保留精确值，因此后续动作可以直接使用；与整段历史不同，它可以去噪并按需选取。
4. 学习选择器与自适应保留：选择器根据当前状态、任务查询和候选证据打分，决定哪些证据进入 W_t；自适应保留策略在预算内保留高价值证据，并支持“临时证据扩展”：早先被省略的证据在后续步骤可以再次被选中、重新进入上下文。这使压缩从“一次性丢弃”变成“可逆的缓存替换”。
5. 训练信号：片段显示选择器使用离线状态标注与证据引用训练；标注 schema 比 Actor 的有界状态更丰富。另一个关键标签是“后续 API 调用是否复用某个证据单元”：若后续动作的参数用到了早先观察中的值，则该单元可视为对决策有用。完整模型还包含 next-action training；消融中的 ranking only 去掉了 next-action training 与 temporary evidence expansion，说明二者都是完整方法的一部分。
6. 推理与成本：论文强调上下文管理不需要额外的 LLM 调用；选择或剪枝由本地轻量模型完成。但本地模型处理的 token 仍被计入成本，因此“无额外 LLM 调用”不等于零开销，而是避免调用大型 Actor 或外部 API。这个区分对解读 NCS 很重要。
7. 设计权衡：CarryOn 用“状态负责进度、证据负责精确细节”的分工，换取可逆性和跨 Actor 通用性；代价是需要维护证据池、源引用和选择器，且状态与证据可能不一致。其核心假设是：当前决策所需的证据可以从状态条件化地预测，且被省略的证据在未来仍可被找回。

Q4: 论文做了哪些实验？

1. 基准与 Actor：论文在三个基准、三个 Actor 上评估。证据明确出现 AppWorld 与 Tau2；Introduction 还提到办公工作流，结合三个基准的表述，第三个基准很可能是办公或企业工作流类基准（合理推断，片段未给出名称，需核对原文）。三个 Actor 明确出现 Claude、Gemma、Qwen；具体版本与规模未在片段中给出。
2. 对比方法：包括 Full History（保留全部历史）、摘要、压缩、剪枝、历史选择类外置管理器，以及 recency packing（在相同基础预算下保留最近证据）。片段还提到 strongest baseline，但未完整列出所有 baseline 名称，不能补造。
3. 指标：Success（任务成功率）、Sα（论文报告 S0.8，成功优先并计入资源使用）、NCS（归一化每次成功成本），以及 mean peak input、Actor calls、token 总量等成本指标。Tau2 的 token 统计包含 User simulator；CarryOn 的选择器本地 token 也计入。
4. 主结果：CarryOn 取得 75.7% 平均任务成功率，比最强基线高 6.7 个百分点，并在平均 S0.8 与 NCS 上领先。AppWorld 上，片段称 CarryOn 相对 Full History 提升 Success 并降低 mean peak input，但相关句子被截断，无法确认是“对三个 Actor”还是仅部分 Actor；Tau2 上则出现相反的成本现象：CarryOn 的 mean peak input 高于 Full History。
5. 消融：Table 2 在 AppWorld + Claude 上比较四个变体：完整 CarryOn 79.8%；w/o MEMORY（去掉控制状态）66.1%；Ranking only（去掉 next-action training 与 temporary evidence expansion）76.8%；Fine-grained training（用后续 API 调用复用标签的细粒度单元，但无状态标注引用）73.2%；Recency packing（同预算下保留最近单元）76.2%。论文称 CarryOn 在三项指标上均领先。
6. 训练与成本核算：片段提到每个训练任务使用一张 H100；成本估计排除 rollout collection 与 teacher labeling，因此 NCS 不是全生命周期成本。这个口径会影响对“便宜”程度的判断。
7. 证据缺口：三个基准的完整列表、Actor 版本、所有 baseline、Sα/NCS 的精确公式、Table 1 的完整数值、统计显著性检验，均未在检索片段中完整出现；阅读原文时应优先补齐这些。

Q5: 发现了什么实验现象？

1. 最大跌幅来自去掉控制状态：w/o MEMORY 从 79.8% 降到 66.1%，跌幅 13.7 个百分点，远大于去掉学习选择或细粒度训练。这说明长程任务的主要瓶颈可能在于“任务进度或下一步没有被稳定承载”，而不只是“证据找不到”。证据选择无法替代状态跟踪；二者是互补的。这也支持论文把 state 与 evidence 分开的设计。
2. recency packing 是强基线：在相同基础预算下保留最近证据得到 76.2%，仅比完整方法低 3.6 个百分点，且与 ranking only 的 76.8% 差距很小。这说明“最近性”在长程任务中本身就是很强的先验，学习选择器的增量并非压倒性。论文的贡献因此更应理解为“状态 + 可回召证据 + 预算控制”的组合，而不是单纯证明学习选择器远胜启发式。
3. 细粒度标签的质量很关键：Fine-grained training 用后续 API 调用复用作为标签、但没有状态标注引用，只有 73.2%，比完整方法低 6.6 个百分点。一个合理解释是：API 复用只覆盖“进入动作参数”的证据，无法覆盖“用于推理、约束检查、状态更新”的证据；状态标注引用提供了更接近决策过程的监督。这是对“自动标签足够好吗”的一个重要反例。
4. 临时证据扩展与 next-action training 有可测增益：Ranking only 去掉二者后为 76.8%，比完整方法低 3.0 个百分点。说明“被省略证据还能回来”以及“选择器面向下一动作训练”不是装饰性设计；但增益小于控制状态。
5. 成本优势不是普遍的：AppWorld 上 CarryOn 降低 mean peak input，但 Tau2 上 mean peak input 高于 Full History。这与“上下文管理器必然省 token”的直觉相反。可能机制包括：Tau2 是多轮对话或客服场景，状态与证据的组装开销更大；临时证据扩展会在某些步骤造成峰值；Full History 可能本身被截断或 token 统计口径不同；Tau2 还计入 User simulator token。论文仍报告 CarryOn 在平均 Sα 与 NCS 上领先，说明成功率的提升可能抵消了峰值成本，但“峰值更高”仍是部署时的重要边界条件。
6. 跨 Actor 并不完全一致：片段出现 for Claude and Gemma and matching Full History for Qwen 的残句，无法确认具体指标；但可推测 Qwen 上 CarryOn 的优势可能只是持平 Full History。若属实，说明外置管理器的收益依赖 Actor 的工具使用能力与上下文敏感度，不能假设跨模型普遍增益。
7. 指标间存在张力：Success 高不一定 NCS 低；仅看成功轨迹的成本会漏掉失败消耗；S0.8 以成功为先，可能掩盖峰值成本。论文用两个指标互补，但权重 w 的选择会影响排序；片段提到 Appendix D.2 的权重敏感性分析，却没有给出结论，不能断言排序完全稳健。
8. 训练成本被排除：NCS 的成本估计不含 rollout collection 与 teacher labeling，这会系统性低估需要大量标注或采样才能部署的方法。若把训练成本摊入，CarryOn 相对免训练压缩方法的优势可能缩小。
9. 证据噪声提醒：检索片段存在双栏错序，像 Both methods complete 66.3% 这类残句无法归属；不要把它当作可用结果。

Q6: 有什么可以进一步探索的点？

1. 更可靠的证据效用监督：当前用后续 API 调用复用作为标签，容易漏掉推理、约束检查、否定证据和状态更新所需的证据。可以尝试用下游成功率做强化学习或信用分配，训练一个“反事实证据效用”评估器；或用过程奖励模型标注“某证据是否改变了决策”。这能直接检验论文的核心假设：证据相关性是否可从局部动作预测。
2. 状态表示与验证：紧凑状态是最大贡献，但也最脆弱。可研究结构化状态 schema、层级任务图、不确定性标记、状态-证据一致性检查；当 Actor 写入错误状态时，能否通过源链接回查并纠正。还可比较“Actor 自维护状态”与“外部模型维护状态”的权衡。
3. 预算与峰值感知：Tau2 上峰值输入反而更高，说明平均成本与峰值成本需要分开优化。可研究 per-step 预算分配、峰值约束下的证据调度、临时扩展的延迟或合并、KV-cache 复用、分层记忆（工作集、缓存、归档）。这对在线部署比平均 token 更关键。
4. 证据冲突与时效：长程任务中同一实体可能被多次更新（余额、订单状态、同事列表）。需要研究证据版本化、冲突消解、过期失效、来源可信度；源链接不仅是解释工具，也可以作为事务日志。
5. 跨 Actor 与跨基准泛化：目前三个 Actor 的结果并不完全一致，第三个基准名称也未在片段中确认。应在更多模型规模、开源或闭源、多模态工具、不同工具接口上验证；特别要报告“在哪些 Actor 上不如 Full History”的负结果。
6. 评测与成本核算：Sα 与 NCS 是有价值的尝试，但需要公开精确公式、权重敏感性、置信区间、失败成本分解。建议报告成功-成本 Pareto 前沿，而不是单点均值；把训练、标注、采样成本摊入部署成本；区分峰值、平均、总成本。
7. 安全与隐私：证据池会长期保存用户数据（余额、同事、支付备注），需要访问控制、PII 脱敏、证据删除、提示注入防护。检索到的旧证据可能被恶意工具输出污染；源链接可帮助审计，但不能自动保证可信。
8. 与 Actor 训练结合：CarryOn 是外置、Actor 无关的，但可与轻量微调或蒸馏结合，让 Actor 更会写状态、读证据；也可把选择器蒸馏成更小的模型，或与 KV-cache 淘汰策略联合设计。
9. 理论理解：可以把问题形式化为“最小充分上下文”或信息瓶颈：在预算约束下最大化决策所需信息，最小化无关信息。研究证据相关性的可预测性、长尾旧证据的回召概率、状态误差传播上界。
10. 应用迁移：科学工作流中的实验记录、代码代理的跨文件依赖、办公自动化的多应用状态，都适合“状态 + 源链接证据”的范式；但科学场景对可复现性和证据审计要求更高，需要额外设计。

Q7: 总结一下论文的主要内容

一、问题意识：论文从长程 LLM Agent 的“上下文成本-信息精度”矛盾出发。多步工具调用让观察、工具返回和中间结果不断累积，Actor 每一步重复处理历史，成本随交互长度上升；但后续动作可能依赖很多步之前的精确细节。Figure 1 的 Venmo 任务是全文的典型例子：Agent 需要先找到同事、检查并充值余额、再逐个转账并写备注；第 9 步得到的同事记录要到第 33 步才用得上。若保留全历史，输入成本高且噪声大；若摘要或剪枝，像“7 位同事”“余额 140 美元”“备注 For Lunch”这样的字段可能被丢掉，导致任务失败。论文因此把目标从“压缩上下文”改写为“在预算内保留与当前决策相关且足够精确的信息”。
二、方法主线：CarryOn 采用 Actor 与上下文管理器分离的架构。Actor 维护一个紧凑控制状态，记录任务进度、待办子目标、关键变量和下一步；证据管理器从原始观察中抽取细粒度证据单元，并为每个单元保留来源引用。每一步的 Actor 输入由任务查询、紧凑状态、工作证据集和回召证据集组装而成（片段给出 X_t = Compose(q, m_t, W_t, R_t)）。学习到的选择器根据当前状态给候选证据打分，自适应保留策略在预算内决定保留或淘汰；被省略的证据不是永久删除，而是可以在后续步骤通过 temporary evidence expansion 重新进入上下文。这样，压缩变成可逆的缓存替换，而不是一次性有损摘要。
三、训练信号：片段显示选择器使用离线状态标注与证据引用训练；标注 schema 比 Actor 的有界状态更丰富。另一个重要监督是“后续 API 调用是否复用某个证据单元”：如果后续动作的参数用到了早先观察中的值，该单元就被视为有用。完整方法还包含 next-action training；消融中的 ranking only 去掉了 next-action training 与 temporary evidence expansion。论文强调上下文管理不需要额外 LLM 调用，选择或剪枝由本地轻量模型完成，但本地 token 仍计入成本。
四、实验设计：论文在三个基准、三个 Actor 上评估。证据明确出现 AppWorld 与 Tau2；Introduction 还提到办公工作流，第三个基准很可能是办公类基准（合理推断，片段未给名称）。Actor 包括 Claude、Gemma、Qwen。指标包括 Success、S0.8、NCS、mean peak input、Actor calls 与 token 成本；Tau2 的 token 统计包含 User simulator，训练成本估计排除 rollout collection 与 teacher labeling。
五、主要结果：CarryOn 取得 75.7% 平均任务成功率，比最强基线高 6.7 个百分点，并在平均 S0.8 与 NCS 上领先。AppWorld 上，完整方法在 Claude 上达到 79.8%；去掉控制状态后降到 66.1%，是最大跌幅；Ranking only 为 76.8%；Fine-grained training 为 73.2%；Recency packing 为 76.2%。AppWorld 上 CarryOn 相对 Full History 提升成功率并降低 mean peak input；但 Tau2 上 mean peak input 反而高于 Full History，说明成本优势不是普遍的。
六、关键发现与张力：第一，紧凑控制状态是最大贡献，说明长程任务的核心瓶颈之一是进度承载，而不是单纯证据检索。第二，recency packing 仅比完整方法低 3.6 个百分点，学习选择器的增量有限，论文的强项更像是“状态 + 可回召证据 + 预算控制”的系统组合。第三，细粒度训练若只用 API 复用标签、没有状态标注引用，会掉到 73.2%，说明自动标签是有效但不完备的代理。第四，Tau2 的峰值成本反常提示：临时证据扩展可能造成上下文峰值，平均成本与峰值成本需要分开优化。第五，跨 Actor 结果并不完全一致，片段中 Qwen 上可能只是与 Full History 持平。第六，NCS 未计入训练或标注成本，可能低估真实部署代价。
七、贡献与边界：论文的贡献包括：把长程上下文管理重新表述为“状态 + 细粒度源链接证据”的问题；给出可学习选择器与自适应保留策略；提出 Sα 与 NCS 两个互补指标；在三个基准、三个 Actor 上给出系统实验与消融。边界是：它是外置管理器，不提升 Actor 的基础推理；依赖离线标注与证据效用代理；在部分基准上峰值成本不降反升；对证据冲突、隐私、安全、分布外任务的讨论在可用片段中不足。
