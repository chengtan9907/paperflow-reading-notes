# Pixel is All You Need

> ★★★★☆ 推荐阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：pixel-space reasoning · visual chain-of-thought · image generation · multimodal unification

## 一句话总结

论文通过审计现有图像、视频与统一多模态生成管线，指出画布上的正确答案几乎都先由文本模块算出、生成器只负责渲染，并从零训练无文本通路的像素模型，证明把推理步骤直接写在画布上可以让小型模型学会多步符号推理。

## 摘要

> 根据检索到的摘要与正文片段，论文首先审计现有生成系统：在作者能够检查管线的系统中，画布上的正确答案几乎都先以文本 token 形式出现；生成模块虽然能读画布、写文本，但推理发生在 prompt rewriter 或文本模块，生成器只是把结果渲染成像素。作者由此提出核心问题：完全去掉文本通路、从零训练的像素生成器，能否直接在画布上读写并推理文本？为此论文构建十个像素空间推理任务，在统一画布上呈现问题、中间推理步骤与最终答案，并在相同模型架构、训练数据和 40k 步训练预算下比较逐帧推理与直接回答。现有图像编辑模型经 LoRA 后训练可以学会复制可见字符串，但在算术与事实题上仍接近 0%；而从零训练的 33M 像素模型能够在未见题上生成多步中间步骤，交织完成算术、点计数、区域涂色、曲线追踪与求和。作者据此主张，当前视觉生成器的推理失败更像训练范式问题，而不是像素本身不能承载推理。

Q1: 这篇论文试图解决什么问题？

（1）论文要解决的不是单纯的图像生成质量问题，而是一个更基本的归因问题：现有图像编辑、视频生成和统一多模态系统在画布上给出正确答案时，究竟是谁在推理。摘要指出，在作者能够检查管线的系统中，画布上的正确答案几乎都先以文本 token 形式出现；生成模块虽然能读画布、写文本，但推理发生在 prompt rewriter 或文本模块，生成器只负责渲染最终结果。这意味着，许多看起来像“视觉推理”的成功，可能只是文本模块算完之后把答案画出来。

（2）这一归因问题直接关系到“视觉能否统一其他模态”的议程。论文的长期愿景是把文本、图像、音频、触觉和机器人动作都画在同一张画布上，从而不需要为每种模态单独设计 tokenizer、cross-encoder adapter 或 decoder。但语言是最难的第一关：算术、逻辑、事实回忆与组合推理主要发生在语言中，也是 LLM 的推理介质。视觉要真正包含语言，不能只会渲染看起来像文字的像素，而必须直接读取画布上的问题、在像素空间中计算，并把答案写回像素。

（3）现有评测只看最终像素是否正确，无法区分“生成器自己推理”与“文本模块先算好、生成器只渲染”。论文因此需要一个可诊断的实验设计：一方面检查现有系统的管线，另一方面构建答案可见性不同的任务，让模型从“复制可见字符串”逐步过渡到“必须计算或回忆”的算术与事实题。Figure 3 的 Copy、Instruction、Context、Visual、Arithmetic、Factual 六个类别，正是这种答案可见性梯度的操作化。

（4）论文还需要回答一个训练范式问题：如果像素模型能够推理，那么推理应该以什么形式监督？是让模型直接从问题画布生成最终答案画布，还是让它在画布上逐帧写出中间步骤？前者是 direct answering，后者是 frame-by-frame reasoning。只有把两者放在相同架构、相同训练数据、相同训练预算下比较，才能判断“把中间步骤写在像素里”本身是否带来收益，而不是把更多数据、更多算力或更强架构的效果误归因于像素推理。

（5）该问题背后的隐含假设包括：符号推理可以被忠实地渲染为像素；固定等宽字体和受控画布足以代表文本推理；从零训练、无文本通路的模型能够在不依赖语言先验的情况下学习算术与事实知识；最终答案的自动判题可以近似衡量推理过程。论文的边界也在这里：合成任务、有限字号与布局、较小模型规模、有限任务家族，都意味着结论应被理解为“像素空间推理是可行的”，而不是“像素模型已经具备开放域语言推理”。

Q2: 有哪些相关研究？

（1）第一类相关工作是文本空间中的链式思维与 scratchpad 推理。LLM 通过在 token 序列中写出中间步骤来分解算术、逻辑和多跳问题，推理能力还会随参数规模呈现可预测的 scaling 趋势。论文把这一点作为对照背景：如果文本 token 可以作为推理介质，那么像素是否也能充当同样的外部 scratchpad？区别在于，论文要求中间步骤不是隐藏的文本 token，而是画布上可见的像素轨迹。

（2）第二类是统一多模态理解与生成模型。论文引用 Deng et al. 2025、Zhou et al. 等作为“在单一网络中统一理解与生成”的代表，并在结论中把审计范围扩展到统一多模态系统。这类系统通常仍包含文本模块或文本解码路径；论文的批评是，生成模块即使能读画布、写文本，也不代表它在推理，推理可能仍发生在文本侧。

（3）第三类是文本渲染与视觉文本生成。论文引用 Chen et al. 2023、Yang et al. 2023、Wu et al. 2025 等工作，说明近期生成器已经能渲染长段落、较 legible 的文字。但这篇论文强调“渲染文字”与“在文字上推理”是两种能力：前者只要求视觉逼真，后者要求读取语义、执行计算并写出结果。

（4）第四类是指令驱动的图像编辑。论文引用 Brooks et al. 2023、Labs et al. 2025 等，指出编辑模型可以遵循复杂指令，但管线中往往有 prompt rewriter 或文本模块承担指令理解和答案计算，生成器只执行局部渲染。论文用 LoRA 只后训练生成模块，正是为了把“生成器能否自己学会”与“文本模块能否代劳”分开。

（5）第五类是视觉推理任务与多模态基准。算术表达式、数学应用题、迷宫、曲线追踪、计数与涂色等任务在 VLM 或多模态推理文献中并不陌生；论文的差异在于，它不是让 VLM 看图后输出文本答案，而是让像素生成模型在画布上写出中间步骤和最终答案。任务被组织成五组配对：Expressions/Multiplication、Word Problems/Factual Questions、Mazes/Sum Mazes、Curve Tracing/Trace Then Sum、Count Then Paint/Compute Then Paint，用配对变体分离“感知/追踪”与“计算/涂色”等子能力。

（6）第六类是像素级生成模型与视觉世界模型。论文称其模型为 pixel model / pixel generator，从零训练、无文本通路，按帧在画布上生成状态。它与扩散模型、自回归图像生成、视觉规划等相邻，但检索片段没有给出具体 backbone、tokenization 或损失函数细节，因此不能把它直接归类为某一类生成架构。

（7）现有工作的共同缺口是：很少有研究同时做三件事——审计现有生成管线是否把推理外包给文本、构建答案可见性可控的像素空间推理任务、以及在相同预算下比较“写中间像素”与“直接给答案”。论文的定位就是补这个缺口，并把“当前生成器不会推理”从能力判断转化为训练范式判断。

Q3: 论文如何解决这个问题？

（1）论文采用“审计现有系统 + 从零训练像素模型”的双轨设计。审计部分检查图像编辑、视频生成和统一多模态系统的管线，重点看画布答案是否先在文本 token 中出现；如果生成模块只是渲染文本模块算出的结果，那么系统的视觉推理主张就不成立。

（2）审计的操作化手段包括 prompt rewriter 开关和生成模块后训练。检索片段显示，关掉 rewriter 后，两个图像编辑模型在每个样本上都把答案框留空，Wan 3.0 则留空或写入“17”“#ab)”一类涂鸦；这说明生成器本身没有独立完成答案的能力。另一个手段是对四个图像编辑模型（FLUX.2-klein、FLUX.3-klein、Qwen-Image-2.1、LongCat-Image-Edit）的生成模块做 LoRA 后训练，看它能否在只获得生成侧监督的情况下学会任务。

（3）任务套件包含十个像素空间推理任务，分成五组配对：Expressions 与 Multiplication、Word Problems 与 Factual Questions、Mazes 与 Sum Mazes、Curve Tracing 与 Trace Then Sum、Count Then Paint 与 Compute Then Paint。每个任务是一张方形灰色画布，尺寸为 192×192，Word Problems 为 256×256；文本用固定等宽字体渲染在 24 列、12 行、每格 8×16 像素的网格上。问题占据上方行，一条水平线把问题与底部两行答案区隔开，曲线、区域、点等视觉元素画在剩余空间。Figure 4 的图注进一步说明：问题与正确的中间推理步骤位于水平线上方，最终答案写在下方。

（4）从零训练部分完全移除文本通路，构建“纯视觉世界”。论文训练 pixel model，让每一个推理步骤直接由模型写在像素上。逐帧推理（frame-by-frame reasoning）把画布状态序列作为监督，模型在相邻帧对上学习“下一步写什么”；直接回答（direct answering）则把原始问题画布直接映射到带答案的最终画布，不写任何中间步骤。摘要明确说，两种模式使用相同模型架构、相同训练数据和相同训练预算；在 40k 步的等预算比较下，论文转向“写中间步骤”的收益论述。

（5）训练数据方面，检索片段提到最优示范会在每一帧随机执行一到三个操作，并以一定概率换到新行；这说明监督包含可变长度、可变位置的中间步骤，而不是固定模板。模型需要学会在画布上安排计算、写入中间结果，并在底部答案区给出最终答案。

（6）评测方面，论文使用自动判题器，对空白做归一化，并在任务不区分大小写时忽略大小写。对视频，判题器读取 8 个等间隔帧，同时报告最终帧是否正确以及任意帧是否正确。除 Default 外还有四个控制条件；检索片段在“four conditions control…”处截断，具体控制变量需要回原文核对。

（7）整篇论文的方法论核心是“把推理介质变成可观察变量”：文本模块在管线中时，正确答案可以先在文本 token 中出现；把文本通路移除后，推理是否仍然发生，只能看画布上是否出现可读的中间步骤。LoRA 后训练、rewriter 开关、逐帧与直接回答的等预算比较，都是为这个因果归因服务的。

Q4: 论文做了哪些实验？

（1）现有系统审计实验。论文检查图像编辑、视频生成和统一多模态系统的生成管线，测试它们在像素空间推理任务上的表现。Figure 3 聚焦四个图像编辑模型：FLUX.2-klein、FLUX.3-klein、Qwen-Image-2.1、LongCat-Image-Edit。图注明确说，这四个基座模型在每一个任务上都从 0% 开始；也就是说，未经后训练的生成模块完全不能完成这些任务。

（2）生成模块后训练实验。论文用 LoRA 只后训练生成模块，任务类别包括 Copy、Instruction、Context、Visual、Arithmetic、Factual。这个实验的目的不是让文本模块变强，而是测试生成器本身能否在生成侧监督下学会任务。Figure 3 的图注说，后训练能教会生成器复制可见字符串，但随着问题中答案可见性下降，准确率陡降，在 Arithmetic 与 Factual 上停留在 0% 到 2%。

（3）prompt rewriter 消融。检索片段显示，关掉 rewriter 后，两个图像编辑模型在所有样本上都让答案框留空；Wan 3.0 则留空或写涂鸦。这个实验直接检验“生成器是否能独立作答”，结果支持论文的核心归因：文本模块不在时，生成模块不会推理。

（4）从零训练的像素模型实验。论文在十个任务上训练无文本通路的 pixel model，模型规模至少包括 33M 参数级别。训练 regime 分为 direct answering 与 frame-by-frame reasoning：前者一次性从问题画布生成最终答案画布；后者在画布上逐帧写出中间步骤。两者使用相同架构、数据与 40k 步预算。

（5）受控比较实验。摘要明确说，在相同模型架构、训练数据和训练预算下比较两种 regime；40k 步等预算下，论文讨论“写中间步骤”的收益。检索片段没有给出完整的准确率数字，但行文方向表明 frame-by-frame 是作者主张的胜出条件。具体提升幅度、方差和显著性需要回原文表格核对。

（6）泛化实验。检索片段提到“Word problems across sizes”和“three-step Word Problems with new names”，说明论文还测试了不同模型规模下的 Word Problems，以及在替换名字后的三步应用题上做泛化。片段还提到逐帧推理在这些设置下的表现，但具体数值未给出。

（7）视频评测实验。对视频生成系统，判题器读取 8 个等间隔帧，报告最终帧是否正确以及任意帧是否正确。这个设计同时衡量“最终答案是否保持”和“过程中是否曾经出现正确答案”，两者之间的差异可以揭示时序一致性或答案保持问题。

（8）评测与条件控制。判题器做空白归一化，并在任务不区分大小写时忽略大小写；除 Default 外还有四个控制条件。论文还报告了图像与视频两种判题协议，说明它不是只用一个最终答案指标，而是尽量把“过程正确”和“最终正确”分开观察。

Q5: 发现了什么实验现象？

（1）现有生成器表现出明显的“复制—推理”双分离。Figure 3 图注显示，四个图像编辑模型未经后训练时在所有任务上都是 0%；LoRA 后训练后，生成器可以学会复制可见字符串，Copy 类表现很高，但随着答案可见性下降，准确率迅速跌落。到 Arithmetic 与 Factual 时只剩 0% 到 2%。这说明生成模块能学会“把看到的字符串搬到答案区”，却不能因此学会算术或事实回忆。

（2）答案可见性是决定成败的关键变量。Copy、Instruction、Context、Visual 到 Arithmetic、Factual 构成一个梯度：越接近“答案已经写在问题里”，生成器越容易成功；越需要自己计算或从参数知识中回忆，成功率越接近零。这一趋势不是简单的任务难度排序，而是对“推理是否被外包给文本模块”的诊断。

（3）prompt rewriter 消融给出了更强的因果线索。关掉 rewriter 后，两个图像编辑模型在每个样本上都留空答案框，Wan 3.0 则留空或写“17”“#ab)”一类涂鸦。失败模式不是“算错”，而是“根本不写”或“乱写”，说明生成器没有形成独立完成任务的内部过程。

（4）从零训练的像素模型给出了正向存在性证据。Introduction 片段说，一个 33M 模型在未见问题上的 rollout 可以交织算术、点计数和区域涂色，或者交织曲线追踪与求和。这不是说模型已经达到高准确率，而是说它能在像素画布上生成多步、跨子技能的中间推理轨迹。作者据此主张，像素空间本身可以承载一定程度的符号推理。

（5）逐帧推理与直接回答的对比是论文最关键的训练范式观察。摘要说两者在相同架构、数据、40k 步预算下比较；行文从“直接回答”转向“写中间步骤”的收益论述。合理推断，frame-by-frame 明显优于 direct answering；但检索片段在“writing…”处截断，具体准确率差距、任务间差异和失败案例需要回原文。

（6）泛化结果指向组合性而非纯记忆。片段提到三步 Word Problems 在更换名字后的结果，以及不同模型规模下的 Word Problems。若逐帧模型在新名字、三步题上仍能工作，说明它学到的至少部分是可重组的操作序列，而不是把训练题答案背下来；具体泛化幅度仍待核对。

（7）结论提到模型会“消除初始示范中的绕路”（eliminate the detours present in its initial demonstrations）。这暗示训练后的推理路径可能比示范更直接，模型不只是模仿示范的每一步，还可能压缩或优化中间过程。该现象很有趣，但片段没有给出度量方式，需看原文如何定义 detour。

（8）视频评测的“最终帧”与“任意帧”指标之间存在张力。判题器读 8 个等间隔帧，同时报告最终帧正确率和任意帧正确率；两者差距可以反映模型是否在过程中算对但最后写错，或是否在某一帧偶然出现正确答案。这个指标设计提醒读者：像素空间的“过程正确”不等于“最终答案正确”。

（9）失败模式具有诊断价值。现有系统的典型失败是答案框空白或涂鸦；后训练生成器的失败是能复制但不会算；从零像素模型的失败则可能集中在长程步骤、事实知识或复杂布局。论文的作者结论是：当前视觉生成器的推理失败更像训练范式造成，而不是像素介质本身不能推理；但这一结论的适用范围应限定在合成任务与受控画布内。

Q6: 有什么可以进一步探索的点？

（1）规模扩展与 scaling law。论文的结论明确说“scaling this paradigm up is the natural next step”。可以进一步问：像素空间推理是否像文本 LLM 一样随参数、数据、训练步数呈现可预测的 scaling？33M 模型只是存在性证明，更大模型是否在算术、事实、长程任务上持续提升，还是会被像素序列长度和分辨率成本卡住，是首要问题。

（2）从合成画布走向自然视觉。当前任务是灰色画布、固定等宽字体、受控网格；未来可以扩展到自然图像中的文字、手写、图表、公式、地图、UI、CAD 图和科学示意图。关键挑战是字体、布局、噪声、遮挡、多语言和分辨率变化，这些都会影响“读像素—推理—写像素”的闭环。

（3）架构与 tokenization。论文没有在检索片段中展开 pixel model 的具体 backbone。未来可以比较自回归像素预测、扩散/flow matching、离散视觉 token、连续 latent canvas 等不同架构在推理任务上的归纳偏置；也可以研究自适应分辨率、局部裁剪、稀疏画布更新，以降低长序列像素推理的成本。

（4）过程监督与验证。像素中间步骤是可观察的，因此可以训练过程奖励模型、步骤级判题器或一致性检查器，判断每一步是否忠实于问题，而不仅看最终答案。还可以研究模型能否在画布上擦除、重写、自我纠正，以及错误步骤如何传播。

（5）文本与像素的混合推理。论文为了归因，刻意移除文本通路；但实际系统未必要二选一。可以研究“文本作为工具、像素作为共享工作区”的混合架构：文本模块负责检索和语言先验，像素画布负责空间操作、可视中间状态和可检查的推理轨迹。关键是不要让文本模块再次把答案算完，生成器只负责渲染。

（6）可解释性与忠实性。像素链式推理看起来直观，但模型可能写出“看起来合理”的中间步骤而实际计算并不依赖它们。未来需要因果干预：删除或替换某一中间帧，看最终答案是否相应改变；或者用探针分析模型内部状态，判断像素步骤是外部记忆、正则化, 还是事后解释。

（7）长程推理与错误累积。十个任务大多是短程、可分解的；未来可以扩展到更长步骤、更多分支、需要回退和重试的任务，例如多步几何证明、复杂表格计算、迷宫规划、机器人动作序列。逐帧生成会遇到误差累积、画布空间不足和全局一致性等问题。

（8）评测协议。需要更严格的基准：答案可见性可控、训练分布与测试分布分离、过程与最终答案分别评分、视频/序列任务区分“曾经正确”和“最终正确”。还应报告判题器的解析失败率、空白率、格式错误率，避免把“写不出来”误判为“算错”。

（9）跨领域应用。论文的愿景覆盖音频频谱图、触觉压力图、机器人轨迹等；可以进一步验证同一画布范式是否能统一这些模态。对 AI-for-science，图表理解、曲线拟合、实验示意图和科学公式推导是潜在场景，但当前论文只提供合成任务证据，离真实科学应用还有明显距离。

Q7: 总结一下论文的主要内容

一、研究问题。论文从一个 provocatively simple 的观察出发：在作者能够检查管线的图像编辑、视频生成和统一多模态系统中，画布上的正确答案几乎都先以文本 token 形式出现。生成模块可以读画布、写文本，但真正的推理发生在 prompt rewriter 或文本模块，生成器只是把已经算好的答案渲染成像素。作者因此提出：如果视觉要成为统一所有模态的基底，就必须证明像素生成器能够完全不依赖文本通路，直接在画布上读取问题、写出中间推理步骤并给出答案。

二、审计现有系统。论文检查了图像编辑、视频生成和统一多模态系统的管线，并用三类证据支撑其归因：第一，Figure 3 显示四个图像编辑模型（FLUX.2-klein、FLUX.3-klein、Qwen-Image-2.1、LongCat-Image-Edit）未经后训练时在所有任务上都是 0%；第二，只对生成模块做 LoRA 后训练，可以教会它复制可见字符串，但准确率随答案可见性下降而陡降，Arithmetic 与 Factual 只有 0% 到 2%；第三，关掉 prompt rewriter 后，两个图像编辑模型在每个样本上都留空答案框，Wan 3.0 则留空或写“17”“#ab)”一类涂鸦。作者据此认为，现有系统的“视觉推理”主要是文本模块在推理，生成器只负责渲染。

三、像素空间任务套件。论文构建十个任务，分成五组配对：Expressions/Multiplication、Word Problems/Factual Questions、Mazes/Sum Mazes、Curve Tracing/Trace Then Sum、Count Then Paint/Compute Then Paint。每个任务是一张方形灰色画布，192×192，Word Problems 为 256×256；文本用固定等宽字体渲染在 24 列、12 行、每格 8×16 像素的网格上。问题写在水平线上方，正确的中间推理步骤也写在上方，最终答案写在下方两行答案区；曲线、区域、点等视觉元素画在剩余空间。这个设计的巧妙之处在于，它把“读题—推理—写答案”全部放在同一像素画布上，同时用配对任务分离感知、追踪、计数、计算和涂色等子能力。

四、从零训练的像素模型与训练范式。论文移除文本通路，构建纯视觉世界，训练 pixel model。模型至少包括 33M 参数级别；每个推理步骤由模型直接写在像素上。训练分为两种 regime：direct answering 把原始问题画布直接映射到带答案的最终画布，不写中间步骤；frame-by-frame reasoning 在画布状态序列上训练，让模型逐帧写出中间推理。摘要明确说，两者使用相同模型架构、相同训练数据和相同训练预算，并在 40k 步等预算下比较。训练示范不是固定模板：检索片段提到最优示范会在每一帧随机执行一到三个操作，并以一定概率换到新行，因此监督包含可变长度、可变位置的中间步骤。

五、主要结果。现有生成器的结果呈现“复制—推理”双分离：Copy 类可以被后训练学会，Instruction、Context、Visual 逐步下降，Arithmetic 与 Factual 接近零。从零训练的 33M 像素模型则给出了正向存在性证据：在未见问题上，它的 rollout 可以交织算术、点计数、区域涂色，或者曲线追踪与求和。逐帧推理与直接回答的等预算比较是论文的核心训练范式证据；摘要的行文方向表明“写中间步骤”带来收益，但检索片段在具体数值处截断，精确提升幅度需要回原文。论文还报告了三步 Word Problems 在更换名字后的泛化，以及不同模型规模下的 Word Problems 结果。

六、结论与边界。作者在结论中把问题拉回到模态统一：他们问视觉能否统一其他模态，并从“画布上的文本符号推理”这个最难的第一关开始。结论认为，当前视觉生成器的失败源于训练方式，而不是像素本身不能承载推理；因此视觉可以成为统一文本与其他模态的可信基底，下一步自然是 scaling。这个结论很有冲击力，但证据边界也很清楚：任务都是合成画布、固定字体、有限任务家族，模型规模较小，训练预算有限，事实题还涉及从零学习世界知识的困难。读者应把论文理解为“像素空间推理可行的强存在性证明”，而不是“像素模型已经替代文本 LLM 的开放域推理”。
