# OmniScore-Bench: Evaluating Vision-Language Models on Musical Score Reading

> ★★★★☆ 推荐阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：vision-language model · optical music recognition · benchmark · musical score understanding

## 一句话总结

论文提出 OmniScore-Bench：用 3,000 道题、6 个能力方面、24 个任务子类型，把「VLM 读乐谱」拆成符号定位、对象关联、结构转录、音乐一致性与证据链接问答等可单独观测的操作来评测，并对 12 个 VLM 给出按操作分化的能力画像与跨 scope 的排名差异。

## 摘要

> 视觉语言模型（VLM）已经能够就乐谱回答问题，但它们「识别记谱符号—恢复乐谱结构—解释音乐含义」这三类能力需要分开评测。现有的光学音乐识别（OMR）资源主要建立检测与转录两类测量：单一的转录分数无法说明一个 VLM 乐谱阅读器强在哪里、卡在哪里。为此作者提出 OmniScore-Bench，用 3,000 道题覆盖 6 个方面与 24 个任务子类型来评测 VLM 的 OMR 能力。每道题都显式声明可见范围（visible scope）、附带参考标注（reference annotations）并规定答案模式（answer schema），从而支持自动评测，评测范围从符号定位一直到音乐一致性（musical consistency）与证据链接问答（evidence-linked question answering）。对 12 个 VLM 的评测显示出「按操作分化」的能力画像，并且在节选（excerpt）、单页（single-page）、多页（multipage）三类任务上，转录任务的领先模型并不相同。控制分析进一步考察了乐谱图像、辅助给定信息（auxiliary givens）以及不同细节层级的问题各自起到什么作用。

Q1: 这篇论文试图解决什么问题？

1. 论文要解决的问题（论文明确表述的部分）
论文把问题定义为：VLM 已经能「就乐谱回答问题」，但「回答得像」与「真的读懂了谱」是两件事。作者要求把三种能力分开检验——识别记谱符号（recognise notation）、恢复乐谱结构（recover its structure）、解释音乐含义（interpret its musical meaning）。这三者在端到端问答里被压缩成一个答案字符串，无法区分。

2. 为什么现有 OMR 评测不够（论文明确的论证）
作者的核心指控是「归因失败」：既有 OMR 资源建立的是检测（detection）与转录（transcription）两类测量，而「单一的转录分数无法揭示一个 VLM 乐谱阅读器的强项与瓶颈」。论文点名了这批资源的能力边界：DeepScoresV2 支持 musical-object detection；MUSCIMA++ 提供手写符号与符号间关系；单声部与钢琴谱（monophonic / pianoform）数据集支持转录；Sheet Music Benchmark（SMB）把扫描乐谱与标准化转录评测、OMR Normalised Edit Distance（OMR-NED）结合起来；MSU-Bench 则考察整谱理解，并报告了在视觉输入下的定位错误与幻觉。
这里的逻辑链是：MSU-Bench 已经证明「整谱级答案 + 视觉输入」会产生定位错误与幻觉，那么「一个 score-level 的答案本身无法区分失败发生在定位记谱符号、关联音乐对象，还是解释音乐后果这三个环节中的哪一个」。这是论文最锋利的一句动机陈述。

3. 更深一层的方法论问题：可观测性（observability）
作者给出的组织原则不是「更多题」，而是「让每一个被请求的操作单独可观测」。这是评测设计层面的主张：一个操作若不能被单独请求、单独判分，它就不能被诊断。由此推出的设计约束是——题目必须显式声明「你在这一题里能看到什么范围」（visible scope），必须带参考标注作为判分锚点，必须有答案模式使自动判分可行。这三条其实是「可观测性」在工程上的落地。

4. 隐含假设（合理推断，需要作者在正文中辩护）
- 分解可加性假设：假设把读谱拆成 24 个子操作分别测，能够预测或解释整谱级表现。但组合性失败（每一小步都对、串起来不一致，例如音高对了但节奏错位、跨谱表关联错）恰恰是乐谱理解的典型失败模式，评测设计需要显式检验「局部正确 → 全局正确」的传播关系。
- 语义可标注假设：假设「音乐含义」「音乐一致性」可以被参考标注穷尽刻画。乐谱的「含义」高度依赖和声、调性、体裁与分析传统，标注覆盖度直接决定这一层的效度。
- scope 与能力的解耦假设：excerpt / single-page / multipage 三档若被当作「同一能力的难度梯度」，则多页任务的失败可能来自上下文长度、分辨率下降或跨页指代，而不是乐谱阅读能力本身。作者用「不同 scope 上转录领先者不同」来呈现这一现象，但把该现象解释成能力差异还是工程约束差异，需要正文的受控分析支撑。

5. 边界条件与可能的反例
- 先验泄漏（prior leakage）：模型可能靠标题、作曲家、作品编号或常见曲目记忆来「猜」答案，而不是读谱。论文把 auxiliary givens 列为控制变量之一，说明作者意识到了这条通道（合理推断：控制分析的一大目的就是估计先验知识的贡献量）。
- 二维符号系统的空间语义：五线谱的音高编码在纵轴、时间在横轴，且有加线、临时记号、跨谱表连线等非局部依赖，这与自然图像的目标定位分布不同；VLM 的预训练视觉先验未必匹配（推测）。
- 判分刚性：answer schema 提升自动判分可行性，但会惩罚「正确的另一种表述」（例如等价的音名拼写、等价的时值表示），这类假阴性需要在正文中报告（证据缺口）。

Q2: 有哪些相关研究？

1. OMR 数据集与评测资源（论文明确点名的一支）
- DeepScoresV2：定位在 musical-object detection，面向密集符号的检测任务。
- MUSCIMA++：提供手写乐谱的符号与符号间关系标注，是「关系」这一维度上最直接的先行资源。
- 单声部与钢琴谱（monophonic / pianoform）转录数据集：论文以 [5, 15, 27, 30] 一并引用，片段中未给出具体数据集名（证据缺口；常见的 PrIMuS / Camera-PrIMuS / GrandStaff 一类名称并未在可见文本中出现，不应臆断）。
- Sheet Music Benchmark（SMB）+ OMR Normalised Edit Distance（OMR-NED）[17]：把扫描版乐谱与标准化转录评测绑定，给出可比较的编辑距离指标。这是本文最主要的「被超越的评测范式」参照物：它测的是转录结果序列层面的距离。
- MSU-Bench [7]：最贴近本文的问题设定——考察完整乐谱（complete-score）理解，并且报告了两类关键现象：视觉输入下的定位错误与幻觉。本文正是从这两个现象出发，主张必须把失败拆到操作级别。

2. 乐谱多模态数据集（引用片段中出现的一支）

Grohganz 等（片段中作者串有断行噪声）。这类工作提供的是「音频—乐谱—歌词—结构」对齐的多模态资源，属于「音乐分析场景」而非「读谱能力诊断」，因此在本文的谱系里更可能是数据来源或语义层参照，而不是直接竞品（合理推断）。片段中还出现「Astra music [6]」，疑为另一乐谱/音乐数据资源的引用，但可见文本不足以确认其身份，需核对参考文献 [6]。

3. 与 VLM 通用评测的关系（片段未直接覆盖，属外部脉络）
本文在方法学上属于「能力分解式多模态评测」：把文档理解、图表理解、OCR grounding 一类评测中已经成熟的「结构化答案 + 定位标注 + 自动判分」套路迁移到乐谱这一专门符号系统上。它与「单一总分排行榜」式评测构成范式竞争：后者追求可比性，前者追求可归因性。这一对立是本文最值得带走的方法论张力（合理推断，论文正文应有更明确的 positioning）。

4. 与符号音乐生成 / MIR 的关系（推断）
OMR 的输出（MusicXML / ABC / LilyPond 等符号表示）是符号音乐生成、风格分析、可演奏性检查等下游任务的前置环节，因此「VLM 能不能可靠读谱」直接决定这些下游流水线能否用 VLM 替代专用 OMR 系统。本文并不提出新模型，其竞争对象是「用 OMR 指标衡量 VLM」的既有做法，而非某个具体 OMR 系统。

5. 定位小结
本文相对先行工作的差异点不在数据规模，而在「评测单元」的选择：先行工作以谱面（score）或符号序列为单元，本文以「操作（operation）」为单元，并要求每个操作自带可见范围、标注与答案模式。相关工作的缺口也在这里——在 MSU-Bench 指出定位错误与幻觉之后，尚未有工作系统性地把读谱拆成 24 个子类型并给出跨 12 个模型的按操作画像（论文明确）。

Q3: 论文如何解决这个问题？

1. 总体思路：不改模型，改评测单元
论文的贡献是一个评测基准而非一个新模型。其组织原则一句话可概括：让每一个被请求的操作单独可观测。围绕这条原则，基准的每个实例都被设计成「可归因的最小单元」。

2. 三件套设计（论文明确的三个要素）
每道题都指定：
- visible scope（可见范围）：题目显式声明模型在这一题里能看到什么范围。从实验设置看，scope 至少分三档——excerpt（节选）、single-page（单页）、multipage（多页）。这是把「分辨率 / 上下文长度 / 跨页指代」这几类混淆因素显式化，而不是让它们隐藏在固定输入里。
- reference annotations（参考标注）：给判分提供锚点，使「定位类」答案可以与人工标注直接比对，而不是靠另一个模型打分。
- answer schema（答案模式）：规定答案的结构，使自动评测可行。这一步是「从符号定位到音乐一致性再到证据链接问答」这条评测链条能够统一跑通的关键工程约束。

3. 操作层级（从摘要可复原的阶梯）
- 符号层：symbol question 要求给出类别与坐标（classes and coordinates）。这是最底层的 grounding。
- 关系层：relation question 要求给出「哪些被识别出的对象彼此相关」，即把符号串成结构，而非孤立检测。
- 结构/转录层：把符号与关系组合成可比较的记谱序列，与 OMR 传统的转录测量对接。
- 语义/一致性层：musical consistency，检查解读在音乐上是否自洽。
- 证据链接问答层：evidence-linked QA，要求答案同时给出支撑证据（合理推断：证据指向谱面位置或标注 id），这是最高层、也最接近真实使用场景的操作。
（注：上述阶梯由摘要中「from symbol localisation to musical consistency and evidence-linked question answering」以及 symbol/relation 两类题的描述复原；六个 aspect 的确切命名与划分边界属证据缺口，需回原文核对。）

4. 规模与覆盖
3,000 道题，6 个 aspect，24 个 task subtype。以 3,000/24 计，平均每子类型约 125 题（这是算术推算，非论文报告数值）。这一规模说明设计取向是「广覆盖换取画像分辨率」，而不是「单任务大规模压测」。

5. 控制分析（作为方法的一部分）
论文设置了受控分析来考察三类因素的作用：
- score images：乐谱图像本身的作用。典型做法是有图 / 无图 / 退化图的对照，用来估计「模型到底有没有在看图」。
- auxiliary givens：辅助给定信息（如标题、作曲家、调号、乐器、上下文文字等）的作用，用来估计先验知识与外部提示的贡献。
- questions at multiple levels of detail：同一乐谱上不同细节粒度的问题，用来估计粒度对成功率的影响。
这三组控制实际上把「读谱能力」与「先验猜测」「语言推理」「分辨率」分离开，是本文相对普通 benchmark 最像「实验」而非「测榜」的部分。

6. 设计权衡（需要在正文中验证的代价）
- 可判分性 vs 表达自由度：answer schema 收紧答案空间，可能把等价正确表述判为错误。
- 分解粒度 vs 生态效度：24 个子类型的细粒度诊断力强，但每个子类型的题量与统计功效会被摊薄；子类型之间的相关性结构（是否真的存在 24 个可分离能力）需要因子分析或 IRT 一类证据支撑（合理推断，属可加强之处）。
- scope 分档 vs 可比性：三档 scope 让排名对输入条件敏感，提升了现实性，但也意味着「谁是第一」必须绑定 scope 陈述——这恰好是论文报告的核心发现之一。

Q4: 论文做了哪些实验？

1. 评测对象
12 个视觉语言模型（论文明确为 twelve VLMs）。具体模型清单、是否含闭源/开源、是否含专用 OMR 系统、是否含人类专家基线，在本次可见证据中均未出现（证据缺口，需回原文核对）。

2. 评测矩阵
- 题目：3,000 道，6 个 aspect，24 个 task subtype。
- scope：excerpt / single-page / multipage 三档。摘要明确以这三档报告转录任务的领先者差异，因此三档是并行的实验条件，而非单一难度梯度。
- 操作层级：符号定位 → 关系 → 转录 → 音乐一致性 → 证据链接问答。

3. 指标设计
评测目标是「从 symbol localisation 到 musical consistency 再到 evidence-linked QA」的自动评测。合理推断：符号层用类别 + 坐标匹配（如 IoU 或点距离阈值）计分；转录层沿用或对齐 OMR 传统的序列距离（论文把 OMR-NED 作为先行范式点名，是否直接采用需核对）；一致性层与证据链接层需要基于标注的规则化判分或结构化比对。具体阈值、是否报告置信区间、是否做显著性检验，均为证据缺口。

4. 控制实验（消融式设计）
- 乐谱图像的作用：有图 / 无图（合理推断还包括图像退化或裁剪）对照，用于量化视觉输入的边际贡献。
- 辅助给定信息（auxiliary givens）的作用：控制模型能拿到多少外部提示，用于分离「读谱」与「靠先验/上下文推断」。
- 问题细节层级：同一乐谱上不同粒度的问题，用于观察粒度—成功率关系。
这三组是本文最有信息量的实验，因为它们回答的是「模型凭什么答对」，而不只是「答对多少」。

5. 分析维度
- 按操作（operation）而非按模型出报告，得到 operation-specific capability profiles。
- 按 scope 出报告，观察排名是否随 scope 改变。
这两条构成了论文的分析骨架：能力画像（横向）+ 条件敏感性（纵向）。

6. 证据缺口清单（必须在原文核对才能引用为事实）
- 12 个模型的具体名单与版本、推理配置（是否 few-shot、是否 CoT、图像分辨率上限、是否多图输入）。
- 六个 aspect 的名称与 24 个 subtype 的完整列表。
- 每个子类型的题量与难度分布；题目是否按作品/作曲家划分以避免记忆污染。
- 标注者数量、标注一致性（IAA）、参考标注的来源（人工 / 合成 / 既有数据集转换）。
- 具体分数、置信区间、模型间差异的显著性。
- 是否有 cost/latency 报告，是否有失败案例分析章节。

Q5: 发现了什么实验现象？

以下第 1–3 条由摘要明确支持；第 4–7 条为基于设计线索的合理推断或推测，需回原文核对具体数值与方向。

1. 能力是「按操作分化」的，不是单一标量
论文明确报告 12 个 VLM 呈现 operation-specific capability profiles。这句话的方法论含义比数值更重要：读谱能力不构成一个单因子。一个模型可以在符号定位上很强而在音乐一致性上很弱，反之亦然。若把这类模型放进单一转录指标排行榜，排序会掩盖能力结构。

2. 没有全局最强：转录领先者随 scope 改变
摘要明确指出「different transcription leaders across excerpt, single-page and multipage tasks」。这是本论文最反直觉、也最有实践后果的现象：在节选上最好的模型，在单页或多页上未必最好。可能的解释有三类（推测，需正文判别）：(a) 分辨率与 token 预算的权衡在不同 scope 下方向不同；(b) 多页需要跨页结构一致性（反复记号、排练号、分谱），是另一种能力；(c) 训练数据里的谱面尺度分布与不同 scope 的输入分布匹配程度不同。

3. 熟练度取决于「操作 + 所需表征」
摘要的原句（去噪后）表明：模型的熟练度取决于操作类型与所需表征（required representation）。也就是说，同一个音乐对象，要求输出「坐标」、输出「类别名」、输出「与其他对象的关系」、输出「音乐后果」，对模型而言是不同难度量级的任务。这为「为什么端到端转录会误判模型能力」提供了机制解释。

4. 图像的作用可能不是单调正向（合理推断）

Q6: 有什么可以进一步探索的点？

1. 从「分解评测」到「分解训练」
本文证明了操作级观测可行。自然的下一步是把 operation-level 的标注转成过程监督：对符号定位、关系判定给稠密奖励，用 RL 或过程奖励模型训练读谱能力，而不是只对最终答案给稀疏奖励。这与 agent 方向的连接点在于「工具调用 + 自校验」：模型可以先调用 OMR 工具得到候选符号，再用视觉证据复核，评测则可复用本文的 evidence-linked QA 协议来判分（合理推断的延伸方向）。

2. 组合性与一致性建模
最关键的科学问题不是「每个子任务多少分」，而是「局部正确如何传播为全局正确」。可行的研究议程：构造同一乐谱上的「子任务正确性 → 端到端转录正确性」配对数据，拟合传播模型，找出瓶颈环节（例如关系层是瓶颈还是语义层是瓶颈）。若发现「关系层饱和但转录仍错」，则说明瓶颈在时序/排版约束，而非符号识别。

3. scope 与分辨率的 scaling 规律
论文已显示排名随 excerpt / single-page / multipage 变化。可进一步做受控 scaling：固定乐谱内容，只变图像分辨率、切片策略、页数，测量各操作的成功率曲线，分离「视觉带宽」与「上下文长度」两种约束。这对任何长文档 VLM 评测都有迁移价值。

4. 抗先验泄漏的评测协议
auxiliary givens 的控制分析提示了先验通道的存在。可探索：按作曲家/作品做严格划分、使用新近或未发表作品、对元信息做遮蔽、构造「同一谱面换标题」的反事实题，量化标题对答案的因果影响。这类反事实设计比单纯扩大题量更能提升基准效度。

5. 「音乐一致性」的可操作定义
当前 musical consistency 依赖标注。可探索把一致性下沉到可判定的音乐理论约束（声部进行规则、调性内和弦、节拍重音对齐），用约束求解器自动检验，从而把主观判断转为可复现的判分。这也会带来新的失败模式分类学。

6. 跨符号系统与跨版式泛化
五线谱之外还有简谱、tablature、中世纪记谱、手写谱、总谱与分谱。OMR 的既有资源已经区分印刷/手写，本文则在 scope 上做区分。下一步可做「符号系统 × 版式 × scope」的三维泛化矩阵，检验能力是通用的视觉符号 grounding 还是五线谱专用。

Q7: 总结一下论文的主要内容

一、论证主线
论文的起点是一个看起来已经被解决的问题：VLM 能够就乐谱回答问题。作者把这个表面能力拆成三层——识别记谱符号、恢复乐谱结构、解释音乐含义——并主张这三层需要分开评测。随后给出归因论证：既有 OMR 资源建立的是检测与转录两类测量，而「单一的转录分数无法揭示一个 VLM 乐谱阅读器的强项与瓶颈」。这条论证被两个具体现象加固：MSU-Bench 已经报告了视觉输入下的定位错误与幻觉，说明整谱级答案本身不可靠；而一个 score-level 的答案无法区分失败发生在「定位记谱符号」「关联音乐对象」「解释音乐后果」中的哪一环。

二、技术主线（评测即方法）
作者没有提出新模型，而是把方法论创新放在评测单元上。组织原则是「让每一个被请求的操作单独可观测」。落地为三件套：每道题显式声明 visible scope（可见范围），携带 reference annotations（参考标注）作为判分锚点，规定 answer schema（答案模式）使自动判分可行。操作阶梯从低到高为：符号题（要类别与坐标）→ 关系题（哪些被识别出的对象彼此相关）→ 结构/转录 → 音乐一致性 → 证据链接问答。规模为 3,000 道题、6 个 aspect、24 个 task subtype。

三、实验主线
评测 12 个 VLM。scope 分 excerpt / single-page / multipage 三档并分别报告，因此「谁是转录第一」必须绑定 scope 陈述。核心发现有三条：其一，模型呈现 operation-specific capability profiles，即读谱能力不是单因子；其二，转录领先者在三档 scope 上不同，没有全局最强；其三，模型熟练度取决于操作类型与所需表征。除主实验外，论文设置了三组受控分析：乐谱图像的作用、辅助给定信息（auxiliary givens）的作用、以及不同细节层级问题的作用——这三组分析的功能是把「真的在读谱」与「靠先验/上下文猜」区分开。
