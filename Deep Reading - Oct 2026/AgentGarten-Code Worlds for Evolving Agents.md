# AgentGarten: Code Worlds for Evolving Agents

## 一句话总结

AgentGarten 通过把模拟器/游戏引擎的程序化世界状态与共享的实时神经渲染器耦合，构造既保持显式状态与规则、又具备真实视觉分布的“代码世界”，使智能体仅用 4 轮交互经验即可完成传统强化学习需数百万步才能掌握的任务。

## 摘要

> 论文提出 AgentGarten 框架，将模拟器或游戏引擎与一个共享的神经渲染器结合，用于构建实时交互环境。模拟后端维护持久世界状态并执行程序定义的交互规则；渲染器通过统一接口读取结构化条件，生成视觉观测。神经渲染器以预训练视频模型为基础，适配几何条件，并通过研究者提出的 Adversarial Forcing 进行蒸馏，同时优化推理以实现实时交互。Adversarial Forcing 通过精确重放（exact replay）使历史预填充变得可微，让后续预测的损失能够更新渲染器对先前观测的编码，并加入真实数据对抗监督以提升视觉质量。在 AgentGarten 中，智能体通过视觉观测感知世界、实时交互，并将每一轮经验蒸馏成 playbook，供后续智能体继承与改进。实验表明学习效率显著提升：智能体仅用 4 轮即可学会任务，而传统强化学习需要数百万轮。新世界可以写成代码并通过同一接口渲染，因此环境数量与难度可以随智能体同步扩展。

Q1: 这篇论文试图解决什么问题？

论文试图解决的核心问题是：交互式虚拟环境需要同时具备“忠实性”（faithful，即状态、规则、动态一致）与“真实性”（realistic，即视觉观测符合真实世界分布），但现有方案在这两点之间存在根本性权衡。模拟器和游戏引擎拥有显式状态和可编程交互规则，能够支持智能体学习，但扩充视觉多样性需要大量 3D 资产生成和复杂渲染管线，导致新环境构建和定制成本极高。视频世界模型能够从数据合成丰富、可交互的视觉观测，但任务相关的状态和物理转移规则隐含在生成历史与学习表征中，无法直接检查、编辑和测试环境行为。AgentGarten 的目标是同时获得可控制、可检查的动态和多样化的视觉观测，从而支持导航、操控、多智能体交互等多种任务的可扩展、可泛化智能体训练。

Q3: 论文如何解决这个问题？

AgentGarten 的解决方案分为三个层面。第一，环境层面：每个场景程序（scene program）运行在模拟器或游戏引擎中，维护持久状态并执行显式交互规则；引擎通过统一接口导出结构化条件（如深度图和表面法线），供渲染器生成视觉观测。这样，“世界的物理/逻辑”由代码定义，可检查、可编辑、可测试。第二，渲染层面：构建共享的神经渲染器，以预训练视频模型为基础，将其适配到几何条件上；训练时使用论文提出的 Adversarial Forcing 目标。Adversarial Forcing 包含三个组成部分：基础自回归/自强制目标（Self Forcing，细节在附录 A.4 中）、通过精确重放恢复历史编码梯度的 replay 项、以及使用真实视频监督的对抗损失。具体而言，标准 Self Forcing 中历史预填充不可微；exact replay 通过只改变注意力执行方式（例如 block-by-block SDPA 与 full-sequence FlexAttention 的对比）实现逐位一致的重放，从而让后续预测的损失能够更新先前观测的编码。对抗损失则从真实视频中提供监督，改善视觉质量。第三，推理层面：为实时交互优化，包括手写 kernel、CUDA graph 捕获和极小的 decoder，使 480×832 分辨率视频在单张 H100 上达到超过 35 FPS 的生成速度。第四，智能体学习层面：智能体通过视觉观测感知世界，实时交互，并将每一轮经验蒸馏成 playbook，供后续智能体继承和细化，从而绕过 tabula rasa 探索。

Q4: 论文做了哪些实验？

论文实验分为三个主要部分。一是视觉质量评估：比较 Self Forcing 与 Adversarial Forcing 训练的渲染器在相同条件轨迹上的 30 秒 rollout 表现。二是重放精度评估（对应 Table 1）：在仅改变注意力执行方式的情况下，测量全序列 FlexAttention 重放与缓存 rollout 之间的相对 L2 误差，以及 block-by-block SDPA 重放的一致性；同时测量前向时间与峰值内存变化。三是推理吞吐量评估（对应 Table 2）：在单张 NVIDIA H100、BF16、480×832 输出、四步采样器、四潜帧块等条件下，测量端到端生成速度（包括条件编码、四步去噪、解码和主机传输）。设置中缓存保留 5 个 sink 帧和 44 个 Recent 潜帧，即每个四帧块需要 attend 49 帧历史；吞吐量在缓存填满后的稳态下测量（48-block、769 帧 rollout 的第 17–48 block）。四是智能体学习效率实验：比较 AgentGarten 中智能体通过 playbook 经验蒸馏的学习（约 4 轮）与传统强化学习（数百万轮）的样本效率；同时涉及多个场景，包括导航、操控、工具使用、车辆、多智能体 hide-and-seek、自博弈 RL 对照，以及两个智能体共享一个世界状态的第三人称视角设置。

Q5: 发现了什么实验现象？

实验现象可归纳为以下几点。第一，在长程 rollout 中，Self Forcing 训练的渲染器会发展出重复的表层纹理模式，并逐渐丢失场景细节；Adversarial Forcing 则能在整个 30 秒 rollout 中保持自然纹理和精细细节。第二，重放精度方面，全序列 FlexAttention 重放与缓存 rollout 的相对 L2 误差为 3.99%，而 block-by-block SDPA 重放与缓存 rollout 逐位一致（bitwise identical）；重放前向时间相比缓存减少 5.4%，峰值内存变化仅 0.2%。这说明精确重放可以在几乎不影响运行时开销的前提下恢复历史编码的可微性。第三，推理吞吐量方面，渲染器在单张 H100 上可生成超过 35 FPS 的 480×832 视频，达到实时交互要求。第四，在智能体学习层面，带有反思式 playbook 的智能体能够利用通用先验绕过 tabula rasa 探索，快速收敛到物理环境中的有效工具使用策略；与传统强化学习动辄数百万轮相比，仅需约 4 轮。第五，在 hide-and-seek 场景中，只能通过渲染观测感知的智能体在约第 4 轮出现掩体（shelter），在第 10 轮出现斜坡穿越（ramp crossing）行为；同样的流程还在另外四个不同世界中改善了结果。检索片段还显示自博弈 RL 相关设置以及两个智能体共享世界状态的第三人称视角渲染，但具体定量结果在可用证据中未完整呈现。

Q6: 有什么可以进一步探索的点？

论文在结论中指出了若干可进一步探索的方向。一是设计更紧凑、更完整的条件表示：深度图和表面法线虽然实用，但稠密几何视频冗余较大——物体形状一旦确定，刚体运动只需少量位姿参数描述，而条件视频会在大量像素和帧中重复表面信息。空间下采样虽可降低成本，但可能丢失精细控制所需的薄结构、窄间隙和小接触变化。二是补足几何条件缺失的状态信息：例如旋转对称物体在深度/法线上可能不变，但表面涂装的标记在旋转；材质、颜色和物体身份也无法由几何唯一确定。三是利用代码世界已有的更抽象、更紧凑的状态表示，例如描述物体属性和交互状态的结构化文本，或高维潜特征；结构化文本可以指定子弹旋转的方向和角速度等。但将这类表征与代码世界状态对齐、并让预训练视频模型适应它们，仍是开放问题。四是处理视觉历史的长期保持问题：视觉历史可以保留几何无法刻画的属性，但在长时间遮挡或访问超出记忆窗口后可能丢失，需探索更长记忆或更持久的状态编码。

Q7: 总结一下论文的主要内容

论文的核心论点是：智能体的能力受限于其练习环境；理想的训练环境必须同时具备“忠实性”（状态、规则、动态一致且可检查）和“真实性”（视觉观测符合真实世界分布），但现有模拟器/游戏引擎与视频世界模型分别只能满足其一，存在根本性权衡。AgentGarten 提出的解决方案是把两者耦合：每个场景程序运行在模拟器/游戏引擎中，以代码形式定义持久状态和交互规则，并通过统一接口导出结构化几何条件；一个共享的神经渲染器实时生成视觉观测，为智能体提供逼真的“眼睛”。这样，环境的物理/逻辑层是显式可编程的，而视觉层由数据驱动的渲染器补全，从而绕过了传统 3D 资产生成的高成本。神经渲染器的训练采用论文提出的 Adversarial Forcing：在自回归自强制目标基础上，通过精确重放（exact replay）让历史预填充变得可微，使后面预测的损失能够反向更新先前观测的编码；再加入真实视频的对抗监督，改善长程 rollout 的视觉保真度。推理侧通过手写 kernel、CUDA graph 和微型 decoder 实现实时性能（480×832 在 H100 上超过 35 FPS）。在智能体学习侧，智能体通过视觉观测感知世界并实时交互，每轮经验被蒸馏成 playbook，由后续智能体继承和细化，大幅提升样本效率：约 4 轮即可完成传统强化学习需要数百万轮的任务。实验还展示了多类场景（导航、操控、工具使用、车辆、多智能体 hide-and-seek）以及自博弈 RL 对照，说明框架的通用性。论文最后讨论了当前几何条件接口的冗余与不完备问题，并展望了用结构化文本或潜特征等更紧凑、更完整的条件表示来进一步推进。整体上，这篇论文提出了一种“代码世界 + 神经渲染器 + 经验迭代”的环境构建范式，目标是让环境和智能体以代码规模同步演化。
