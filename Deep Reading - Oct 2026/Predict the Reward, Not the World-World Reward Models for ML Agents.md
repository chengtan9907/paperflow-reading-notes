# Predict the Reward, Not the World: World Reward Models for ML Agents

> ★★☆☆☆ 按需阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：world reward model · ml agents · program search · pairwise preference learning

## 一句话总结

论文提出 World Reward Models（WRM）：不预测程序执行结果，而是从真实执行产生的程序对中学习直接判断哪个候选更优，并用 9B 的 ForeCritic 在 26 个 ML 任务的 12,438 个留出程序对上取得 79.4% 的成对选择准确率。

## 摘要

> 搜索式机器学习（ML）agent 通过编写候选程序、执行候选程序并保留最优结果来改进方案。真实执行能提供可靠反馈，但单次运行可能耗时数小时，而且多数候选最终会被丢弃。近期方法让大语言模型充当 world model，预测每个程序的执行表现，以节省执行成本；但预测错误会把虚假信息注入搜索。论文主张，agent 不需要预测执行结果，只需要预测执行会支持哪个选择。为此提出 World Reward Models（WRMs），从真实执行结果中学习直接选择更优候选，不预测任何中间结果。论文证明：在相同输入下，先预测执行再选择的选择器不能超过最佳直接选择器；预测结果引入的误差可使 likelihood-trained world model 在每个实例上都偏好更差程序；在 executed winners 上使用 cross-entropy 可驱动 WRM 趋向最优。作者实现 ForeCritic，将 9B typed decision model 适配到 5k 个已执行程序对；在来自 26 个 ML 任务的 12,438 个留出程序对上，选择更优程序的准确率为 79.4%。

Q1: 这篇论文试图解决什么问题？

一、问题定义
搜索式机器学习（ML）agent 把任务求解写成一个程序搜索循环：LLM 生成若干候选程序，执行器运行并给出真实分数，agent 保留当前最优，再基于反馈生成下一轮候选。这个循环的优点是反馈真实，缺点是每一次执行都可能耗时数小时；更严重的是，大量候选程序最终会被丢弃，搜索预算被消耗在“试错”而不是“改进”上。论文要解决的核心问题因此是：能否在不执行所有候选的情况下，仍然可靠地决定应该保留哪个程序，从而把真实执行留给真正值得运行的候选。

二、现有解法为何不够
近期 agent 让 LLM 充当 world model，先预测每个候选程序的执行结果或分数，再按预测排序。论文认为这条路线存在目标错配：world model 优化的是“预测执行结果”，但搜索真正需要的是“做出正确选择”。预测结果只是中间变量；一旦预测错误，搜索就会把更差的程序当成更好的程序，错误信息还会进入后续迭代。摘要强调“a wrong prediction feeds the search false information”，说明作者关注的不是预测误差本身，而是误差如何改变搜索轨迹。

三、论文的核心质疑
论文的核心质疑可以概括为：不要预测世界，直接预测奖励/选择。也就是说，agent 不需要知道某个程序会得 0.83 还是 0.70，只需要知道在执行反馈下哪个候选更可能胜出。这个重构把绝对结果预测转成相对决策问题，使训练目标与搜索目标对齐。

四、论文要回答的研究问题
1. 在相同输入与同一候选集上，先预测执行再选择的选择器，是否可能优于直接选择器？
2. 预测执行结果的误差在什么条件下会系统性伤害排序，甚至让 world model 在每个实例上都偏好更差程序？
3. 用什么训练目标可以让直接选择器逼近最优？
4. 在真实 ML 任务上，少量真实执行对是否足以训练出可用的 WRM？

五、隐含假设与边界
论文的论证依赖若干前提：直接选择器类有足够表达能力；训练与测试的任务/程序分布可比；程序优劣可由执行分数定义；ties、噪声、非传递性偏好没有在摘要中展开；WRM 的推理成本低于真实执行成本。若这些前提不成立，直接选择的优势可能缩小。尤其是“same inputs”下的理论结论，主要说明“预测再选择”不带来表达力上的额外收益；在有限数据下，预测式模型仍可能因归纳偏置或正则化而表现更好，这一点需要看原文定理的精确假设。

Q2: 有哪些相关研究？

一、搜索式 ML agent 与程序搜索
论文所在的直接背景是搜索式 ML agent：agent 不是一次性生成答案，而是维护候选程序池，反复生成、执行、评分、保留最优。摘要片段明确提到 AIDE（Jiang et al., 2025），并把它作为“engineering agents treat a task as a search over programs”的代表。此类工作的共同点是依赖真实执行反馈，因而可靠但昂贵；论文要解决的正是这种“可靠但太慢”的瓶颈。

二、LLM 作为 world model
第二条相关路线是让 LLM 预测程序执行表现，用预测分数替代真实执行。摘要称近期 agent 尝试让 LLM 充当 world model，预测每个程序会如何表现。这条路线与模型-based RL、程序性能预测、代码执行结果预测有相邻关系。论文的批评是：预测结果是中间变量，预测误差会污染搜索；而且 likelihood/回归训练并不直接优化候选排序。

三、reward model 与 pairwise preference learning
WRM 的名字表明它与 reward model 传统相关：不建模环境，而是学习一个打分/偏好函数。论文从真实执行结果构造程序对，让模型判断哪个更好；这接近 pairwise preference learning、Bradley-Terry 类排序模型和 RLHF 中的 reward model。区别在于，这里的“偏好”来自程序执行分数，而不是人类标注；模型被用作搜索中的 critic/selector，而不是直接做策略优化。

四、decision-focused learning 与 predict-then-optimize
论文的理论主张与 decision-focused learning 的论点相邻：当预测结果最终服务于一个决策问题时，应直接优化决策质量，而不是只优化预测精度。传统 predict-then-optimize 先预测参数再求解，可能因预测误差与决策损失不一致而次优。论文把这一逻辑推到程序选择：先预测执行再排序，不如直接学习排序。这个归类是基于论文主张的合理推断，摘要没有逐条列出这些文献。

五、critic、verifier 与 reranking
WRM 也可以放在 LLM critic/verifier/reranker 的谱系中：给定任务和候选程序，模型输出相对判断，用于筛选候选。与 prompting 式 LLM-as-judge 不同，WRM 是在真实执行对上训练的专门模型；与执行器不同，它不运行程序。论文的贡献在于把“critic”从辅助提示提升为搜索的核心决策模块，并给出理论依据。

六、定位与证据边界
当前证据只来自摘要和图注，无法确认论文实际引用了哪些工作、与哪些 baseline 做了定量比较。可以确认的相关锚点是 AIDE 与 LLM world model 路线；其他归类属于相邻研究传统的框架性定位，不应视为论文原文的完整 related work 列表。

Q3: 论文如何解决这个问题？

一、总体思路：把 outcome prediction 改成 relative decision
论文的方法论核心是“预测奖励，不预测世界”。给定任务描述和两个候选程序，WRM 不输出每个程序的执行分数，而是直接输出哪一个更优，或给出候选胜出的概率。训练信号来自真实执行结果：执行过的程序对中，分数更高者作为 winner。这样，模型优化的是排序/选择损失，而不是执行结果的似然或回归误差。

二、ForeCritic 的模型与数据
作者实现 ForeCritic，把一个 9B typed decision model 适配到 5k 个已执行程序对。摘要使用“adapts”一词，具体是全参数微调、参数高效微调还是其他适配方式，当前证据无法确认。“typed decision model”中的 typed 具体指类型系统、结构化输入还是某种决策头，也需要原文核对。可以确认的是：模型规模为 9B，训练数据为 5k 个真实执行程序对，输出用于候选选择。

三、训练目标
论文证明“cross-entropy on executed winners drives a WRM toward the optimum”。直观理解是：对真实执行中胜出的程序做 cross-entropy（或等价的 pairwise 分类损失），使模型提高 winner 相对 loser 的决策概率；当训练分布覆盖候选对、模型类足够表达时，最小化该损失会逼近最优选择器。具体损失形式是二分类 cross-entropy、pairwise softmax 还是 listwise 目标，摘要没有给出公式，需要看方法节。

四、三个理论结果
1. 预测再选择不优于最佳直接选择：在相同输入下，任何“先预测执行结果、再根据预测做选择”的选择器，都可视为直接选择器类中的一个受限子类；因此最佳直接选择器至少不会更差。这个结论说明，预测执行结果本身不创造额外的决策信息。
2. 预测误差可使 likelihood-trained world model 系统性偏好更差程序：似然训练优化的是观测结果的概率，不保证 pairwise ordering；在某些实例上，预测误差可能让模型在每一个实例上都选错。这比“预测偶尔错”更强，指向目标错配导致的系统性失败。
3. executed winners 上的 cross-entropy 驱动 WRM 趋向最优：把训练信号直接对齐到“谁赢”可避免中间结果预测的误差传播。

五、推理与搜索集成
推理时，WRM 对候选程序做相对比较，选择它认为更优的程序；搜索只执行被选中的候选，或用 WRM 先做 top-k 剪枝，再对少量候选做真实执行。图 1(c) 用“learns from real executions”“no outcome predicted”概括这一流程，并给出 P(win)=0.86 的示意。具体搜索算法如何嵌入、是否每轮只选一个、是否保留候选池，当前证据不足。

六、设计取舍
WRM 的优点是把容量集中在决策边界上，利用相对标签，避免绝对分数尺度问题；缺点是依赖高质量的程序对，可能忽略分数差距的大小，对 ties、非传递性和多候选排序需要额外处理。与 world model 相比，WRM 不提供可解释的中间分数，也不一定能预测“差多少”；它只回答“选哪个”。

Q4: 论文做了哪些实验？

一、可确认的实验骨架
1. 训练数据：5k 个已执行程序对（executed program pairs），标签来自真实执行结果中的相对优劣。
2. 模型：ForeCritic，基于 9B typed decision model 适配。
3. 评估数据：来自 26 个 ML 任务的 12,438 个留出程序对（held-out pairs）。
4. 主指标：成对选择准确率，即从两个候选中挑出真实执行分数更高者的比例；ForeCritic 为 79.4%。
5. 对照线索：图 1(b) 标注 LLM world model 约 60% 正确；图 1(a) 展示真实执行搜索的候选分数；摘要片段提到 AIDE。
6. 理论部分：三项命题，分别关于预测再选择的表达力上限、likelihood-trained world model 的系统性排序错误、以及 executed winners 上 cross-entropy 的最优性驱动。

二、实验试图回答什么
第一，直接学习相对决策是否比预测执行结果更准确；第二，少量真实执行对是否足以训练出跨任务可用的选择器；第三，理论上被批评的 world model 失败模式是否在真实 ML 任务上出现；第四，WRM 能否作为搜索中的 critic，减少需要真实执行的候选数量。

三、证据缺口
当前只有摘要和图注，无法确认：26 个任务的具体名称与领域分布；12,438 个程序对是任务内留出还是任务级留出；5k 训练对与评估对是否来自同一任务分布；是否做了去重与泄漏控制；79.4% 的置信区间与统计显著性；是否报告了端到端搜索的最终分数、执行次数、wall-clock 和成本节省；是否与同规模 LLM world model、prompting 式 judge、AIDE 等做了公平对比；是否有数据规模、模型规模、损失函数的消融。图 1(b) 的“约 60%”也没有给出精确评测集与计算方式，不能直接当作严格 baseline。

四、实验设计上的关键问题
如果 79.4% 只是成对准确率，它不等于搜索最终能提升多少。搜索是迭代过程，20.6% 的错误选择可能改变后续候选分布，造成误差复合。另一个关键问题是推理成本：9B 模型每次比较都要前向计算，如果候选对很多，成本可能抵消节省的执行时间。论文需要给出“每美元/每小时获得的最终分数”这类预算感知指标，才能支撑其实际价值。

Q5: 发现了什么实验现象？

一、最主要的实验现象
在 12,438 个留出程序对上，ForeCritic 选择更优程序的准确率为 79.4%；图 1(b) 标注 LLM world model 约 60% 正确。两者相差约 19 个百分点（以 60% 粗略计）。这个差距与论文的核心假设一致：直接学习相对决策，比先预测绝对执行结果再排序更容易。但要注意，这不是严格的同条件消融；模型规模、训练数据、提示方式、任务分布都可能影响结果，不能仅凭这两个数字断定差距全部来自目标函数。

二、图 1 的示意说明了什么
图 1(b) 给出一个具体失败案例：world model 预测两个候选为 0.83 与 0.70，但真实分数是 0.64，预测排序与真实排序不一致，错误预测会误导搜索。图 1(c) 则给出 WRM 的 P(win)=0.86 示例，表示模型对“哪个候选会赢”给出较高置信度。这些是示意图，不是总体实验指标；不能把 0.86 当作平均准确率。图 1(a) 中的 0.64、0.71、0.80 等数字是候选程序的真实执行分数示例，也不应解释为方法整体性能。

三、理论揭示的失败模式
论文的第二个理论结果比“world model 偶尔预测错”更强：预测结果引入的误差可以让 likelihood-trained world model 在每个实例上都偏好更差程序。这意味着，优化执行结果的似然并不保证优化候选排序；一个在分数预测上看起来校准的模型，仍可能在 pairwise 决策上系统性失败。这个现象与“预测目标与决策目标错配”的解释一致。

四、指标之间的张力
79.4% 的成对准确率意味着约五分之一的选择会出错。在单轮 reranking 中，这或许可接受；但在多轮搜索中，错误选择会改变候选生成的条件，可能造成误差累积。另一个张力是成本：WRM 避免了执行，但引入 9B 模型的推理开销；如果推理延迟接近甚至超过短程序的执行时间，节省就不明显。当前证据没有给出预算-性能曲线，无法判断在什么任务上 WRM 真正划算。

五、消融、scaling 与负结果
当前证据没有提供数据规模消融（例如 1k/5k/更多程序对）、模型规模消融（9B 与其他规模）、损失函数消融（cross-entropy vs 回归/似然）、候选数量消融，也没有报告按任务类型分解的成功/失败案例。无法判断 79.4% 是普遍水平还是被某些简单任务拉高。也没有看到对“WRM 何时不如真实执行”的负结果分析，这是实际部署前需要补上的。

Q6: 有什么可以进一步探索的点？

1. 端到端搜索评估：报告最终最优分数、达到目标分数所需真实执行次数、wall-clock 和总成本，而不只是成对准确率；绘制预算-性能曲线，与真实执行搜索、LLM world model、prompting judge 在同等预算下比较。
2. 成本感知的选择策略：当 WRM 对某对候选的置信度低、或候选分数差距很小时，回退到真实执行；学习一个“何时执行、何时相信 WRM”的策略，把 WRM 的不确定性与执行成本联合优化。
3. 主动数据收集：用 WRM 的不确定性选择最有信息量的程序对进行真实执行，减少 5k 对标注成本；研究 hard negative 挖掘、分数边际采样和任务平衡采样。
4. 从 pairwise 到 listwise/多候选排序：真实搜索每轮有多个候选，pairwise 比较可能不一致；可研究 listwise loss、Plackett-Luce、 tournament/排序聚合，并约束传递性。
5. 理论扩展：给出有限样本泛化界，分析 ties、噪声分数、非传递偏好、部分反馈和模型误设下的选择误差；明确“最佳直接选择器”所在的函数类与假设。
6. 与 world model 结合：把预测执行结果作为辅助特征，但用 decision-focused loss 训练；研究在什么条件下“预测+决策”的归纳偏置能帮助有限数据学习，而不只是表达力上的比较。
7. 跨任务与 OOD 泛化：测试未见任务、未见语言、不同代码库和不同评分标准下的表现；检查训练/评估任务重叠与数据污染，报告任务级留出结果。
8. 可解释性与 reward hacking：分析 WRM 依赖哪些程序特征（长度、API 调用、输出格式、测试通过率线索），防止模型利用伪相关或评分器漏洞；研究对抗性候选与分布偏移下的稳健性。
9. 推理效率：蒸馏更小的 WRM、量化、缓存、批量比较；测量 9B 模型延迟，给出“执行节省/推理开销”的盈亏平衡点。
10. 科学应用：把 WRM 用于 AI-for-Science 中昂贵的实验代码、数据分析 pipeline 或模拟器配置筛选；需要验证科学任务上的执行分数是否稳定、候选对是否足够多、以及错误选择对科学结论的影响。
11. 人机协作：在 WRM 不确定或高风险场景引入人类判断；研究人类反馈与执行反馈的混合奖励建模。
12. 搜索策略联合设计：WRM 不只是 reranker，也可用于候选生成前的预算分配、早停、分支剪枝；需要研究选择器与搜索策略的联合优化，而不是把 WRM 固定为后处理模块。

Q7: 总结一下论文的主要内容

一、背景与问题
论文从搜索式机器学习（ML）agent 的实际工作流出发：agent 写候选程序、执行、获得真实分数、保留最优，再迭代。真实执行是最可靠的监督，但单次运行可能耗时数小时，而且大多数候选最终会被丢弃。为了节省执行，近期方法让 LLM 充当 world model，预测每个程序的执行表现，再按预测排序。论文指出，这条路线有一个根本性的目标错配：搜索需要的是“选哪个”，world model 优化的却是“预测结果”；预测错误会把虚假信息注入搜索，且误差会随迭代传播。

二、核心主张
论文提出“Predict the Reward, Not the World”：agent 不需要预测执行结果，只需要预测执行会支持哪个选择。基于此，作者提出 World Reward Models（WRMs），从真实执行结果中学习直接比较候选程序，不预测任何中间执行结果。这个主张既是方法设计，也是评价范式的转变：从“预测执行有多准”转向“选择做得有多对”。

三、方法与理论
方法上，作者实现 ForeCritic，把一个 9B typed decision model 适配到 5k 个已执行程序对。训练信号来自真实执行中的 winner：模型被要求提高 winner 相对 loser 的决策概率。论文给出三项理论结果：第一，在相同输入下，先预测执行再选择的选择器不能超过最佳直接选择器；第二，预测结果引入的误差可以使 likelihood-trained world model 在每个实例上都偏好更差程序；第三，在 executed winners 上使用 cross-entropy 可驱动 WRM 趋向最优。三项结果共同支撑“直接学决策”优于“先学世界再决策”的论证。

四、实验与发现
实验在 26 个 ML 任务构造的 12,438 个留出程序对上进行。ForeCritic 选择更优程序的准确率为 79.4%。图 1(b) 标注 LLM world model 约 60% 正确，并用一个预测 0.83/0.70、真实 0.64 的例子说明错误预测如何误导搜索；图 1(c) 用 P(win)=0.86 示意 WRM 的直接决策。论文的观察可以概括为：相对决策比绝对结果预测更容易；world model 的错误不是随机噪声，而可能是目标错配导致的系统性排序错误；直接选择器在少量真实执行对上可以学到可用的判断。

五、贡献与意义
论文的贡献有三层。概念层：把 ML agent 的候选选择问题从 outcome prediction 重构为 relative decision，指出“预测世界”不是搜索的必要中间步骤。理论层：给出预测再选择的上限、likelihood 训练的系统性失败模式、以及直接选择目标的最优性驱动。实证层：用 9B ForeCritic 和 5k 执行对，在 26 个任务、12,438 个留出对上报告 79.4% 的成对准确率。对 agent 研究而言，这意味着可以把宝贵的真实执行预算集中到少数候选，把 critic 从“预测分数”改成“做选择”。

六、边界与待核验
当前证据主要来自摘要和图注，仍有关键缺口：79.4% 是成对准确率，不等于端到端搜索的最终分数提升；没有看到执行次数、wall-clock、成本节省和预算-性能曲线；没有看到任务级留出、置信区间、统计显著性、数据泄漏控制；也没有看到数据规模、模型规模、损失函数的消融。理论结论依赖“相同输入”“最佳直接选择器”等假设，有限数据下预测式模型仍可能因归纳偏置而占优。9B 模型的推理成本是否抵消执行节省，也需要原文实验回答。因此，论文的论证主线是清晰的，但实际部署价值仍取决于端到端搜索实验和成本分析。
