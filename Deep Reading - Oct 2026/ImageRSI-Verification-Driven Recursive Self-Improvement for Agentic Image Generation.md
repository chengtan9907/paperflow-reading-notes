# ImageRSI: Verification-Driven Recursive Self-Improvement for Agentic Image Generation

> ★★★★☆ 推荐阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：text-to-image generation · agentic image generation · verification and repair · experience library

## 一句话总结

ImageRSI 在冻结的图像生成器之上，把“任务内五维验证—修复”“跨任务经验库（候选经验须过配对 A/B 验证才能入库）”“离线裁判自进化（SFT + GRPO，复用前先评估）”三者耦合成验证驱动的递归自我改进框架，并配套 961 条逐条带检查清单的 ImageReq-Bench，在 MindBench 与 ImageReq-Bench 上分别取得 52.6% 与 65.66% 的 Checklist Strict Accuracy（CSA）。

## 摘要

> 说明：原 PDF 摘要为双栏排版，抽取文本存在严重的跨栏串行与断行错误（例如“image satisfies them”“Beyond fixing the current image, verification and2026”），以下为在保留可辨识语义前提下的去噪复述，个别衔接处属于合理推断。
> 一、问题陈述
> 复杂的 text-to-image 请求仍然难以被可靠满足。验证并修复一张图可以修好单个输出，但一次成功修复并不必然迁移到其他请求。
> 二、核心主张
> 论文提出 ImageRSI：一个以 frozen image generator 为底座、包含三个组件的框架——(1) 每个任务内部的三维/五维验证与修复；(2) 跨任务共享的经验库（experience library）；(3) 裁判（judge，即给图像打分的验证模型）的离线更新。候选经验只有在通过配对 A/B 验证后才能进入经验库；裁判则在累积的图像—判断记录上用监督微调与 GRPO 更新，并在被复用于打分之前先接受评估。
> 三、基准
> 论文同时提出 ImageReq-Bench：围绕真实世界图像生成请求中的困难案例构建的 961 条请求，每条请求配一份评估检查清单（evaluation checklist），使评测可以逐条判定约束是否被满足。
> 四、结果
> 在 MindBench 上以 Nano Banana Pro 作为生成器时，ImageRSI 的 Checklist Strict Accuracy（CSA）为 52.6%；在 ImageReq-Bench 上为 65.66%。摘要片段还显示其相较 emoGen R2（47.56%）与 SCOPE（46.87%）分别高出 18.10 与 18.79 个百分点（该两个差值对应 ImageReq-Bench 的 65.66%，算术上自洽），并提到相对以 Qwen-Image-2.0 为生成器的对照设置提升 25.8 个百分点（该句在抽取文本中被截断，具体比较对象需回原文核对，属证据不足）。

Q1: 这篇论文试图解决什么问题？

一、任务层面的问题
1. 复杂 text-to-image 请求往往同时叠加多重约束：事实性世界知识、精确文字渲染（品牌名、标注文字）、物体计数、属性绑定、空间关系。论文 Introduction 把这几类明确列为当前强模型（正文提到 GPT-Image、Wan2.7-Image）仍会失败的方面。这意味着失败并非“画质不够”，而是“约束满足不全”。
2. 请求中的约束常常是隐式的。论文给出的代表性例子是“日食标注示意图”：用户只说画一张带标注的日食图，但隐含要求月球位于太阳与地球之间、三者共线、每个天体都有清晰可读的标签。可靠生成因此要求先推断出意图约束，再逐条验证是否被满足——这把问题从“生成质量”推向“约束推断 + 约束核验”。

二、方法层面的问题：为什么“修好一张图”不等于“学会一件事”
3. 现有 agentic 系统大多把验证与迭代修复用于单个请求：生成 → 检查 → 改 prompt → 再生成。单次修复成功可能只是随机采样碰巧变好，而不是策略真的可靠，因而不足以支撑“这个经验值得复用”的结论。
4. 论文点出三类会污染经验学习的噪声：(i) 随机生成本身可能偶然产生改进；(ii) 冗余轨迹（同一失败模式被多条轨迹重复记录）会高估证据强度；(iii) 裁判自身的判断错误会强化错误诊断，使错误经验自我确认。
5. 由此推出设计需求：候选经验必须经过准入验证（而非直接写入）、必须携带显式的适用条件、必须有修订/合并/退役的判据。论文正是把“经验的生命周期管理”当作核心缺口。

三、评测层面的问题
6. 固定 prompt 的 benchmark 只能衡量最终输出质量，无法回答“agent 是否随着跨任务经验积累而变强”。要验证递归自我改进，需要能够把“任务内修复收益”与“跨任务迁移收益”区分开的评测协议，以及细粒度、可逐条核对的判据（checklist）。这是 ImageReq-Bench 出现动机的直接来源（合理推断，摘要与引言片段均指向“fixed-prompt benchmarks 的局限”）。

四、设定上的隐含约束
7. 论文把生成器冻结（frozen image generator），改进只能发生在条件空间：请求解析、经验检索、外部知识注入、prompt 修改与裁判能力。这一设定把问题从“再训练生成模型”转为“在推理侧做信用分配与经验管理”，代价是性能上限受底座生成器能力约束（合理推断）。

五、可质疑之处
8. 把“经验”表示为可检索的文本规则加效果记录，隐含假设“缺陷—修复”的因果关系能被自然语言规则稳定表达，并在新任务上复现。在强随机性、长尾组合约束、跨风格跨生成器的条件下，这一假设是否成立，需要迁移实验与负迁移分析来支撑；仅凭总体 CSA 提升不足以证明（推测，需回原文核对是否存在负迁移或经验冲突的定量分析）。

Q2: 有哪些相关研究？

说明：PDF 抽取文本中 Related Work 段落未完整保留，以下按 Introduction 引用的文献簇与论文自身定位重建，具体归属需回原文核对。

一、Agentic 图像生成与“验证—修复”回路
1. 直接前驱是一类把生成器包在智能体循环里的系统：解析请求、生成、用视觉语言模型检查、再修改 prompt 重生成。片段中出现的 Shen et al., 2026、Chen et al., 2025、Ouyang et al., 2026、He et al., 2026a、Feng et al., 2026a 被论文归为“只在单个请求上做验证与迭代修复”的一类，其共同缺陷是修复收益不外溢到后续任务。
2. 与之相对，ImageRSI 的差异点不在“是否修复”，而在“修复之后留下什么”：把修复过程转成可验证、可检索、可退役的经验资产。

二、自我改进与经验复用
3. 论文引用的 Ye et al., 2025b、Yang et al., 2024、Zhu et al., 2025 涉及从轨迹中学习、把成功轨迹沉淀为未来任务的候选策略。论文对这些工作的批评是：单次成功不构成可靠性证据，冗余轨迹会夸大证据，因此需要配对 A/B 准入。
4. 这与 Reflexion 式“语言化反思记忆”、Voyager 式“技能库”属同一思想谱系，但 ImageRSI 把重点放在经验的准入控制与生命周期（修订/合并/退役），而不是记忆的写入本身（此处为领域定位性推断，论文未必显式引用这些名字）。

三、裁判模型与生成式反馈
5. LLM/VLM-as-a-judge、reward model、以及“带证据的理由生成”是该方法的基础设施。片段显示裁判输出 y 包含每个维度的分数与基于证据的理由，训练目标来自模型生成的标注，且“被 J(k) 接受”不被当作真值——说明论文对裁判标签的可信度有明确区分。
6. 裁判后训练涉及 SFT 与 GRPO（Deng et al., 2026 等后训练方法被引用），属于把 RLVR/可验证奖励范式搬到“图像评判”任务上的做法。

四、Benchmark 谱系
7. 固定 prompt 的图像生成 benchmark（Niu et al., 2025；He et al., 2026b）测最终质量；WISE 被提到“提供世界知识的采样覆盖”，属于知识密集型生成评测；MindBench 作为外部基准被用于主结果。
8. ImageReq-Bench 的定位差异：面向真实请求中的困难案例、以 checklist 为判据、可逐条严格判定（CSA），从而能测“跨任务是否变强”而非只测“这一批 prompt 画得好不好”。

五、相邻技术线
9. 精确文字渲染、计数、属性绑定、空间关系这几类子问题在 T2I 文献中各有专门 benchmark 与解法（如布局控制、区域约束、外部知识检索增强）。ImageRSI 并不提出新的生成骨干，而是把这些子能力组织进一个验证驱动的外层系统。

Q3: 论文如何解决这个问题？

一、总体架构
1. 底座是 frozen image generator（主实验使用 Nano Banana Pro；另有以 Qwen-Image-2.0 为生成器的对照设置）。生成器权重不动，所有改进来自“条件”的改变：请求解析、经验检索、外部知识注入、prompt 修改。
2. 三个组件构成闭环：(a) 任务内的验证与修复；(b) 跨任务经验库；(c) 裁判的离线自进化。三者分别对应“把这一张修好”“把这次学到的东西存下来”“让打分的人越来越准”。

二、任务内循环：解析—检索—生成—五维验证—定点修复
3. 解析：把用户请求拆成可核验的约束集合，包括显式约束与需要推断的隐式约束（引言中的日食示意图即隐式空间与知识约束的例子）。
4. 检索：从经验库取相关经验；在需要时额外检索外部知识（片段中出现“retrieves relevant experience and, when needed, external knowledge”），用于事实性、世界知识类约束。
5. 生成：按当前条件生成图像。
6. 验证：按五个维度打分——Alignment、Faithfulness、Quality、Aesthetic、Physics。每个维度不仅给分，还给基于证据的理由（片段：target y contains a score and an evidence-based reason for each dimension），使缺陷可定位。
7. 修复：由缺陷反馈导向 targeted repair，即针对被定位的缺陷改 prompt/条件，而不是笼统地“再画一次更好看的”。片段中“How it works: Generate once, Check & fix…”提示流程是先一次性生成再进入检查—修复回路。

三、经验库：准入、条件、生命周期
8. 候选经验不是直接写入，而是先做配对 A/B 验证（paired validation / paired A/B trials）：在同一请求或受控请求对上比较“用该经验”与“不用该经验”的结果，用配对比较抵消随机采样的运气成分。只有通过验证的候选才被 admit 进库。
9. 每条经验记录包含：规则本身、观察到的效果与副作用（observed effects and side effects）、支撑轨迹（supporting trajectories）、配对验证试验、准入状态（admission state）。片段还提到记录会“constrain when these versions are later selected”，即经验带有适用条件，在后续被选中时用于约束其作用范围。
10. 生命周期管理：记录的结果用于经验的 revision（修订）、consolidation（合并）或 retirement（退役），避免过时或冲突的经验长期污染检索。

四、裁判自进化：SFT + GRPO，复用前先评估
11. 离线阶段，把累积的“图像—判断”记录整理成训练数据：输入是图像（及请求），目标是各维度的分数与证据理由。
12. 训练分两步：先监督微调（SFT）建立格式与基本判别，再用 GRPO 做强化优化。片段明确出现“supervised fine-tuning and GRPO on accumulated image–judgment records”。
13. 门控：更新后的裁判在被重新用于打分之前必须先评估（“evaluated before reuse”），防止裁判退化直接把错误诊断注入经验库——这是对“judge errors can reinforce incorrect diagnoses”这一失效模式的直接对冲。

五、设计逻辑小结
14. 三个组件共享同一个失效模型：随机性 → 需要配对验证；冗余轨迹 → 需要证据强度控制与合并；裁判错误 → 需要裁判自进化 + 复用前评估。方法不是堆模块，而是逐条对应噪声源。
15. 代价：每个任务多次生成 + 多次裁判调用 + 配对试验，推理成本显著高于单次生成；论文是否给出成本/延迟数据，抽取片段中未见（证据不足）。

Q5: 发现了什么实验现象？

一、主结果的量级与结构
1. ImageReq-Bench 上 CSA = 65.66%，MindBench 上 CSA = 52.6%（Nano Banana Pro 为生成器）。两个基准的绝对水平差异明显，提示 MindBench 的检查清单更严格或任务更难，跨基准不能直接比大小（合理推断）。
2. 相对 agentic 基线：65.66% 对 emoGen R2 的 47.56%（+18.10 pp）、对 SCOPE 的 46.87%（+18.79 pp）。两个基线的水平非常接近（相差 0.69 pp），而 ImageRSI 一次性拉开近 19 pp，说明增益不是“比最强基线好一点点”，而是换了一个能力档位——如果该数字在多次运行下稳定，这是本论文最强的实证点。
3. 相对底座生成器：片段出现 Qwen-Image-2.0（22.4%）与“25.8 percentage points”的提升表述。若按 22.4 + 25.8 推算约为 48.2%，则该设置下的绝对水平低于 Nano Banana Pro 设置（52.6%/65.66%），符合“底座越强、外层系统收益越容易被吸收”的直觉，但该推算基于被截断的句子，属推测，必须回原文核对比较口径（是同一基准、同一指标、同一生成器吗）。

二、严格指标的张力
4. CSA 是 strict accuracy：清单全对才算通过。52.6% 意味着在 MindBench 上仍有近一半请求至少有一条约束未被满足。这与“大幅超越基线”并不矛盾——它揭示的是：外层 agent 系统能显著拉开与基线的差距，但距离可靠满足复杂多约束请求仍有很大空间。这个“高分增益 + 低绝对水平”的组合是解读该论文时最需要保留的张力。
5. 分维度五维打分（Alignment、Faithfulness、Quality、Aesthetic、Physics）与单一 CSA 之间存在潜在张力：总分提升可能由某一维（如 Quality/Aesthetic）驱动，而真正难的 Faithfulness（事实/文字/计数）改善有限。论文是否做了维度级归因，抽取片段中未见（证据不足，需核对 §4.2/§4.3）。

三、裁判行为
6. 案例 (a)：裁判能正确定位“缺失的品牌名”，说明其证据理由具备空间/语义定位能力，而不是只给一个标量分。这是“缺陷反馈指导定点修复”能成立的前提。

Q6: 有什么可以进一步探索的点？

一、经验表示与信用分配
1. 当前经验以“规则 + 效果/副作用 + 支撑轨迹 + 准入状态”的文本记录形式存在。可探索更强的结构化表示：把经验写成可执行的约束补丁（布局约束、计数断言、文字渲染模板），使其可被程序化验证而非仅靠裁判打分。
2. 信用分配问题：一次修复成功可能由多个 prompt 修改共同导致，如何把功劳/责任精确分配到具体编辑？可引入受控消融式编辑（单变量修改）或 Shapley 式归因。
3. 经验的负迁移检测：建立“某经验在新任务上导致性能下降”的监测与回滚机制，把 retirement 从人工规则变成在线统计过程。

二、裁判的可靠性与自进化
4. 裁判自进化的闭环风险（用裁判筛经验、再用经验训裁判）需要外部锚点：人类标注子集、可验证检查器（如 OCR 验证文字、检测器验证计数与空间关系）、或多裁判投票与校准。可探索“可验证子任务用程序判、主观子任务用模型判”的混合验证。
5. 校准（calibration）与选择性预测：让裁判在不确定时弃权并触发更贵的验证路径，而不是给一个高置信错误分。
6. GRPO 训练裁判的奖励设计：若奖励来自与人类的一致性，需研究 reward hacking（裁判学会迎合标注风格而非真实质量）。

Q7: 总结一下论文的主要内容

一、论文要解决的问题
论文从一类具体失败出发：复杂 text-to-image 请求经常在事实知识、精确文字渲染、物体计数、属性绑定、空间关系上出错，而且请求中的约束常常是隐式的（如“带标注的日食示意图”隐含月球位于日地与地球之间、三者共线、标签清晰）。现有 agentic 系统用“生成—检查—改 prompt—重生成”的回路可以修好单张图，但论文指出三个使“修复”无法转化为“学习”的噪声源：随机生成可能碰巧变好；冗余轨迹会高估证据；裁判错误会强化错误诊断。同时，固定 prompt 的 benchmark 只能测最终输出质量，无法回答 agent 是否随跨任务经验积累而变强。

二、方法主线
ImageRSI 的做法是把生成器冻结，把改进全部放在外层条件空间，并组织成三个互相咬合的组件。
1. 任务内验证—修复：解析请求得到约束集，检索相关经验与（必要时）外部知识，生成图像，然后按 Alignment、Faithfulness、Quality、Aesthetic、Physics 五个维度打分；每个维度不只给分，还给基于证据的理由，使缺陷可定位；缺陷反馈再驱动 targeted repair，即针对被定位的问题修改条件，而不是笼统重画。
2. 跨任务经验库：修复过程留下的轨迹被抽象为候选经验；候选经验不直接入库，而要先经过配对 A/B 验证（paired validation trials），以抵消随机采样的运气；通过后才被准入。每条经验记录规则本身、观察到的效果与副作用、支撑轨迹、配对试验与准入状态，并携带适用条件以约束其后续被选中时的作用范围；积累的结果用于经验的修订、合并或退役。
3. 裁判自进化：把累积的“图像—判断”记录（每个维度含分数与证据理由）用于裁判的监督微调，再用 GRPO 强化；更新后的裁判在重新投入打分之前必须先通过评估，形成门控，防止退化裁判污染经验库。
这三者不是并列模块，而是对同一组失效模式的逐条回应：随机性→配对验证；冗余轨迹→证据强度控制与合并退役；裁判错误→自进化 + 复用前评估；单次修复不可迁移→经验库 + 适用条件。

三、实验主线
论文构建了 ImageReq-Bench：961 条来自真实世界图像生成请求的困难案例，每条配一份 evaluation checklist，主指标为 Checklist Strict Accuracy（CSA，逐条全满足才算通过）。主实验以 Nano Banana Pro 为冻结生成器，在 MindBench 上取得 CSA 52.6%，在 ImageReq-Bench 上取得 65.66%。在 ImageReq-Bench 上相对 agentic 基线 emoGen R2（47.56%）与 SCOPE（46.87%）分别提升 18.10 与 18.79 个百分点，这两个差值与 65.66% 精确自洽。论文还报告了以 Qwen-Image-2.0 为生成器的设置（片段给出 22.4% 与“25.8 percentage points”的截断表述，具体口径需回原文核对），并给出按任务类别的结果、§4.4 的端到端性能分析、裁判后训练效果分析，以及展示裁判定位“缺失品牌名”与主体一致性判断的案例研究。

四、论证结构与隐含前提
论文的论证是“机制对应失效模式”的工程论证，而不是理论证明。其成立依赖若干隐含前提：(a) 缺陷—修复的因果关系能被自然语言经验稳定表达并跨任务复现；(b) 配对 A/B 能有效分离信号与随机性；(c) 裁判的进步方向与真实质量方向一致，或至少不系统性偏离。第三点尤其关键，因为裁判同时充当“经验准入的裁判者”和“被经验训练的学习者”，存在闭环放大误差的风险；论文用“复用前评估”缓解，但抽取文本中未见外部人类锚点的系统对照。

五、结果如何解读
“比最强基线高近 19 pp”与“严格准确率只有 52.6%/65.66%”必须同时读：前者说明外层系统确实能带来档位性提升，后者说明复杂多约束请求的可靠满足仍远未解决。此外，主结果绑定 Nano Banana Pro，跨生成器证据薄弱，成本与延迟数据在抽取文本中缺失，因此不宜把结论外推为“通用地解决了复杂指令遵循”。
