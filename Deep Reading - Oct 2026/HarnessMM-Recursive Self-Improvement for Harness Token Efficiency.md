# HarnessMM: Recursive Self-Improvement for Harness Token Efficiency

> ★★★★☆ 推荐阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：agent harness · token efficiency · decision reuse · recursive self-improvement

## 一句话总结

HarnessMM 通过「受保护决策复用」与「递归自我改进（RSI）」把 agent harness 中工具反馈后重复触发的模型—工具推理回调替换为已解决的持久化决策，并以「替换悖论」核算净节省；摘要报告在 MBPP 消融上相较单次使用动作图和保留回调分别降低 26.91% 与 19.52% 成本。

> 1. 背景：可执行技能、与观察无关的计划以及编译后的工具依赖，可以复用或调度先前的计算（摘要引用 [19,40,43]）；ActionEngine 进一步针对可复用应用记忆执行任务程序，并带有反应式修复（[52]）。
> 2. 问题：agent harness 在工具反馈之后会反复调用模型推理，即使上一次调用已经固定了下一步动作。
> 3. 方法总览：论文提出 HarnessMM（Harness Minus Minus），通过受保护决策复用（Guarded Decision Reuse）与递归自我改进（RSI）提升 harness token 效率。
> 4. RSI：从训练反馈中迭代优化配套 harness 配置，并用验证集选择部署配置。
> 5. 运行时控制器：在模型—工具边界复用已解决决策，以替换后续的模型—工具推理回调，同时 actor 权重保持固定。
> 6. 表示：可执行决策图（Executable Decision Graphs）存储精确动作、字面参数、因果依赖和公开守卫。
> 7. 执行：受保护决策复用从观察到的回执中激活这些持久化决策；经认证的回调替换（Certified Callback Substitution）通过原生接口执行它们，并记录对已注册慢回调的移除。

Q1: 这篇论文试图解决什么问题？

需要先说明证据质量：当前可见证据仅为摘要片段，且 heuristic_draft 中大量文本是摘要断行造成的噪声，不能作为事实依据；以下分析基于可辨识的摘要内容与 agent 系统领域常识，推断处会标注「合理推断」或「推测」。

1. 论文要解决的核心问题
Agent harness 是连接模型推理与工具执行的脚手架。典型循环是：模型推理 → 选择工具/参数 → 执行工具 → 观察反馈 → 再次推理。问题在于，工具反馈之后 harness 往往会再次调用推理模型，即使前一次调用已经确定了「下一步该做什么」。这类重复回调不会改变动作语义，却持续消耗 token、延迟和调用成本。论文把这一现象作为 harness token 效率的核心浪费来源。

2. 为什么现有的「复用」思路不够
摘要提到三类已有复用：可执行技能、与观察无关的计划、编译后的工具依赖（[19,40,43]）；ActionEngine 进一步把任务程序执行到可复用应用记忆上，并支持反应式修复（[52]）。这些工作说明程序化执行有价值，但它们主要处理「计划/技能/依赖」层面的复用。HarnessMM 把问题收窄到一个更具体的契约：某个 episode-specific 动作仍然是字面动作；后续反馈可能改变它的适用性；执行记录能够识别到底是哪一个推理边界被绕过了。换句话说，论文不是用一个通用模板替代具体动作，而是要在动作级别、带守卫地复用「已解决的决策」。

3. 与提示/agent 程序优化的区别
Feedback、APE、STOP、ADAS、Self-Refine、Reflexion 等工作（摘要引用 [13,24,36,49,53]）优化的是指令或 agent 程序。摘要明确指出：这类优化「构造了一个 harness」，但部署时哪些回调会重复出现，仍由部署环境决定。因此，优化提示并不自动消除运行时冗余回调。HarnessMM 的定位是运行时决策复用，和提示/程序优化正交。

4. 为什么「加一个选择器」也不够
摘要提到 Jev 的类型化概率接口（[1]）可以支持紧凑的候选选择，但「增加选择器并不会自动移除原始回调」。这正是论文提出替换悖论的动机：系统可能增加了选择开销，却仍保留慢回调，导致总成本没有下降。论文要求把「被消除的推理」与「新增的作者化、选择、恢复开销」放在同一本账上核算。

5. 关键难点
（1）适用性判定：一个持久化决策在什么条件下仍然成立？后续工具回执可能使原决策失效，因此需要公开守卫。
（2）回执证据：守卫必须能从观察到的回执中验证，否则会误触发。摘要把「不受支持的证据」列为回退条件。
（3）安全替换：如何通过原生接口执行决策，并记录「移除了哪个已注册慢回调」，使替换可审计。
（4）净收益核算：替换本身有成本，包括构建决策图、选择候选、处理失败恢复；替换悖论要求这些成本不能超过被消除的推理。
（5）RSI 的泛化：从训练反馈迭代优化 harness 配置，并用验证集选择部署配置；如果训练/验证分布与部署分布不一致，守卫和选择策略可能失效。
（6）回退策略：新语义决策、无证据、选择器弃权都要回退到原始 actor；回退太频繁会侵蚀收益，回退太少会引入错误。

6. 隐含假设
（1）大量重复推理确实可以被「已解决决策」覆盖；（2）守卫和回执足以判定动作适用性；（3）慢回调可以被注册、识别并替换；（4）训练/验证反馈能够代表部署分布；（5）成本可以按 token 或调用次数度量；（6）actor 权重固定，因此方法不依赖模型微调；（7）替换后的动作执行与原回调语义等价。这些假设是否成立，摘要没有提供充分验证。

什么算「已解决决策」？决策图如何构建？守卫是手工定义、从数据学习还是由模型生成？RSI 具体搜索什么配置？验证集如何选择？MBPP 消融的「成本」是 token、美元还是延迟？是否报告了任务成功率？回退率有多高？替换悖论是否有形式化公式或只停留在概念层面？这些缺口在摘要中无法回答，读者应把全文中的方法节和实验节作为核查重点。

Q3: 论文如何解决这个问题？

以下描述基于摘要片段重构，具体算法细节需以全文为准；推断处已标注。

1. 总体架构
HarnessMM 可以理解为一个「训练时优化 harness 配置、部署时复用已解决决策」的两层系统。训练阶段用 RSI 迭代优化配套 harness 配置，验证集负责选择部署配置；部署阶段由一个控制器在模型—工具边界判断是否可以用持久化决策替换后续推理回调。Actor 模型权重保持固定，因此方法不依赖微调，而是改变 harness 的执行路径。

2. 递归自我改进（RSI）
RSI 从训练反馈中迭代优化 harness 配置。摘要没有说明优化算法是进化搜索、提示搜索还是其他形式；合理推断是类似 APE/ADAS 的迭代改进循环，但优化对象从指令/程序扩展到 harness 配置。验证阶段用于选择配置，说明论文关注泛化而不是只拟合训练反馈。需要全文确认：配置空间包含哪些维度（决策图、守卫、选择器策略、替换策略等），迭代次数和停止条件是什么。

3. 运行时控制器
控制器负责在模型—工具边界复用已解决决策，替换后续的模型—工具推理回调。关键点是 actor 权重固定：控制器不改变模型，只改变「何时调用模型、何时直接执行」。这使方法可以与不同基础模型组合，但也意味着效果上限受基础模型能力约束。

4. 可执行决策图（EDG）
EDG 存储精确动作、字面参数、因果依赖和公开守卫。精确动作和字面参数意味着复用不是模糊语义匹配，而是可执行的具体调用；因果依赖描述决策之间的先后关系；公开守卫是可检查的适用性条件。公开一词可能意味着守卫对系统或审计者可见，而不是隐式模型判断。摘要没有说明图如何构建（从轨迹抽取、人工编写还是 RSI 搜索），这是需要全文确认的关键细节。

5. 受保护决策复用（GDR）
GDR 从观察到的回执中激活持久化决策。可以理解为：当工具反馈满足某个守卫时，系统认为之前已解决的决策仍然适用，于是不再调用推理模型，而是直接进入执行。回执在这里扮演证据角色；没有回执或回执不受支持时，不应激活。

6. 经认证的回调替换（CCS）
CCS 通过原生接口执行存储的动作，并记录对已注册慢回调的移除。认证可能包含两层含义：执行走原生接口（保证动作真实发生），以及记录移除了哪个慢回调（保证可审计、可核算）。这为替换悖论中的成本核算提供了依据：系统能说清楚「消除了多少推理」和「新增了多少开销」。

7. 回退与安全边界
摘要明确列出三类回退条件：新的语义决策、不受支持的证据、选择器弃权。也就是说，当系统遇到未见过的情况、无法验证守卫、或选择器不愿选择时，会重新调用原始 actor。这是防止错误替换的安全阀，但也意味着回退率会直接影响净收益。

8. 替换悖论作为设计约束
论文把核算错配称为替换悖论：计算被节省只在「被消除的推理」超过「新增的作者化、选择和恢复」时成立。这个视角要求系统设计者同时优化两侧：一方面提高决策复用率，另一方面降低构建决策图、选择候选和处理失败的成本。摘要没有给出形式化不等式，但这一思想可以作为评估任何 harness 复用方案的分析框架。

9. 证据边界
当前无法确认：EDG 的具体数据结构、守卫的学习方式、RSI 的搜索空间、选择器的实现、回执匹配算法、成本度量单位、以及替换后的语义等价性验证。这些是全文方法节需要重点核查的内容。

Q7: 总结一下论文的主要内容

一、研究问题与动机
论文关注 agent harness 中一类特定但普遍的低效：工具反馈之后，harness 会再次调用模型的推理能力，即使上一次调用已经确定了下一步动作。典型 agent 循环是「推理—选工具—执行—观察—再推理」，其中「再推理」并不总是必要的；如果先前的决策已经足够具体，并且工具回执没有改变其适用条件，那么再次推理就是重复计算。论文把这类重复回调视为 harness token 效率的主要浪费来源，并试图在 actor 权重固定的前提下，通过复用「已解决决策」来绕过冗余推理。

二、核心概念与技术路线
论文提出 HarnessMM，包含四个关键构件。第一是可执行决策图（EDG）：存储精确动作、字面参数、因果依赖和公开守卫，使决策可以被持久化、检查和复用。第二是受保护决策复用（GDR）：从观察到的工具回执中激活持久化决策；只有当回执满足守卫时，才认为决策仍然适用。第三是经认证的回调替换（CCS）：通过原生接口执行存储的动作，并记录对已注册慢回调的移除，使替换可审计、可核算。第四是递归自我改进（RSI）：从训练反馈中迭代优化配套 harness 配置，并用验证集选择部署配置。运行时由一个控制器在模型—工具边界决定是否复用决策；遇到新的语义决策、不受支持的证据或选择器弃权时，回退到原始 actor。

三、替换悖论
论文提出「替换悖论」作为核算框架：计算被节省，只有当被消除的推理成本超过新增的决策作者化、候选选择和失败恢复成本时才成立。这个视角解释了为什么「增加一个选择器」并不自动带来净收益——选择器可能只是增加了开销，而原始慢回调仍然存在。替换悖论把注意力从「复用率」转移到「净成本」，要求系统同时优化复用收益和复用开销。

四、实验证据
摘要报告 MBPP 消融结果：HarnessMM 比单次使用动作图成本低 26.91%，比保留回调成本低 19.52%。这两个数字表明，在该实验设置下，持久化决策复用与回调替换确实带来了成本下降。摘要还提到一个示例，把语义不确定性与执行不确定性分离：模型负责语义决策，回执和守卫负责执行适用性。这一设计原则可能是 GDR/CCS 有效的原因之一。

五、贡献与定位
论文的贡献可以概括为：（1）把 harness token 效率形式化为决策复用问题，并界定 episode-specific 动作、反馈改变适用性、执行记录识别绕过边界这一窄契约；（2）提出 GDR + CCS 的可审计替换机制；（3）提出 EDG 表示；（4）提出 RSI 优化 harness 配置；（5）提出替换悖论作为核算视角；（6）报告 MBPP 上的初步成本收益。与提示优化、程序化 agent、缓存/记忆系统相比，HarnessMM 的生态位是运行时回调层的决策复用，而不是指令优化或工具接口设计。
