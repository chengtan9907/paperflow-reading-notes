# ProteinGeoBench: Frontier Structural-Biology Agents Are Fluent at Lookup but Lost in Geometry

> ★★☆☆☆ 按需阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：protein structure · agent benchmark · scientific agents · evaluation reliability

## 一句话总结

论文提出并系统评估 ProteinGeoBench——131 个蛋白质结构任务，发现四个前沿智能体的聚合分数接近，却掩盖了“元数据查找较强、坐标数值计算较弱”的任务族差异；同时排名受运行预算、网络/数据库访问与 agent harness 影响，因而主张按任务族报告分数并附运行次数、harness 与访问条件。

## 摘要

> ProteinGeoBench 是 131 个蛋白质结构任务的基准。论文用四个前沿模型的 4,249 次 rollout，以及 26 个模型的 4,486 次补充试验，检验聚合分数是否掩盖任务族差异。四个前沿模型均分 0.707–0.816；其中三个在 0.031 内，彼此差异未分辨，第四个为 0.707 且与三者差距排除零。三个模型在元数据查找上优于数值计算，第四个略优于数值计算。数值任务为 28/131，却占四个模型全部失败的 12 个任务的一半。排名依赖预算：每任务一次运行时，23.9% 的 bootstrap 重采样把不同模型排在第一。15 任务切片上，移除网络比屏蔽八个结构数据库域降分更多，但两组对照在不同 pass 中评分，不能干净分解。替换各模型自带 CLI agent 使分数变化 −0.071 至 +0.086，不足以排除中等 harness 效应。26 个模型上，数值表现随非数值表现上升而非持平。不同实验使用不同任务子集，因而不能把模型、harness、访问条件和任务组成相互排序。论文主张按任务族报告分数，并附运行次数、harness 与访问条件。

Q1: 这篇论文试图解决什么问题？

（1）论文试图解决的核心问题不是“如何训练更好的蛋白质结构模型”，而是“蛋白质结构智能体的基准分数到底测到了什么”。一个结构生物学家可以先问某个结构如何被测定，再要求智能体从同一坐标文件计算距离或二面角；前者可从数据库记录检索，后者必须识别相关原子并执行计算。若基准只给一个聚合分，这两种能力会被混在一起，模型可能靠检索拿分却被误读为具备几何计算能力。

（2）第二层问题是任务族之间的能力剖面可能互相抵消。两个模型可以有相近总分，但一个强在元数据查找、另一个强在数值计算；此时总分既不能说明谁更“懂结构”，也不能说明模型在真实工作流中的短板。论文因此把 lookup 与 compute 的对比作为核心测量对象，而不是只报告总榜。

（3）第三层问题是 agent 评估条件本身会改变排名。前沿模型是随机系统，单次运行、重复次数、是否联网、能否访问结构数据库、使用哪个 CLI harness，都会影响分数。论文要问：在任务抽样和运行预算变化时，第一名是否稳定；网络访问与数据库域屏蔽各自贡献多少；替换 harness 是否足以改变结论。这些问题属于评估科学，而不是模型能力本身。

（4）现有生物医学 agent 基准的缺口在于任务输出形式各异：LAB-Bench 以多项选择测文献、数据库导航和序列操作；BixBench 要求多步数据分析与开放式回答；BioAgent Bench 在多个 harness 上做端到端评估；其他基准各有侧重。论文的 Table 8 按 agentic、结构文件、确定性评分、未发表结构、lookup vs compute、harness 变化、网络变化和重复运行等维度比较，指出少有基准同时覆盖这些维度。ProteinGeoBench 的定位是把蛋白质结构文件上的检索与计算拆分，并把访问条件和 harness 作为显式变量。

（5）该问题背后有一个明确前提：任务被视为从更大可能问题总体中的抽样，因此用任务 bootstrap 给区间，而不是把固定任务集当作唯一真值。这个前提合理，但也意味着结论依赖任务族标签的代表性；若任务族边界模糊或某些族样本过少，族间比较的外推会受限。论文对“不同实验使用不同任务子集”的反复提醒，正是在限制这种外推。

（6）需要区分“问题”与“结果”：三个模型 lookup 强于 numeric、Gemini 例外、Grok 数值最低但概念推理第二，这些都是实验发现，不是论文要解决的问题。把它们写成方法或背景会误导读者；本报告按证据把它们归入实验结果与现象部分。

Q2: 有哪些相关研究？

（1）生物科研 agent 基准：LAB-Bench 通过多项选择题评估实用研究能力，覆盖文献使用、数据库导航和序列操作；BixBench 要求智能体对生物数据集做多步分析并回答开放式问题，发布时其评估的最强前沿模型约为 17% 准确率；BioAgent Bench 在多个 agent harness 上评估端到端能力。论文还列出 BiomniBench、BioDesignBench、ProtStructQA 和 Harness-Bench 作为相邻工作。Table 8 用统一维度标注这些基准是否覆盖结构文件、确定性评分、未发表结构、lookup 与 compute 的对比、harness 变化、网络变化和重复运行；表中的空白不表示该能力不存在，只表示不是该论文的明确重点。

（2）与 Harness-Bench 的关系最直接：Harness-Bench 关注 harness 变化对评估的影响，ProteinGeoBench 也替换各模型自带的命令行 agent，并把分数变化作为测量对象。区别在于 ProteinGeoBench 的任务域是蛋白质结构，任务本身包含元数据检索与坐标几何计算，因而可以把“能力族差异”和“评估条件差异”放在同一个框架下讨论。

（3）与 ProtStructQA 等蛋白质结构问答基准相比，ProteinGeoBench 的差异不只是题目领域，而是强调结构文件上的可计算量、lookup 与 numeric 的任务族拆分，以及网络/数据库访问的条件操纵。不过，当前可检索片段没有给出 ProtStructQA 的完整任务形式，不能仅凭名称断言其只做问答；相关细节需回原文核对。

（4）数据与工具生态方面，论文使用实验结构、AlphaFold 预测结构以及嵌合 cadherin 构建体等来源；这些属于结构生物学数据资源，不是 benchmark 方法本身。论文的贡献在于评估设计，而不是提出新的结构预测模型。

（5）与通用 agent benchmark 的关系：论文把工具访问、harness、运行预算和任务组成视为分数的一部分，而不是外部噪声。这与“只报一个准确率”的排行榜文化形成对照，也为科研 agent 的可复现评估提供了任务族分层、配对 bootstrap 和单次运行排名稳定性等可复用工具。

（6）需要指出的差异点：ProteinGeoBench 并非完全确定性评分。Table 8 标注其确定性评分，但正文说明 LLM judge 占奖励权重 5.3%，另有 0.100 的完整性下限。因此它更接近“以规则评分为主、少量模型评分辅助”的混合评分，而不是零 judge 的纯确定性基准。

Q3: 论文如何解决这个问题？

（1）任务套件：论文构建 131 个蛋白质结构任务，覆盖元数据查找、数值计算、概念推理、序列验证等任务族；其中数值任务 28 个，元数据查找族在 Table 4 中有 36 个任务，概念推理至少有 16 个任务。任务族的作用不是装饰性分类，而是把“可从数据库记录检索的答案”和“必须从坐标计算出的答案”分开，从而暴露聚合分数掩盖的能力差异。

（2）受控切片：论文选取 15 个任务做访问与坐标来源实验，选择标准是该测量可以在实验坐标、去除元数据的副本和 AlphaFold 预测上定义。作者明确说选择先于 factorial 结果，但不是随机抽样；这使该切片的内部对照有意义，外推则受限。

（3）评分与奖励：任务奖励包含完整性下限 0.100，LLM judge 贡献 5.3% 权重；通过阈值约为 reward > 0.85，无准确率credit 的集合约为 reward < 0.15。这个设计让部分完成也能得分，但也引入地板效应：低分任务可能拿到 0.100 的完整性分而非零分，跨模型回归和任务难度比较需要因此校正。

（4）模型与运行规模：四个前沿模型共 4,249 次 rollout；其中 486 个模型-任务单元有八次重复，用于估计分数信度；另有 26 个模型的 4,486 次补充试验。论文用任务 bootstrap（5,000 次重采样）给 95% 区间，配对比较模型差异；区间未做多重比较校正，因此“显著”标签应谨慎解读。

（5）条件操纵：一是在 15 任务切片上移除网络访问；二是屏蔽八个结构数据库域，以区分“联网”与“访问结构数据库”两种条件；三是把模型替换为各自自带的命令行 agent harness；四是改变坐标来源（实验坐标、去元数据副本、AlphaFold 预测）。这些操纵不是完全因子设计，部分对照在不同评分 pass 中完成，因此不能把各因素的主效应相加或相减。

（6）统计与诊断：论文报告任务族均值、配对任务 bootstrap 区间、Spearman–Brown split-half 信度（0.962，基于 486 个有八次重复的模型-任务单元）、单次运行下的排名稳定性（23.9% 的 bootstrap 重采样第一名变化），以及 26 个模型上 numeric 对 non-numeric 的回归（斜率 +0.672，95% CI [+0.318,+0.982]）。回归作者自己也指出受奖励下限偏差影响，只能谨慎解释。

（7）发布：套件以 CC BY 4.0 发布为 Harbor 任务，并附带四模型运行的 job 配置；release v1.0 是论文对应的版本。这使评估协议可复核，但任务生成、评分细则和 26 模型名单仍需回原文与仓库核对。

Q4: 论文做了哪些实验？

（1）四前沿模型主实验：在 131 个任务上评估 Claude Opus 5、GPT-5.6-sol、Grok 4.5、Gemini 3.1 Pro，共 4,249 次 rollout；报告均分、配对差异和任务族分数。Table 4 使用 130 个四模型均有测量的任务做族间比较。

（2）任务族分层：至少报告元数据查找（36 个任务）、数值计算（28 个）、概念推理（16 个任务含一个评分组件）、序列验证等族；逐族比较模型，检验总分接近是否掩盖族间反转。

（3）分数信度：对 486 个模型-任务单元做八次重复，计算 Spearman–Brown split-half 信度，得到 0.962；该指标衡量同一模型-任务重复运行的分数稳定性，不直接回答模型间差异是否真实。

（4）运行预算与排名稳定性：模拟每任务只运行一次，用 bootstrap 重采样任务，统计第一名变化的频率；结果 23.9% 的重采样把不同模型排在第一。该实验把“评估预算”作为排名不确定性的来源。

（5）访问条件实验：在 15 任务切片上比较移除网络访问与屏蔽八个结构数据库域。结论是屏蔽域降分 0.08–0.10，移除网络降分 0.13–0.24（依基线而定）；但两组对照在不同评分 pass 中完成，不能把差值读成干净的访问机制残差。另有一个坐标来源实验：实验坐标且断网时均分 0.515，比匹配参考臂低 0.237。

（6）harness 替换实验：把每个模型替换为其自带的命令行 agent，观察分数变化；范围为 −0.071 至 +0.086。作者认为该对比的精度不足以排除中等 harness 效应。

（7）26 模型扩展：在 4,486 次补充试验上做跨模型回归，检验 numeric 表现是否随 non-numeric 表现持平或上升；得到正斜率 +0.672（95% CI [+0.318,+0.982]），但因奖励下限造成偏差，作者只做有限结论。

（8）失败集分析：统计四个模型全部失败的 12 个任务，发现其中一半是数值任务；数值任务只占 28/131，却在全员失败集中过度出现。该分析描述难度集中，不等同于任务区分度分析。

（9）评分诊断：检索片段还提示 passing 集合（reward > 0.85）与 no-accuracy-credit 集合（reward < 0.15）可能出现重叠，说明仅凭最终恢复的数字不足以解释得分；由于上下文不完整，这一点需回原文核对具体统计口径。

Q5: 发现了什么实验现象？

（1）总分接近，但任务族剖面不同。四个前沿模型均分 0.707–0.816；Opus 5 与 GPT-5.6-sol 只差 0.003，Opus 5 与 Grok 4.5 的原始差为 0.030，但去掉被排除的基础设施单元后变为 +0.023 且区间跨零，作者因此把领先三者视为未分辨，只把 Gemini 3.1 Pro（0.707）与三者分开。这个结果本身是负结果：在总榜上，除 Gemini 外没有可靠排序。

（2）任务族出现反转。元数据查找族中，Opus 5 为 0.907、Grok 4.5 为 0.855、GPT-5.6-sol 为 0.852、Gemini 3.1 Pro 为 0.713；三个模型在该族最高，且数值计算是其最弱族。Gemini 是例外：数值计算反而是其最好族。Grok 4.5 的数值计算只有 0.636，是四者最低，却在概念推理上排第二。这说明“前沿模型都擅长 lookup、弱于 geometry”是常见模式，不是普遍规律；标题的概括必须加上“三个模型”这一限定。

（3）数值任务在全员失败集中过度出现。数值任务只占 28/131，却占四个模型全部失败的 12 个任务的一半。这更像是难度集中：数值任务里有一批所有模型都做不出的题。它不能证明数值任务比其他族更能区分模型；相反，全员失败任务对模型间排名没有贡献，反而降低了有效区分度。若把“数值任务占比高”误读为“数值任务最关键”，就会把难度和区分度混为一谈。

（4）高分信度与排名不稳定并存。八次重复的 split-half 信度为 0.962，说明同一模型-任务的分数很稳定；但每任务只运行一次时，23.9% 的 bootstrap 重采样会把另一个模型排在第一。两者不矛盾：前者是重复运行下的分数稳定性，后者是任务抽样与预算限制下的模型排序不确定性。高信度不保证小差距可分辨。

（5）访问条件的影响不对称，但不能干净分解。15 任务切片上，屏蔽八个结构数据库域的降分为 0.08–0.10，移除网络的降分为 0.13–0.24；实验坐标且断网时均分 0.515，比匹配参考臂低 0.237。表面上看“断网影响大于屏蔽域”，但两组对照在不同评分 pass 中完成，作者明确不把二者差值读成测得的残差。这是一个重要的方法学克制。

（6）harness 替换带来双向变化。分数变化从 −0.071 到 +0.086，说明 harness 不是无关紧要的实现细节；但该对比的精度不足以排除中等 harness 效应，因此不能据此断言某个模型“本质上”更强。对 agent 排行榜而言，这意味着 harness 应作为报告项，而不是隐含默认。

（7）26 模型上 numeric 与 non-numeric 正相关，而非此消彼长。回归斜率为 +0.672（95% CI [+0.318,+0.982]），即数值表现随非数值表现上升。作者提醒 Figure 2b 的奖励下限会偏置估计，因此只能得出“在这些任务上数值表现随非数值表现上升”的有限结论，不能推出“缩放模型会因果性提升数值能力”。

（8）评分地板与 judge 权重构成诊断风险。0.100 的完整性下限意味着低分任务可能不是零分；5.3% 的 LLM judge 权重意味着评分并非完全确定性。检索片段还提示 passing 与 no-accuracy-credit 集合可能重叠，暗示最终恢复的数字不是唯一解释来源。这些现象要求读者在比较族间分数和跨模型回归时检查评分口径，而不能只看均分。

（9）总体模式：聚合分数像是一个混合指标，把检索、计算、工具访问、harness 和评分地板混在一起；任务族分层后，模型的能力剖面和失败模式才变得可读。论文最强的经验结论不是“谁第一”，而是“总分会掩盖什么”。

Q6: 有什么可以进一步探索的点？

（1）全因子评估设计：目前不同实验使用不同任务子集，不能把模型、harness、网络访问、数据库访问和任务组成排出主次。下一步应在同一任务子集上做完全或部分因子设计，至少让每个模型在相同任务、相同访问条件和相同 harness 条件下交叉运行，才能估计主效应与交互作用。

（2）分层随机切片与功效分析：15 任务切片的选择不是随机抽样，虽然选择先于 factorial 结果，但外推受限。可预先注册分层随机抽样，按任务族、难度和结构类型分层，并报告每个族的最小可检测效应；这比事后选切片更能支持族间比较。

（3）测量模型与不确定性传播：把模型能力、任务难度、评分噪声、运行次数和 harness 变异写成多层贝叶斯模型或测量模型，显式估计“模型间差异”的后验，而不是只对任务做 bootstrap。这样可以同时处理重复运行、任务抽样和评分地板，避免把 0.962 的信度误当成排序确定性。

（4）过程级错误分类：论文的结果指向“lookup 强、geometry 弱”，但没有充分展示失败发生在哪一步。后续可对数值任务做轨迹级标注：是否找错链/残基、是否选错原子、是否读错坐标单位、是否混淆距离与二面角定义、是否在工具调用中丢失精度。这类错误分类学比总分更能指导 agent 与工具设计。合理推断：数值任务的失败可能集中在原子识别和几何定义，而不是算术本身，但需要原论文的过程数据验证。

（5）工具与访问策略的受控比较：断网、屏蔽数据库域、提供本地结构文件、提供专用几何工具，是不同干预。未来应在同一任务上比较“检索工具”“坐标计算工具”“两者都有”和“两者都无”，并记录工具调用次数与错误类型，才能把访问效应分解为检索缺失、计算缺失和协调失败。

Q7: 总结一下论文的主要内容

（1）问题定位：论文关注的不是再训练一个蛋白质结构模型，而是追问蛋白质结构智能体的基准分数到底测到了什么。一个结构生物学家可能先问某个结构如何被测定，再要求智能体从同一坐标文件计算距离或二面角；前者可从数据库记录检索，后者必须识别原子并执行计算。单一聚合分数可能把这两种能力混在一起。ProteinGeoBench 因此把任务拆成元数据查找、数值计算、概念推理、序列验证等族，并在 131 个任务上评估四个前沿模型，另用 26 个模型做扩展试验。

（2）基准与评估设计：131 个任务中 28 个是数值任务；论文使用 4,249 次四模型 rollout，并对 486 个模型-任务单元做八次重复以估计分数可靠性；另有 4,486 次跨 26 模型试验。评分包含 0.100 的完整性下限和 5.3% 权重的 LLM judge，因此并非完全确定性评分。评估不只报告总分，还报告任务族分数、配对任务 bootstrap 区间、单次运行下的排名稳定性，以及在 15 任务切片上改变网络访问、屏蔽八个结构数据库域、替换模型自带 CLI harness、改变坐标来源的对照。

（3）主要发现：四个前沿模型均分 0.707–0.816；Opus 5、GPT-5.6-sol、Grok 4.5 三个领先者在 0.031 内，彼此差异多未分辨；Gemini 3.1 Pro 为 0.707，与三者差距均排除零。聚合分数掩盖了任务族差异：三个模型在元数据查找上高于数值计算，Gemini 例外，数值计算反而是其最好族；Grok 4.5 数值最低（0.636）但概念推理第二。数值任务只占 28/131，却占四个模型全部失败的 12 个任务的一半，说明该族聚集了高失败率任务，但不能据此推断它更能区分模型，因为全员失败任务本身不提供模型间区分。

（4）评估条件的影响：单次运行下，23.9% 的 bootstrap 重采样会把另一个模型排到第一，尽管八次重复的 split-half 信度高达 0.962；这说明单个分数稳定不等于模型间差异可分辨。15 任务切片上，移除网络访问比屏蔽八个结构数据库域降分更多（屏蔽域 0.08–0.10，断网 0.13–0.24，依基线而定），但两组对照在不同评分 pass 中完成，不能把差值读成干净的残差。替换 harness 使分数变化 −0.071 至 +0.086，区间不足以排除中等 harness 效应。26 模型上，数值表现随非数值表现上升而非持平，回归斜率 +0.672（95% CI [+0.318,+0.982]），但奖励下限造成偏差，且这是相关而非因果缩放证据。

（5）论证主线与边界：论文的结论不是“某模型最好”，而是“按任务族报告分数，并同时报告运行次数、harness 和访问条件”；不同实验使用不同任务子集，无法把模型、harness、访问条件和任务组成排出主次。该工作属于基准与测量方法论文，贡献在于暴露聚合分数的掩蔽效应和评估条件敏感性，而不是提出新的结构预测或生成算法。
