# HALO: Human-Grounded Granular Evaluation of Proactive Agents

> ★★☆☆☆ 按需阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：proactive agents · human evaluation · agent benchmark · evidence retrieval

## 一句话总结

HALO 提出一个以人类细粒度标注为核心的主动代理评估框架，构建覆盖4类主动需求、10个日常领域和50个个人环境的 HALO-Arena，以及包含10个模型、400个场景、8000条响应和20位专家标注的 HALO-8K，用行动等级、可接受性与拒绝诊断揭示模型在“是否/何时/帮到什么程度”上的差异，并强调证据检索与授权边界。

## 摘要

> 主动代理必须在没有显式请求时决定是否协助、何时协助、协助到什么程度，并判断何时应克制。现有评估多依赖自动分数或二元判定，难以诊断代理是否恰当使用了检索证据、干预时机与强度是否合理、行动是否越出用户授权范围。HALO（Human-Grounded GrAnular EvaLuation of Proactive Agents）针对这一缺口，提出 HALO-Arena：覆盖 Dependency、Blockage、Risk、Opportunity 四类主动需求，横跨10个日常领域和50个个人环境；场景要求代理先从结构化数据库或非结构化文档中检索证据，再判断协助是否必要并选择行动范围。基于该 Arena 构建 HALO-8K：10个模型在400个场景上的8000条响应，由20位专家标注行动等级、可接受性判定和人类诊断；对被拒响应诊断时机、强度及其他问题，并记录推理 token 与检索轮次。实验比较5个专有模型和5个开源模型，可接受性从30.38%到72.88%，最强模型仍有超过25%响应不可接受；专有模型均值63.08%，开源模型47.55%；开源最佳的 DeepSeekV4-Pro 为56.63%。检索轮次与可接受性在10个模型均值层面呈强正相关（r=0.885，ρ=0.830）。清理后的摘要显示，论文的核心贡献是评估协议与诊断数据，而不是提出新的代理模型；具体数值和样本关系仍需结合原文表格核对。

Q1: 这篇论文试图解决什么问题？

heuristic_draft 在本字段主要是 PDF 双栏错位和格式指令残片（如“within the user’s authority”“For example, Lu et al.”），不能作为论文动机依据；以下依据摘要和 Results 片段重构，并对推断处标注。
1. 核心决策问题：主动代理与被动响应式代理不同，它必须在没有显式用户请求时判断“是否行动、何时行动、行动到什么程度”，同时知道“何时不行动”。这不是单一分类问题，而是由需求识别、证据检索、时机判断、强度选择、授权范围判断和克制决策组成的联合问题。论文把这种联合决策作为评估对象，而不是只评估任务成功率。
2. 现有评估的测量缺口：摘要明确指出，现有评估常依赖自动分数或二元 verdict，对人类如何诊断证据使用和干预质量提供的信号有限。二元判定只能告诉研究者“接受/拒绝”，不能区分拒绝是因为时机太早、强度过大、行动越权、证据不足，还是根本不该介入。这会使不同失败模式被压缩成同一个低分，难以指导模型改进。
3. 证据与授权分离：论文用旅行日历的例子说明，同一组事实可以支持“提醒检查旅行用品”，却不支持“直接完成购买”。日历条目、数据库中的用品记录、文件中的购买授权，分别影响干预的时机、内容和合法范围。主动代理必须把检索到的证据用于三个不同判断：是否需要介入、介入内容是什么、介入是否在用户授权内。
4. 评估场景的设计挑战：HALO-Arena 覆盖 Dependency、Blockage、Risk、Opportunity 四类需求，跨10个日常领域和50个个人环境。场景要求代理从结构化数据库或非结构化文档检索证据，再判断协助是否 warranted 并选择 scope。这意味着评估不能只给模型一段用户活动文本，而必须构造多源证据、权限标签和行动空间，否则无法区分“看到了需求”与“有资格行动”。
5. 人类细粒度诊断的必要性：论文引入20位专家标注行动等级、可接受性和人类诊断；对被拒响应进一步标注 timing、intensity 和其他问题。这一设计背后的假设是：主动干预的可接受性具有上下文依赖性，难以用固定规则或自动指标完全替代人类判断；同时，拒绝本身是有信息量的诊断信号，而不只是负样本。
6. 评价范式的张力：Results 片段提到“verdict gains can therefore mask diagnostic failures”，并出现准确率下降11.00和28.75个百分点的重分类/扰动结果。这提示仅优化可接受率可能掩盖证据使用、时机或强度上的诊断问题；论文因此不仅报告接受率，还报告拒绝原因和检索行为。
7. 边界与隐含假设：论文解决的是评估基础设施和测量有效性问题，不直接提出更强的主动代理模型；其因果主张有限。可接受性被当作可操作构念，但专家判断与真实用户长期效用之间的关系仍需验证。片段未显示标注者间一致性、场景难度分布和统计显著性检验，这些是阅读原文时应优先核对的方法缺口。

Q2: 有哪些相关研究？

1. 主动代理与任务提议：摘要提到 Lu et al. (2024) 训练代理从观察到的用户活动中提议任务，并报告66.47%的 F1；Tang et al. (2026) 等工作也涉及直接提供用户活动观察的设定。这类研究的共同点是让代理从行为痕迹推断潜在需求，但“观察到需求”并不等于“拥有补救手段”或“获得行动许可”，HALO 的评估设计正是把这一区分显式化。
2. 证据获取方式不同的 benchmark：论文指出不同 benchmark 在代理如何获得证据上存在差异。有的直接提供用户活动（Lu et al., 2024; Tang et al., 2026），这些观察可能只显示需求，而不建立补救方案或行动授权；PROBE 支持 SQL 和语义文档检索（Pasternak et al., 2025）；交互式 benchmark 还支持额外工具使用（Oh et al., 2026; Zhang et al., 2026）。HALO 的定位是把结构化数据库检索、非结构化文档检索、授权范围判断和人类可接受性诊断放进同一个场景框架。
3. 评估范式的差异：现有工作常用自动评分、任务完成率或二元 verdict 衡量代理表现；这些指标适合大规模比较，但对“为什么不可接受”诊断不足。HALO 的 Related Work 逻辑应是：主动代理的失败往往不是任务没做完，而是介入不该介入的时机、用了不该用的权限、或把“可以提醒”误判为“可以执行”。因此需要把拒绝原因、行动等级和证据使用纳入评估。
4. 与人类评估工作的关系：HALO 不是第一个使用人类评估的 agent benchmark，但它强调“human-grounded granular evaluation”，即不仅让人判断整体好坏，还让人标注行动等级和拒绝诊断。其贡献更接近评估协议与数据集，而不是新模型或新训练目标。
5. 与授权/安全研究的相邻关系：论文的场景标签包含 Identity、Responsibilities、Authority、Restrictions 等（来自 Results 中混入的场景生成模板片段），说明它把用户身份、职责、权限和限制作为场景构造的一部分。这与主动代理的权限控制、隐私边界和“最小必要干预”问题相邻；但片段没有展开具体的权限模型，不能推断论文提出了新的授权算法。
6. 与主动推荐/主动对话的区别：传统推荐系统评估点击率或满意度，主动对话评估用户参与度；HALO 评估的是“是否需要主动介入”以及“介入是否可接受”，更接近 agent 的行为决策评估。它把“克制”作为正面能力，而不是把所有未行动都视为失败。
7. 证据校准：heuristic_draft 的 related work 字段没有可用内容，limitations 字段混入了参考文献（如“Context-aware proactive LLM agents with open-world sensory perceptions”），不能当作论文局限；以上相关研究依据摘要中明确出现的引用和 Results 片段重构，未出现的具体 benchmark 名称和结论不做补写。

Q3: 论文如何解决这个问题？

1. 总体思路：论文不训练新模型，而是构建一套评估基础设施——HALO 框架、HALO-Arena 场景集、HALO-8K 响应数据集和在线标注平台——用来测量主动代理在证据检索、行动范围选择和克制上的表现。核心方法贡献是“把主动协助拆成可标注的决策维度”，而不是提出某个更强的 agent 架构。
2. HALO-Arena 的需求分类：Arena 覆盖四类主动需求——Dependency（依赖）、Blockage（阻塞）、Risk（风险）、Opportunity（机会）。按字面推断，它们分别对应“需要外部资源/他人支持”“任务被卡住”“存在潜在损失”“存在可优化机会”的场景；论文用这四类需求保证主动介入的动机多样，而不是只评估提醒类任务。
3. 场景规模与结构：Arena 覆盖10个日常领域和50个个人环境。Results 片段混入了场景生成模板，显示场景至少包含 scenario_description、Identity/Responsibilities/Authority/Restrictions 等标签、events 和 init_data_commands，并提到4到6的轨迹长度；这些字段的正式定义需回原文确认，但可以看出场景不是单一文本，而是带有用户身份、职责、权限、限制、事件序列和初始数据命令的结构化环境。
4. 证据检索设计：场景要求代理从结构化数据库或非结构化文档中检索证据，再判断协助是否 warranted 并选择 scope。摘要中的旅行例子说明，日历条目可能触发检查旅行用品的数据库查询，而购买授权可能在另一个文件中；代理必须跨源检索，并把证据用于时机、内容和权限三个判断。这使 HALO 能区分“没有检索到证据”“检索到证据但误用”“证据支持提醒但不支持执行”等失败模式。
5. HALO-8K 数据构建：10个模型在400个场景上产生8000条响应；20位专家标注行动等级、可接受性 verdict 和人类诊断。对被拒响应，专家进一步诊断 timing、intensity 和其他问题，其中 Results 片段显示“过度主动（over-proactivity）”占其他拒绝原因的38.8%。同时记录 reasoning tokens 和 retrieval rounds，作为过程行为指标。
6. 评估模型：5个专有模型为 Gemini3.8-Flash、Gemini3.1-Pro、Claude-Opus5.5、Grok4.7、GPT5.6-Luna；5个开源模型为 DeepSeekV4-Pro、GLM5.3-Flash、Qwen3.5-9B、Qwen3.8-27B、GPT-OSS-20B。论文在同一标注协议下比较这些模型，并分别报告总体可接受性、组均值、组内分布和拒绝原因。
7. 标注平台：论文在 Streamlit Community Cloud 部署在线标注平台，前端使用 Streamlit。这属于工程实现细节，但说明评估是可操作的多人标注流程，而不是小规模作者自查。
8. 方法上的关键操作化：把“行动等级”与“可接受性”分开标注，使同一个响应可以同时具有“行动程度”和“人类是否接受”两个维度；把拒绝响应继续诊断，使失败原因可分类；把检索轮次和推理 token 记录下来，使过程指标可以与人类判断做相关分析。
9. 证据缺口：Results 片段一方面说 HALO-8K 有8000条响应，另一方面说“这些分数覆盖100条完成且人工标注的响应，排除传输和解析失败”。这两者的关系在片段中不清楚：可能是每模型100条评分、总池8000条，也可能是其他抽样设计。阅读原文时必须核对评分样本量、抽样方式和每场景响应数，否则会高估统计功效。

Q4: 论文做了哪些实验？

1. 评估设置：论文在相同标注协议下评估10个模型，其中5个专有模型、5个开源模型。专有模型包括 Gemini3.8-Flash、Gemini3.1-Pro、Claude-Opus5.5、Grok4.7、GPT5.6-Luna；开源模型包括 DeepSeekV4-Pro、GLM5.3-Flash、Qwen3.5-9B、Qwen3.8-27B、GPT-OSS-20B。模型名称和分组来自 Results 片段，属于论文明确信息。
2. 场景与响应规模：实验覆盖400个场景，产生8000条响应；场景来自 HALO-Arena 的4类需求、10个领域和50个个人环境。每条响应由20位专家标注行动等级、可接受性 verdict 和人类诊断；被拒响应诊断 timing、intensity 和其他问题。Results 片段还提到“100条完成且人工标注的响应”，具体是每模型100条还是总评分集，需要回原文确认。
3. 主要指标：可接受性（acceptability）是核心结果指标；行动等级（action level）用于刻画代理选择了多大范围的干预；检索轮次（retrieval rounds）和推理 token 用于刻画过程努力；拒绝诊断用于分类失败模式，其中过度主动是“其他拒绝”下的一个类别。
4. 分析设计：论文比较总体可接受性、专有/开源组均值、组内离散度、组间重叠、拒绝原因分布，以及检索轮次与可接受性在10个模型均值层面的相关。片段报告 Pearson r=0.885、Spearman ρ=0.830，说明模型级检索努力与人类可接受性同向变化；这是观察性相关，不是响应级因果效应。
5. 诊断性分析：Results 片段提到对自由文本评论重新分类、以及某种扰动/重分类下准确率下降11.00和28.75个百分点；还提到“verdict gains can therefore mask diagnostic failures”。这些应被理解为评估方法实验：只看接受率可能掩盖证据使用、时机或强度上的诊断问题，因此论文同时报告拒绝诊断。
6. 反直觉/过程分析：片段显示 L0 响应平均16.74条命令，而401条被接受干预平均14.65条命令。若 L0 指最低行动等级或不行动，这意味着部分模型在“不该行动”时仍进行了大量工具调用；该句跨栏严重，L0 定义和样本范围需回原文确认。
7. 公平性检查点：片段没有报告每个模型的推理预算、工具预算、重试次数和版本差异；专有/开源比较可能受这些因素影响。论文用同一标注协议控制判断标准，但不能完全控制模型侧推理资源。阅读时应核对是否报告了置信区间、显著性检验和每场景分层结果。
8. 缺失的实验信息：片段未显示标注者间一致性、场景难度分层、按需求类型/领域的细分结果、以及真实用户研究。不能因为片段没出现就断言论文完全没有做，但这些是评估此类 benchmark 时必须优先查找的内容。

Q5: 发现了什么实验现象？

1. 可接受性跨度很大：10个模型的可接受性从30.38%（GPT-OSS-20B）到72.88%（Gemini3.8-Flash），相差42.50个百分点。这说明在同一标注协议下，主动代理的“人类可接受性”差异远大于一般任务准确率的常见差距；即使最强模型也有超过25%的响应不可接受。
2. 专有/开源均值差距明显但组内异质：专有模型平均63.08%，开源模型平均47.55%，相差15.53个百分点。开源最佳 DeepSeekV4-Pro 为56.63%。但组均值掩盖了分布：开源组最强的三个模型彼此相差在2.50个百分点以内，而整个开源组跨度达26.25个百分点，说明低均值同时反映“顶部不差”和“弱尾很长”。
3. 分组标签不是个体质量的可靠代理：片段明确指出 DeepSeekV4-Pro 超过 Gemini3.1-Pro 和 GPT5.6-Luna，说明专有/开源二分不能完整解释个体表现。评估应报告模型级分布和配对比较，而不是只比较组均值。
4. 过度主动是主要拒绝原因之一：在“其他拒绝”中，过度主动占38.8%。这与论文强调“知道何时克制”的主线一致：失败不只是“没帮上忙”，还包括在不该行动时行动、行动强度过大或越出授权范围。该数值的分母是“其他拒绝”而非全部响应，解释时不能把它当成总体失败率。
5. 检索轮次与可接受性在模型均值层面强正相关：跨10个模型，Pearson r=0.885，Spearman ρ=0.830。合理解释是：更充分的证据检索有助于代理判断是否需要介入、介入内容和授权范围；但这是模型级相关，不能推断“增加检索轮次”一定会让单个响应更可接受，也可能只是更强模型同时更愿意检索。
6. 命令数量与可接受性不是简单正比：片段显示 L0 响应平均16.74条命令，而401条被接受干预平均14.65条命令。若 L0 是不行动/最低行动等级，则“不行动”响应反而调用了更多命令，提示部分模型在无效探索或过度操作；这与“检索轮次正相关”形成张力——关键可能不是工具调用总量，而是检索是否服务于正确的授权判断。该解释是合理推断，L0 定义需回原文确认。
7. 诊断信号可能被 verdict 掩盖：片段提到在重新分类自由文本评论等操作下出现11.00和28.75个百分点的准确率下降，并指出 verdict 增益可能掩盖诊断失败。这意味着两个模型可能有相近的可接受率，但一个主要错在时机、另一个主要错在强度或越权；只看接受率会丢失这种差异。
8. 失败模式具有上下文依赖性：timing、intensity、other 三类诊断说明“拒绝”不是单一现象。过度主动占其他拒绝的38.8%，而片段还出现“Unsupported Ev...”字样（可能指未支持证据/证据不足，但被截断），提示证据使用也是独立失败维度；具体标签定义需回原文核对。
9. 没有模型接近饱和：最强模型72.88%可接受，仍留下27.12%不可接受；开源最低30.38%。这说明主动代理在个人环境中的授权、时机和范围判断仍是开放问题，HALO 的分数不是“接近解决”的信号。

Q6: 有什么可以进一步探索的点？

1. 扩展场景覆盖：当前 Arena 是4类需求、10个领域、50个个人环境、400个场景。可以扩展到更多文化/语言/家庭结构/组织环境，加入多用户权限冲突、长期目标和跨应用工作流；也可以加入多模态感知（日历、邮件、文件、传感器）和动态环境变化，检验代理在证据演化下的时机判断。
2. 从静态响应到交互式评估：HALO 目前评估单次响应层面的行动等级和可接受性。未来可以把场景做成多轮交互：代理可以询问澄清、被用户拒绝后调整、在延迟后重新介入；测量打断成本、信任修复、用户控制感和长期接受度。真实用户在线 A/B 研究是外部效度的关键补充。
3. 把人类诊断转化为训练信号：timing、intensity、over-proactivity、unsupported evidence 等诊断可以变成细粒度偏好数据或 reward model，训练代理学会“先检索证据、判断授权、再决定行动范围”。也可以训练模型输出不确定性并选择询问而非行动。
4. 因果检验检索行为：当前检索轮次与可接受性是模型级相关。未来可以做干预实验：固定模型和场景，强制增加/减少检索轮次，或控制工具预算，看可接受性是否提升；同时区分“有效检索”和“无效工具调用”，避免把命令数量当努力代理。
5. 评估方法学：需要报告标注者间一致性、置信区间、场景难度分层和显著性检验；研究自动评估与人类判断的对齐，降低20位专家标注的成本。可以引入分层贝叶斯模型分离模型能力、场景难度和标注者严格度。
6. 授权与安全：HALO 的场景标签包含 Authority/Restrictions，但片段没有展开权限模型。未来可以把真实权限系统、隐私预算、可审计日志和“最小必要干预”原则纳入评估；研究过度主动的社会风险，以及用户如何撤回/限制代理权限。
7. 科学应用迁移：对 ai-for-science 方向，HALO 的“证据检索—授权范围—行动强度”框架可以迁移到实验室自动化、科学助手和计算工作流代理：代理可以提醒实验步骤或检索协议，但是否允许下单、修改参数、提交任务需要独立授权判断。当前论文场景是日常个人环境，不是生物实验，迁移时需要重新定义证据源、风险等级和权限边界。
8. 理论化主动性：可以用 POMDP/成本收益框架形式化“何时询问、何时行动、行动到哪一步”，把信息价值、打断成本和错误行动代价纳入目标；HALO 的诊断数据可以作为验证这类理论模型的实证基础。

Q7: 总结一下论文的主要内容

一、论文定位：HALO 是一篇评估型论文，核心不是提出新的主动代理模型，而是提出一套“人类 grounded、细粒度”的评估框架，用来测量主动代理在没有显式请求时是否、何时、以多大范围介入。论文的论证主线是：主动代理的关键能力不仅是完成任务，还包括证据检索、授权判断和克制；现有自动评分/二元 verdict 无法诊断这些维度，因此需要人类专家对行动等级、可接受性和拒绝原因做细粒度标注。
二、问题背景：主动代理必须决定是否协助、何时协助、协助到什么程度，并知道何时不应介入。现实中的证据往往分散在日历、数据库、文件等不同来源；同一证据可能支持提醒，却不支持执行购买。现有 benchmark 在证据供给方式上不同：有的直接提供用户活动观察，有的支持 SQL/语义文档检索，有的支持额外工具使用。直接观察用户活动可能只显示需求，不能建立补救方案或行动许可，因此评估需要把“证据检索”和“授权范围”分开。
三、HALO-Arena 设计：Arena 覆盖四类主动需求——Dependency、Blockage、Risk、Opportunity，横跨10个日常领域和50个个人环境。场景要求代理从结构化数据库或非结构化文档中检索证据，再判断协助是否 warranted 并选择 scope。Results 片段混入的场景生成模板显示，场景至少包含 scenario_description、Identity/Responsibilities/Authority/Restrictions 标签、events、init_data_commands，并提到4到6的轨迹长度；这些字段的正式定义需回原文确认，但可以看出场景是带有用户身份、职责、权限和限制的结构化环境，而不是单一提示。
四、HALO-8K 数据与标注：论文构建 HALO-8K，包含10个模型在400个场景上的8000条响应，由20位专家标注。标注维度包括行动等级、可接受性 verdict 和人类诊断；对被拒响应，专家诊断 timing、intensity 和其他问题，其中过度主动占其他拒绝原因的38.8%。论文还记录 reasoning tokens 和 retrieval rounds，作为过程行为指标。标注平台部署在 Streamlit Community Cloud，前端使用 Streamlit。
五、评估模型与协议：论文比较5个专有模型（Gemini3.8-Flash、Gemini3.1-Pro、Claude-Opus5.5、Grok4.7、GPT5.6-Luna）和5个开源模型（DeepSeekV4-Pro、GLM5.3-Flash、Qwen3.5-9B、Qwen3.8-27B、GPT-OSS-20B）。所有模型在同一标注协议下评分；Results 片段称分数覆盖100条完成且人工标注的响应，排除传输和解析失败。这里存在样本量关系不清的问题：8000条总池与100条评分集是每模型抽样还是其他设计，必须回原文核对。
六、主要发现：可接受性从30.38%到72.88%，跨度42.50个百分点；GPT-OSS-20B最低，Gemini3.8-Flash最高。专有模型平均63.08%，开源模型平均47.55%，相差15.53个百分点；开源最佳 DeepSeekV4-Pro 为56.63%。最强模型仍有超过25%响应不可接受。开源组最强三个模型彼此相差在2.50个百分点以内，但全组跨度26.25个百分点，说明低均值来自弱尾；组间也有重叠，DeepSeekV4-Pro 超过 Gemini3.1-Pro 和 GPT5.6-Luna，因此专有/开源标签不能完整解释个体质量。
七、过程与诊断发现：检索轮次与可接受性在10个模型均值层面强正相关（r=0.885，ρ=0.830），提示证据检索努力与更好的人类判断同向；但这是观察性相关。片段还显示 L0 响应平均16.74条命令，而401条被接受干预平均14.65条命令，提示“更多工具调用”不必然转化为更可接受的干预；若 L0 为不行动/最低行动等级，则部分模型在不应行动时仍大量调用工具。过度主动占其他拒绝的38.8%，说明克制是核心失败维度。重新分类/扰动下出现11.00和28.75个百分点的准确率下降，说明 verdict 增益可能掩盖诊断失败。
八、论证主线与贡献：论文的论证链是“主动代理需要证据检索和授权判断→现有自动/二元评估诊断不足→构建带权限标签和多源证据的 Arena→用20位专家做行动等级、可接受性和拒绝诊断标注→实证发现模型间巨大差异、过度主动和检索行为关联→主张人类细粒度评估是主动代理评估的必要组成”。贡献包括评估框架、Arena、8K 数据集、拒绝诊断 taxonomy、过程指标分析和实证发现。
九、局限与证据缺口：片段未显示标注者间一致性、置信区间、显著性检验、按需求类型/领域的细分结果和真实用户研究；100条评分集与8000条总池的关系不清；L0 定义、重分类实验条件、Unsupported Evidence 标签定义均需回原文确认。论文评估的是响应可接受性，不等同于真实用户长期效用；检索轮次与可接受性的相关不能直接解释为因果。专有/开源比较还需核对推理预算、工具预算和版本公平性。
十、阅读建议：先读 HALO-Arena 的场景 schema 和 action level 定义，再读标注指南与拒绝诊断 taxonomy，最后核对 Results 中的样本量、相关分析和重分类实验。若关注 agent 评估方法，重点看“拒绝诊断”和“过程指标”如何与人类判断结合；若关注主动代理安全，重点看 Authority/Restrictions 标签和过度主动的38.8%。
