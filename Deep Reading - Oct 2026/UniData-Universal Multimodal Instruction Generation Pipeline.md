# UniData: Universal Multimodal Instruction Generation Pipeline

> ★★☆☆☆ 按需阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：multimodal instruction generation · multimodal large language models · data generation pipeline · multi-round dialogue

## 一句话总结

UniData 提出一种通用多模态指令生成流水线，将简单用户需求先扩展为多样事件，再借助 any-to-any 大模型按事件生成多轮多模态指令，并在推理阶段利用跨轮相关性修正无关或冗余指令流，以低成本构建高质量的多模态指令数据集，实验表明其生成数据质量在相关性、正确性、多样性等多个维度上优于已有生成流水线。

## 摘要

> 论文关注多模态大语言模型（MLLM）训练数据稀缺问题。由于人工构建高质量多模态指令数据成本高昂，现有自动生成方法大多只支持单一场景、单一模态或单轮指令，难以满足真实世界应用对多模态、多轮指令的需求。为此，作者提出 UniData 通用指令生成流水线：(1) 将用户简单需求扩展为多个多样化事件；(2) 利用 any-to-any 多模态大模型基于事件生成多轮多模态指令；(3) 在推理阶段根据指令轮次间相关性纠正无关和冗余的生成流，提升数据质量。同时作者构建了 UniDataset 训练数据，并设计了用于评估生成数据质量的评测方式。实验表明 UniData 生成的数据在论文考察的四个质量维度上均超过其他生成流水线。

Q1: 这篇论文试图解决什么问题？

1. 核心问题：多模态大语言模型（MLLM）在真实场景应用中对高质量多模态指令数据的需求越来越大，但此类数据稀缺且人工标注成本极高。
2. 现有自动/半自动生成方法（如基于 GPT 的方案）通常只针对单一具体场景设计，不能泛化到更广泛的应用；许多方法在模态支持上受限，输出往往只覆盖文本模态，难以生成图像、音频、视频等多模态输出。
3. 现有方法大多难以生成多轮多模态指令。真实世界对话往往需要多轮交互，指令之间具有时序和语义关联，若只生成单轮指令，训练出的模型缺乏多轮多模态理解与生成能力。
4. 多模态指令生成中容易出现跨轮指令无关、语义重复、逻辑断裂等问题，需要有效的质量控制机制，而现有流水线缺少基于指令轮次间相关性进行推理时纠错的手段。
5. 训练通用生成流水线本身缺乏现成的多模态输入-输出配对数据集，因为现存数据集中绝大多数只支持单一输出模态（尤其只支持文本输出），少数初始尝试（如 NExT-GPT 的 MosIT、GenHowTo）也受限于模态范围，因此需要自建 UniDataset。
6. 更深层的问题在于：数据生成流水线的“通用性”与“数据质量”之间存在张力——覆盖模态越广、轮次越多，生成的无关与冗余内容越难控制，这是论文试图通过事件扩展、any-to-any 生成和跨轮相关性纠错来同时解决的矛盾。

Q2: 有哪些相关研究？

1. 多模态大语言模型（MLLM）：已有大量工作（如 Liu et al., 2023; Li et al., 2023b; Lu et al., 2024b 等）聚焦于让模型理解多模态信息（文本、图像、音频、视频），但输出通常只是语言文本；SEED-X（Ge et al., 2024）和 Show-o（Xie et al., 2025）开始探索图像理解与生成的整合能力。UniData 则面向输入输出均为多模态且多轮的指令数据生成，定位更广。
2. 多模态指令数据构建：早期方法依赖人工收集与标注（Li et al., 2017），需要大量人力（Tang et al., 2024; Liu et al., 2024b; Fang et al., 2024）；部分方法引入 GPT（OpenAI, 2024）做自动或半自动数据生成（Li et al., 2023b; Liu et al., 2023），但往往只针对单一场景，难以泛化。
3. 多模态输入输出数据集：绝大多数现有数据集只覆盖单一模态尤其是输出只含文本；NExT-GPT 的 MosIT（Wu et al., 2024）和 GenHowTo（Souček et al., 2024）是最早包含多模态输入与输出的数据集，但模态范围仍然受限。UniData 通过自建 UniDataset 和生成流水线试图超越这些限制。
4. 多模态生成模型：论文实验中使用并评测了多种 any-to-any 生成模型与专门模型，包括用于评估音乐理解与生成的 MuMu-LLaMA（Liu et al., 2024a），以及可基于文本输入生成相关图像（即文生图）的模型，说明其评测涉及跨模态生成能力对比。
5. 数据质量评估：相关工作通常对生成指令数据做质量评测，但大多局限于单模态或文本指令；UniData 建立了面向多模态多轮指令的多维质量评测协议（相关性、正确性、多样性等维度），并对比多个生成流水线。

Q3: 论文如何解决这个问题？

1. 总体框架：UniData 是端到端的通用多模态指令生成流水线，输入是简单的用户需求，输出是大规模多轮多模态指令数据。流水线分为三大阶段：事件扩展、多模态指令生成、流纠正/质量控制。
2. 第一阶段——扩展多样化事件（Section 4.1）：先用随机因素（Stochastic Factors）等机制将用户基本需求扩展成 N 个多样化事件（Diverse Events），覆盖不同场景与角度，为后续多轮指令提供语义骨架。
3. 事件过滤：在事件扩展之后进行事件过滤，人工标注者丢弃不合理的事件并删除近似重复事件，更干净的事件能产生更好的下游提示与指令（Section 4.3 与 Appendix A.1 提到）。这一步体现了“生成+人工筛选”的半自动路线。
4. 第二阶段——any-to-any 多模态指令生成：利用一个 any-to-any 大模型，基于事件和此前已生成的多模态指令，预测下一轮多模态指令。生成采用带模态指示符（Multimodal Indicator）的多模态 tokenization：引入特殊 token 标记每个模态片段的开始与结束，从而区分文本、图像、音频、视频等模态。
5. 跨轮条件生成：模型输入包含用户需求/事件（Dn）与之前生成的多模态指令（Σ Imn），输出预测下一轮多模态指令 IMn，因此生成的多轮指令在时间顺序和语义上保持条件依赖。
6. 第三阶段——长期多轮指令流纠正（Section 4.3）：在长期多轮指令生成过程中，基于指令轮次之间的相关性（correlations between instruction rounds），纠正指令流并过滤掉不合理数据，例如与用户需求无关的轮次、语义重复冗余的轮次。这里的“流纠正”（correct the instruction flow）发生在推理阶段，而不是仅靠训练时 loss 隐式保证。
7. 训练数据构建（UniDataset）：为了训练该流水线，作者构建了同时包含多模态输入与多模态输出的 UniDataset。由于现有数据集大多只支持单一输出模态，作者需要从零搭建，包含话题池（Topic Pool）、人工标注与过滤等环节。
8. 评测协议：论文设计了四个质量维度对比不同生成流水线的输出数据质量（Table 1 给出定量结果），说明方法不仅关注生成能力，还关注生成数据作为训练语料的下游效用。
9. 需要说明：由于正文 Method/Experiments 章节未随元数据提供，上述步骤中关于“事件扩展—any-to-any 生成—流纠正”的三阶段结构来自摘要、Introduction 和附录语义检索片段，属于论文明确描述的主线；具体网络结构、训练损失、tokenizer 设计细节需要回原文确认。

Q5: 发现了什么实验现象？

1. 质量优势：UniData 生成的数据在评测的四个维度上均优于其他生成流水线，且这种优势在两个（或以上）评测模型/基准上方向一致，说明优势不是单一模型上的偶然现象。
2. 幅度特征：检索片段明确指出 gains“modest in magnitude”——改进方向稳定但幅度温和。这是一个值得注意的指标间张力：方法在系统设计上复杂度较高，但相对 baseline 的量化提升并非巨大，读者应关注实际增益与工程成本的权衡。
3. 模态覆盖效果：通过 MuMu-LLaMA 评测和文生图相关性评测可以看出，UniData 能把指令生成扩展到音乐/音频与图像模态，而现有数据集大多输出只含文本，这是能力边界上的直接对比现象。
4. 事件过滤带来的质量提升：人工剔除不合理事件与近重复事件后，下游提示与指令更干净，说明生成质量的上限受事件质量制约，事件层面的噪声会传播到多轮指令中。
5. 多轮相关性纠错的作用：在长期多轮生成中，基于轮次间相关性过滤无关和冗余内容能改善数据质量；这暗示 naive 自回归多轮生成会产生无关/重复指令流，是生成式数据管线中的典型失败模式。
6. 负结果与失败模式（合理推断）：检索片段中未见消融或失败案例分析；但“冗余与无关流”需要专门设计纠正机制，反过来说明直接 any-to-any 生成容易在长序列上发生语义漂移和重复，这是论文隐含观察到的失败模式。

Q6: 有什么可以进一步探索的点？

1. 扩展模态与场景覆盖：当前 UniData 已覆盖文本、图像、音频/音乐、视频等多模态输入输出，未来可进一步扩展到更多模态（如 3D、触觉、传感器数据）和更垂直的场景（如具身智能、自动驾驶、教育、科学发现）。
2. 降低人工成本：事件过滤和数据集构建仍依赖人工标注者筛选不合理事件和近重复项，未来可探索用模型自动过滤、主动学习或基于质量奖励模型的自动筛选来减少人工参与。
3. 提升生成质量的幅度：实验显示相对 baseline 的增益“modest”，未来可研究更强的 any-to-any 基础模型、多智能体协作生成、planning 与评审机制（生成-批评-修正循环）来拉开质量差距。
4. 多轮指令的一致性与长期记忆：当前基于跨轮相关性纠错，未来可引入显式对话状态跟踪、长期记忆模块或结构化事件图，保证数十轮以上长对话的语义一致性和实体一致性。
5. 更细粒度的质量控制：可将“相关/冗余”的二元过滤升级为可学习质量评分模型，对指令流逐轮打分，实现软过滤、重排序或受控重写。
6. 下游模型的 scaling 分析：研究不同规模、多样性和轮数分布的多模态指令数据对下游 MLLM 能力（理解、生成、多模态对话）的 scaling 规律，探索数据配比与课程学习策略。

8. 统一任何模态生成器：目前借助 any-to-any 大模型做指令生成，未来可训练专用于指令数据合成的统一多模态模型，让“数据生成器”本身随 MLLM 迭代共同进化。
9. 与 Agent/科学发现场景结合：结合用户画像中对 agent 与 AI for Science 的关注，可探索将 UniData 用于具身 agent 任务指令、实验操作多模态指令（图像-仪器-文本-音频）生成，并研究生成数据的可靠性与幻觉控制。

Q7: 总结一下论文的主要内容

UniData 针对 MLLM 训练数据稀缺和高昂人工成本问题，提出统一的通用多模态指令生成流水线。论文的论证主线是：真实世界 MLLM 应用需要多模态、多轮指令数据，但现有数据集多限于单输出模态，现有生成方法多限于单场景且难以多轮，因此需要一个既能覆盖多模态又能控制多轮质量的通用生成方案。技术主线是三步流水线：先把简单用户需求扩展成多个多样化事件，保证语义覆盖；再用 any-to-any 多模态大模型基于事件与已生成历史逐轮生成多模态指令，并通过特殊多模态 token 区分文本、图像、音频、视频等模态；最后在推理阶段基于指令轮次间相关性纠正无关与冗余的生成流。为训练该流水线，作者构建了同时包含多模态输入与输出的 UniDataset，并设计了包含事件过滤、话题池等环节的构建协议。实验主线是与现有指令生成流水线对比生成数据质量，在四个质量维度上 UniData 全面占优且优势在多个评测模型上方向一致，但幅度温和；评测还覆盖了音乐理解生成（MuMu-LLaMA）与文生图相关性等跨模态能力。论文的贡献包括：提出通用多模态指令生成流水线架构、引入事件扩展与跨轮相关性流纠正机制、构建 UniDataset、建立四维数据质量评测协议。局限方面：人工事件过滤仍需要人力；相对 baseline 的改进幅度有限；长程多轮一致性与更细粒度质量控制仍有空间。总体而言，这是一篇面向多模态数据引擎的系统性工作，把数据生成从单模态单轮推向多模态多轮，并用多维评测验证数据质量，而非直接提出新的 MLLM 架构。
