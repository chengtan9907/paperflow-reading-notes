# GitScholar: A Dataset for Predicting AI Research Impact from GitHub Engagement

> ★★★★☆ 推荐阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：research impact prediction · github engagement · arxiv · scientometrics

## 一句话总结

论文发布 GitScholar 数据集，把 44.4 万个 GitHub 仓库的互动数据与 55.8 万余篇 AI 领域 arXiv 论文建立链接，并用实验证明 GitHub 互动信号在早期影响力预测任务中相对强学术 baseline 最高提升 12% 的精度，同时对高影响力 AI 论文具有近乎完整的覆盖并与其未来学术成功持续相关。

## 摘要

> With the rapid pace of AI research and the hundreds of daily new publications, staying up-to-date with the latest developments has become increasingly difficult. For researchers, quickly identifying impactful work is essential, yet manually reviewing each new publication is impractical. Automated impact prediction methods help address this challenge, usually by combining various information sources available, such as a paper's content or citation history. In this work, we propose using GitHub engagement as an additional source and demonstrate that it provides both a timely and accurate signal. To this end, we introduce GitScholar, a novel dataset that links GitHub activity from 444,000 repositories to over 558,000 AI arXiv papers. Our experiments show that GitHub reactions improve early prediction precision by up to 12% over a strong academic baseline. Additionally, we find that GitHub signal offers near-complete coverage of high-impact AI papers, and consistently correlates with future academic success. GitScholar is publicly available at https://huggingface.co/datasets/huawei-csl/GitScholar.

Q1: 这篇论文试图解决什么问题？

【1. 论文要解决的问题域】
论文瞄准的是学术信息过载条件下的“影响力早期识别”问题，具体场景限定在 AI 领域 arXiv 论文。摘要给出的直接动因是：AI 研究推进速度极快、每日新增论文数以百计，研究者已难以持续跟踪全部进展；而对研究者个人而言，尽早识别出真正有影响力的工作又是核心需求，逐篇人工审读在数量上不可行。因此需要自动化/半自动化的影响力预测方法。

【2. 现有信号通道的结构性缺口（合理推断）】
摘要指出已有自动化方法“通常整合论文内容、引用历史等多种可用信息”。据此可推断两条主流信号各有短板：
- 论文内容类信号（标题、摘要、作者、机构、venue、语义表征）在论文发布当刻即可获得，具备及时性，但其对未来影响力的解释力有限，且容易被表面特征（选题热度、写作风格、机构光环）主导。
- 引用历史类信号（引用量、引用网络、早期引用轨迹）被广泛认为预测力强、与“学术影响”定义直接对齐，但存在天然的观测滞后：论文发表后需数月乃至数年才积累起有统计意义的引用，无法支撑“发表后不久就要判断”的需求。
这两者之间构成一个“及时性—准确性”的张力：能及时拿到的信号（内容）不够准，够准的信号（引用）不够及时。

【3. 本文提出的第三条信号通道】
论文主张把 GitHub 互动（repo 侧的 star、fork、issue、PR、贡献者等行为，具体字段清单摘要未披露）作为额外的及时信号。其内在逻辑是（合理推断）：在 AI 领域，大量论文伴随开源实现发布，仓库的互动行为在论文发布后数天到数周内即开始积累，远早于引用，因此理论上可以填补及时性空档，同时因为“有人真的去用/去复现”而带有一定的价值指示性。

【4. 数据层面的缺口】
论文强调 GitScholar 是“novel dataset”，说明作者认为当时的公开资源中缺少大规模、系统化的“论文—仓库”链接语料。其规模口径为 444,000 个仓库与 558,000 余篇 AI arXiv 论文，且明确公开托管于 Hugging Face。缺少此类链接资源会直接阻碍该方向的实证研究与可复现比较。

【5. 任务形式与评价目标（部分为推断）】
从摘要中“early prediction precision”“strong academic baseline”“up to 12%”等措辞可推断，论文把问题形式化为一个二分类/排序式的早期预测任务（预测某论文未来是否属于高影响力），评价指标至少包含 precision，并采用“学术 baseline vs 加 GitHub 信号”的增量式实验设计。论文另外设置了两个非预测型分析：高影响力论文的 GitHub 覆盖率分析，以及 GitHub 信号与未来学术成功的相关性分析。这些分析用于论证 GitHub 信号的“覆盖面”与“方向性正确”，而非直接充当预测模型组件。具体的任务定义、预测时点、标签口径摘要均未给出，需回原文核对。

【6. 论文隐含的前提假设（读者应重点检验）】
- 假设 GitHub 互动是论文学术价值/被采纳程度的有效代理，而非单纯的热度噪声或营销产物；
- 假设 AI 领域（至少是被覆盖的子领域）开源率足够高，使 GitHub 信号具备“接近完整”的覆盖能力——这对偏理论、偏数学或非代码导向的 AI 子领域是否成立，是重要边界条件；
- 假设数据集构建中的论文—仓库链接正确率足够高（链接噪声会同时污染预测实验与覆盖率结论）；
- 假设互动信号与“未来学术成功”之间的相关性不是由共同混杂因子（作者名气、机构、选题热度）驱动。

【7. 问题为什么值得解】
若上述假设成立，该工作可服务于论文推荐、研究趋势监测、科研资源配置与机构评价等下游场景，并为“科学学（science of science）/科研计量”研究提供一个此前缺失的大规模链接型数据基础设施。

Q2: 有哪些相关研究？

说明：本节依据该主题的常规文献版图与摘要线索归纳，属于合理推断与推测，具体被引文献需以原文 Related Work 章节为准。

【1. 学术影响力预测与引用预测】
这是本文最直接的上游脉络。该方向通常分为两类任务：(a) 回归未来引用量；(b) 分类/排序预测论文是否进入高影响力集合（如未来 top-k% 或高被引）。常用信号包括论文内容表征（标题/摘要/全文的文本嵌入）、作者与机构特征、发表 venue、引文网络结构（图神经网络、图表示学习）、以及发表后早期引用轨迹。该脉络的核心局限恰是本文的攻击点：依赖引用的方案在时间上滞后，依赖内容与元数据的方案在准确性上受限。

【2. Altmetrics 与“非引用”影响力信号】
本文把 GitHub 互动定位为额外信息源，这一思路与 altmetrics 文献同源。既有研究考察过 Twitter/X 提及、Mendeley 收藏、博客与新闻提及、下载量等指标与后续引用的相关性及其实用性，争论集中在两点：这些指标反映的是“关注/传播”还是“学术质量”；以及它们是否在时间上真正早于引用并带来增量预测力。本文的工作可视为把 altmetrics 中“代码/仓库”这一支从零散的相关性分析推进为“大规模链接数据集 + 预测任务增量评估”。

【3. 论文—代码链接与软件计量学（software citation / software metrics）】
一条重要邻近脉络研究论文与其开源实现之间的引用关系：包括从论文中抽取仓库 URL/名称、从 README 反解 arXiv ID、以及构建会议级“论文—代码”配对资源的尝试（如 Papers with Code 一类索引）。另一支研究把代码仓库视作科研产出本体，讨论仓库被引用、被复用、被下游依赖的计量方式（software citation、dependency-based impact）。GitScholar 的 444K↔558K 规模正是针对该脉络“数据规模不足”的补位。

【4. GitHub 互动作为关注度代理的实证研究】
已有工作分析 star/fork 增长曲线与项目流行度、社区活跃度、长期存活率的关系，也讨论过 star 数的可操纵性与“热度不等于质量”的问题。本文把这类指标迁移到“论文影响力代理”上，因而会继承该文献的争论：star 是否可被操纵、事件驱动（社交媒体曝光）导致的脉冲式增长是否污染信号。

【5. 科学学（science of science）与影响力动态】
更大的背景脉络包括引用分布的幂律/重尾特征、影响力随时间累积与衰减的动力学、延迟认可（sleeping beauty）现象、以及基于大规模文献计量数据集的实证研究。这一脉络为本文“信号与未来学术成功持续相关”的论断提供了方法论语境与统计检验传统。

【6. 数据集与基准类工作（dataset paper 范式）】
在 AI 与 NLP 社区，数据集论文的评价标准与算法论文不同：贡献主体是可复现的资源、构建流程与基线。GitScholar 明确采取公开发布（Hugging Face）的范式，因此其 related work 中预计会对照既有公开的论文元数据资源（arXiv 元数据、OpenAlex/Semantic Scholar/OpenCitations 等引文资源）与代码托管元数据资源，指出它们在“链接粒度”和“覆盖范围”上的不足。

【7. 潜在未被摘要体现的邻近方向（推测）】
- 冷启动推荐与学术推荐系统：如何在论文刚发布、几乎无历史信息时给出排序；
- 计算社会科学中的“早信号检测”（early signal detection / nowcasting）；
- 研究复现性与代码可用性研究：代码是否公开本身可能既影响引用也影响 GitHub 信号，构成需要控制的混杂。

【8. 与本文的关系定位】
综合来看，本文的 gap 论证可概括为：既有影响力预测主要依赖内容与引用两条通道，缺一条既及时又具价值指示性的通道；而 GitHub 互动这条通道此前缺少与之匹配的大规模、系统化链接数据集，因此无法在统一协议下做严格的增量评估。GitScholar 同时补齐“信号通道”与“数据基础设施”两块。

Q3: 论文如何解决这个问题？

【0. 总体路线】
论文的解决路线可拆成三层：(1) 资源层——构建并公开 GitScholar 数据集，把 GitHub 仓库活动与 AI arXiv 论文大规模对齐；(2) 信号层——把仓库互动当作可早期观测的特征，注入影响力预测模型；(3) 评估层——与一个“强学术 baseline”做增量对比，并辅以覆盖率与相关性两项分析，论证该信号的覆盖面与方向性。

【1. 资源层：GitScholar 数据集构建】
- 规模：444,000 个 GitHub 仓库与 558,000+ 篇 AI 领域 arXiv 论文建立链接。
- 公开方式：托管于 Hugging Face（huawei-csl/GitScholar）。
- 关键但摘要未交代的环节：论文—仓库的链接算法（推测可能混合 arXiv ID 正则抽取、README/论文中的仓库 URL 匹配、Papers with Code 一类第三方索引、仓库名与标题的字符串/模糊匹配，以及去重与噪声过滤规则）；“仓库—论文”是一对一还是一对多/多对多关系；时间戳对齐方式（仓库创建时间与论文发布时间的关系）；以及如何界定“AI 领域”（推测为 arXiv cs.AI/cs.LG/cs.CL/cs.CV 等分类的集合）。这些细节必须回原文或数据集卡片核实，摘要不足以判断数据质量。

【2. 信号层：GitHub 互动的特征化】
- 论文明确将 GitHub 互动称为“GitHub engagement / GitHub reactions”，属于行为计数类信号。
- 具体特征清单摘要未披露。合理推断可能包含：star 数及其时间序列/增长率、fork、watcher、issue 与 PR 数量、贡献者数、提交活跃度、仓库年龄等；也可能包含相对归一化（按仓库年龄或观察窗口归一）以避免“老仓库天然占优”。
- 建模方式未披露。推测可能是把 GitHub 特征与论文元数据/内容特征拼接后交由树模型（GBDT）或神经网络分类器处理，也可能是对不同时间窗口分别训练“早期预测器”。

【3. 任务与标签（推断成分较大）】
摘要中出现的“early prediction precision”提示任务是分类式且强调早期时点；“future academic success”提示标签由论文发表之后累积的引用（或其他学术成功度量）构造，可能是“是否进入高被引/高影响力集合”的二分类，或分位数分档。预测时点（发表后 3/6/12 个月等）、标签窗口长度、是否做时间切分（避免用未来信息训练）均未给出，是复现时的第一优先级核对项。

【4. 评估层：三组证据】
(a) 增量预测实验：强学术 baseline（推测整合论文内容、作者/机构、venue 或早期引用等学术信号）vs baseline + GitHub 信号，报告 precision 提升幅度“最高 12%”。需要注意该数字是相对提升还是绝对提升、是单一最优配置还是跨配置上界，摘要未说明，读者应把它当作需核验的关键量化结论。
(b) 覆盖率分析：检验 GitHub 信号能否覆盖高影响力 AI 论文，结论是“near-complete coverage”。这一分析在方法上等价于论证“信号不会因为大量论文没有仓库而失效”。
(c) 相关性分析：检验 GitHub 信号与未来学术成功是否“consistently correlates”，用于支撑信号的方向有效性，而非证明因果关系。

【5. 方法设计上的取舍】
- 优势取舍：选择 GitHub 互动而非下载量/社交媒体提及，换取“与代码产出的直接绑定”和工程社区活跃度的高时间分辨率。
- 覆盖取舍：限定在 AI 领域 arXiv，牺牲跨学科泛化以换取开源率与仓库生态足够密集，使覆盖率论证成立。
- 评价取舍：以学术引用系统作为 ground truth，意味着模型学习的是“预测引用”而非“预测真实价值”，会把引用文化的偏差（马太效应、venue 效应、社交传播）一并学入。
- 时间性取舍：事件时间点的对齐（论文发布 vs 仓库创建 vs star 突增）若处理不严，容易出现信息泄漏，使早期预测精度被高估。

Q4: 论文做了哪些实验？

【1. 数据集统计与覆盖实验（论文明确报告）】
- 规模统计：444,000 个 GitHub 仓库 → 558,000+ 篇 AI arXiv 论文的链接关系。这是数据集论文的标准首项，用来说明资源的体量与链接密度。
- 覆盖率分析：检验 GitHub 信号对“高影响力 AI 论文”的覆盖程度，结论为 nearly complete。该实验回答的是“有多少真正重要的论文在 GitHub 上有痕迹”，属于信号可用性的下限论证。注意：摘要未披露“高影响力”的判定阈值、覆盖率的分母定义（论文数还是高影响论文数）、以及是否按子领域/年份分层统计，这些需回原文核验。

【2. 早期影响力预测实验（论文明确报告结果，设置未披露）】
- 对比对象：“a strong academic baseline”，即一个只用学术侧信息（推测为论文内容/作者/venue 或早期引用等）的强 baseline。
- 处理条件：baseline + GitHub 互动特征。
- 指标：precision（摘要明确出现该词），报告口径为“up to 12%”的提升。
- 未知项（关键缺口）：预测时点窗口、标签定义与正例比例、数据划分方式（是否按时间切分）、baseline 的具体特征与模型族、是否报告了 recall/F1/AUC/PR-AUC、12% 是相对提升还是绝对百分点的提升、12% 是单一主配置还是跨配置的最大值、是否给出置信区间或多次随机种子的方差。这些直接决定结论强度，摘要不足以判断。

【3. 信号—未来影响相关性实验（论文明确报告结论）】
- 内容：检验 GitHub 信号与未来学术成功之间是否持续相关（consistently correlates）。
- 方法细节未披露：推测可能采用相关系数（Spearman/Pearson）、分位数分层对比或回归控制混杂（年份、venue、作者数等）。
- 解释边界：相关性分析不具备因果识别能力，若未控制作者名气、机构、领域热度等混杂，则不能断言 GitHub 互动“导致”未来引用。

【4. 推测可能包含但摘要未提及的实验（需回原文确认）】
- 特征消融：逐类 GitHub 特征（star / fork / issue / contributor / 增长速率）的贡献拆解。
- 时间窗消融：不同 early 时间点（如 1/3/6/12 个月）下的收益变化趋势，用于论证“信号足够早可用”。
- 子领域分层：cs.LG / cs.CV / cs.CL / cs.AI 等分类下的收益差异，以及理论型论文占比高的子领域是否退化。
- 数据质量实验：论文—仓库链接的人工抽查准确率。
- 基线强度讨论：为何所选 academic baseline 可被称为 strong。
- 负面对照：无仓库论文（cold start）上的表现，用以量化覆盖缺口带来的影响。

Q5: 发现了什么实验现象？

【1. 论文明确报告的现象】

- 现象 B 的合理机制：AI 领域代码发布文化密集，且高影响力论文更可能被社区复现（含第三方复现仓库，若数据集包含此类非官方仓库）。若数据集只收录作者官方仓库，覆盖率结论会显著不同——这是核对重点。
