# Code Plans, Diffusion Renders: Open-Ended Generative World Modeling

> ★★★★☆ 推荐阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：world model · video generation · code generation · diffusion model

## 一句话总结

CoDeR 提出一种分工式世界模型范式：用可执行代码显式构造世界规则与动力学，再由视频生成模型负责视觉渲染，从而在长程记忆、开放式交互、自主世界演化和持久多智能体场景上突破现有视频世界模型的能力边界。

## 摘要

> We introduce \textbf{CoDeR}, a new paradigm for world modeling. Unlike existing video world models that implicitly represent world dynamics through visual observations, our system explicitly constructs an executable world with code and employs video generation models for visual realization. Specifically, we coordinate five complementary roles to translate high-level concepts into structured world rules, executable dynamics, and perceptual observations. This design enables \textit{long-term memory}, \textit{open-ended interactions}, \textit{autonomous world evolution}, and \textit{multi-agent scenarios}, where multiple entities can act, interact, and evolve persistently beyond the current observation. Extensive experiments demonstrate that our framework substantially extends the capabilities of existing world models, enabling long-term memory, open-ended interactions, autonomous evolution, and persistent multi-agent dynamics, while achieving state-of-the-art performance across multiple evaluation settings. Code and model weights will be made publicly available. Project Page: \href{https://becauseimbatman0.github.io/CoDeR}{CoDeR}.

Q1: 这篇论文试图解决什么问题？

1) 论文明确陈述要解决的问题：现有视频世界模型（video world models）把世界动力学「隐含地」表示在视觉观测中，即用像素/潜变量序列的预测过程本身来承载世界状态；CoDeR 认为这种表征方式限制了世界模型的能力上限，于是把能力缺口具体化为四个必须同时满足的目标——长期记忆、开放式交互、自主世界演化、持久多智能体动力学（多个实体能在当前观测之外持续行动、交互、演化）。

2) 对失败机理的诊断（合理推断，摘要未展开）：把状态压进视觉观测通常会带来三类结构性困难。(a) 状态不可寻址：没有显式、可读写的世界状态变量，「记住」只能靠上下文窗口或隐状态，长程会被衰减、覆盖或漂移。(b) 一致性靠拟合而非约束：物体恒存性、物理规则、因果链都是统计意义上成立，长时长 rollout 中误差累积会破坏它们。(c) 交互与演化不可编辑：新规则、新实体、新事件只能通过 prompt 或条件信号软性注入，无法保证被严格执行，也无法被外部程序检查。以上三点是对摘要中「implicitly represent world dynamics through visual observations」的展开解释，属合理推断；原文是否以此论证需回 Introduction 核对。

3) 论文如何重新表述问题：把「世界建模」拆成两个可分离的子问题——世界怎么「算」（用代码显式构造结构化世界规则与可执行动力学），以及世界怎么「看」（用视频生成模型做视觉实现与感知观测）。这等于把「动力学正确性」从生成模型的拟合能力中剥离出来，交给程序性表示；扩散/视频模型退居渲染器角色。这是一个关于「符号-程序表征」与「神经渲染」如何分工的问题设定。

4) 为什么这是真问题而非包装：世界模型研究的核心张力之一，正是「可扩展的视觉真实感」与「可验证、长程一致的因果结构」之间的取舍。纯视频生成路线在真实感上占优但在长程状态维持上吃亏；游戏引擎/符号仿真路线状态精确、可查询、可干预，但内容窄、需大量手工构建、观感受限。CoDeR 试图同时拿两端，因此它真正必须回答的是接口问题：代码侧的状态如何被稳定、可控、可复用地渲染成视频，以及渲染出的观测是否需要（以及如何）回写到代码状态。这个接口是全文最值得审查的技术点。

5) 需要回原文确认的关键问题：五类「互补角色」具体是什么、彼此是流水线还是带反馈的循环；「high-level concepts」的输入形态（自然语言、图像、还是脚本）；世界规则的表示形式（专用 DSL、结构化 JSON、还是通用 Python）；代码执行的沙箱、异常与幻觉代码的恢复机制；（推测）是否存在视觉→状态的逆向感知模块，用于把用户看到的画面转成代码侧的更新。

Q6: 有什么可以进一步探索的点？

1) 代码世界与渲染器的接口标准化：目前「代码状态 → 视频条件」的映射是本范式的核心脆弱点。可探索的方向包括——面向生成的显式状态格式（实体表、场景图、时序事件流）、渲染条件的一致性校验回路、以及渲染结果反哺状态的逆感知模块（把观测转回可执行世界的更新）。这些接口若被标准化，整个方向的可复现性与可比性会显著提升。

2) 规则表示与可验证性：世界规则是用 DSL、结构化 JSON 还是通用代码？不同选择直接影响可验证性（能否形式化检查规则矛盾）、可移植性与 LLM 生成的成功率。一个有价值的方向是把「规则生成」从自由文本代码升级为受约束的、带类型与不变量的规格语言，并配套自动一致性检查与修复。

3) 记忆机制的外化与分层：把长期记忆完全放在代码状态里，会面临可扩展性（状态爆炸）与检索效率问题。可探索记忆的分层——短期在代码状态、中期在结构化事件日志、长期在检索索引——以及记忆压缩与遗忘策略对长程一致性的影响。

4) 评测基准建设：世界模型领域缺少统一基准，而本范式引入了全新的评测维度（代码正确性、状态-观测一致性、交互可恢复性、多智能体持续性）。构建公开、可复核、对纯视频模型与代码-渲染混合模型都公平的基准，本身就是一个高价值研究方向，也能缓解「自建环境自证优越」的质疑。

5) 与真实物理/机器人仿真的衔接：如果可执行世界能被赋予真实物理约束（而非仅程序性规则），该范式就有望用于具身智能的想象-验证循环：在代码世界中推演，用生成模型可视化，再回到真实执行。这条路径对 ai-for-science 与机器人方向的吸引力明确，但需要处理 sim-to-real 的语义差距。

6) 生成模型侧的可控性研究：如何让视频扩散模型忠实服从结构化条件（精确计数、身份保持、空间拓扑、长程身份一致性），是本范式的天花板。相关内容对视频生成社区有独立价值。

7) 成本与可扩展性：双系统（代码执行 + 视频渲染）意味着双重开销。研究渲染的按需触发、稀疏渲染、缓存复用、以及世界规模的 scaling law（规则数/实体数/时长 vs 质量），是该范式能否走向实用的关键。

8) 安全与对齐：能够自主演化且可被代码编辑的世界，天然适合做智能体行为的安全沙箱；反过来，也应研究规则被恶意注入、世界状态被不可逆破坏时的可控停机与回滚机制。

9) 与 LLM/智能体的耦合：五角色协作本身就是一个多智能体系统，可以研究角色分工的最优切分、角色间通信协议、以及在世界模型内部引入自省与规划循环的收益。
