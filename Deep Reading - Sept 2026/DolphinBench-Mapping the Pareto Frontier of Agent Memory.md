# DolphinBench: Mapping the Pareto Frontier of Agent Memory

> ★★★★☆ 推荐阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：agent memory · memory benchmark · long-context agents · task-completion evaluation

## 一句话总结

DolphinBench 主张绕开对话式问答这种「问题本身即检索线索」的记忆评测范式，改为用 agent 的任务完成度直接度量长期记忆能力：构造 3 个知识工作 persona、每人约 500k tokens 的用户消息历史与 200 个任务，并用「带历史必须成功、不带历史必须失败」的双向对照筛选出真正依赖记忆的任务，同时强制所有提交同时报告准确率、总成本与延迟，从而把记忆系统的准确率—成本—延迟 Pareto 前沿本身作为评测对象。

## 摘要

> Agents today often take real-world actions that depend on long-term memory and context recall over time. However, most current memory benchmarks are built for a conversational question-answer format, where the question itself signals that some fact must be retrieved, and often which one. Moreover, benchmarks rarely require anything beyond accuracy from submissions, allowing memory systems to make unreasonable cost/time tradeoffs to achieve higher scores.
> We present DolphinBench, a benchmark that evaluates memory directly through an agent's task completion. DolphinBench includes three knowledge-work personas with roughly 500k tokens of user messages per persona and evaluates agents on tasks that depend on information from that history. We verify all 200 tasks per persona by running an agent with and without the relevant history, requiring success with it and failure without it.
> Finally, we require all evaluations to report total cost and latency alongside accuracy, which enables us to evaluate agent memory systems holistically. No existing memory benchmark combines all three. The dataset and evaluation code are available at https://dolphinbench.ai.

Q1: 这篇论文试图解决什么问题？

一、论文锁定的问题域：agent 长期记忆评测的信度与效度缺口
这篇论文不解决「如何造一个更好的记忆系统」，而是解决「如何判断一个记忆系统更好」。它的攻击面是评测协议本身。摘要给出了两条明确指控，第三条可以从验证协议反推。

二、三重缺陷（前两条为摘要明确主张，第三条为合理推断）
1. 检索线索泄漏（retrieval cue leakage）。现有记忆 benchmark 多为对话式问答：问题一出现，系统就知道「这里要回忆点什么」，很多时候还能从提问措辞判断出要回忆哪一类事实。真实 agent 场景中没有人给出这个提示，agent 必须自己判断当前动作是否需要历史、需要历史的哪一部分、以及回忆结果是否足以支撑行动。QA 形式把「何时检索、检索什么」这个决策环节整体删除了，因此测出的分数与真实记忆能力之间存在系统性偏移。
2. 指标单一导致成本外部化。benchmark 只考核准确率，于是记忆系统可以把成本与延迟当作外部性：无限扩张每轮重放的上下文、对每次查询做昂贵的多路重排与反思式检索、把全部历史原文塞进 prompt。这些策略在纯准确率排行榜上占优，但在真实部署中不可接受。论文的判断是：不报告成本与延迟，就无法对记忆系统做整体评价——这正是标题中 Pareto frontier 的由来。
3. 记忆必要性未经验证（合理推断）。若一个任务在没有历史的情况下也能被答对，那么它在排行榜上的贡献与记忆能力无关。论文用「带历史必须成功、不带历史必须失败」的双向运行来过滤任务，本质上是在为「任务分数上升 = 记忆能力上升」这个因果链条补上构念效度证据。

三、论文的隐含假设（逐条标注强度）
1. 任务完成度可以替代问答准确率作为记忆质量的代理指标——摘要明确主张（evaluates memory directly through an agent's task completion）。
2. 「有/无历史」的成败差异可以归因于记忆能力，而不是模型对任务分布的先验知识、工具可用性差异或采样噪声——这是必要条件假设，论文未在摘要中说明如何控制随机性。
3. 三个知识工作 persona、每人约 500k tokens 的用户消息，足以代表真实长期记忆负载。500k tokens 处于「超出常见上下文窗口、必须依赖检索或压缩」的量级，这是该设定能成立的关键数量级依据（合理推断）。
4. 成本与延迟可被统一计量并跨系统比较。这条最脆弱：不同 provider 的计价、缓存命中策略、并行度都会改变数字，跨系统比较的可比性依赖一套论文未在摘要中说明的计价规范（推测，需查原文的成本核算章节）。

四、边界条件、反例与失败模式
1. 双向验证会系统性排除「部分依赖历史」「多来源冗余」的任务，使任务集合偏向全有或全无式的记忆依赖。这可能高估记忆检索的脆弱性，也可能低估渐进式记忆累积的价值。
2. 单次 with/without 运行受采样温度、工具调用抖动影响，可能产生假阴/假阳任务；论文是否做多次重复与统计检验，摘要未给（信息缺口）。
3. 场景面覆盖单一：个人知识工作者的用户消息历史，缺少多用户共享记忆、跨组织知识边界、对抗性写入（memory poisoning）等情形。
4. 「必须报告成本与延迟」是评测规范而非机制约束。若不设硬性门槛，榜单仍会把高成本高精度系统与低成本低精度系统混排——这恰恰是 Pareto frontier 想解决、但只有靠可视化与分层报告才能真正解决的问题。

论文称「most current memory benchmarks are built for a conversational question-answer format」，所指的很可能是这一类工作：多会话对话记忆基准（如 LoCoMo 一类长对话问答）、长对话记忆评测（如 LongMemEval 一类从历史对话中抽取事实回答提问）、以及各类「记忆问答」数据集。它们的共同结构是：给定历史 + 一个提问 → 要求检索并回答。论文的批评正是针对这一结构中的线索泄漏。

Needle-in-a-Haystack、RULER、∞Bench、LongBench 一类长上下文评测同样把检索任务显式化（提示明确要求找到某个 needle）。DolphinBench 与它们的差别在于：检索需求不由 prompt 显式声明，而由任务能否完成隐含决定。若论文在原文中做对比，这些应是最直接的对标对象。

AgentBench、GAIA、τ-bench、WebArena、OSWorld、SWE-bench、Terminal-Bench 等把评测面从问答转向任务完成，但它们通常不专门构造长期用户历史，也不把记忆必要性作为任务筛选条件。DolphinBench 与这一家族的交集是「任务完成度作为指标」，差异是「以记忆为唯一自变量」。

Q3: 论文如何解决这个问题？

一、总体设计：三个互相约束的支柱
DolphinBench 的解决思路不是改模型，而是改评测协议。摘要中可明确提取出三条设计支柱，三者构成一个互相制约的系统：
1. 评估面替换：从对话式问答换成 agent 的任务完成（task completion）。记忆不再是「被提问的对象」，而是完成任务所必需的条件。这一替换直接消除了检索线索泄漏。
2. 记忆负载构造：三个知识工作 persona，每个 persona 约 500k tokens 的用户消息历史。任务必须依赖这段历史中的信息。
3. 多目标报告：所有评测必须同时给出准确率、总成本与延迟。三者共同定义记忆系统的可行域，标题中的 Pareto frontier 即指这一权衡前沿。

二、任务构造与验证协议（论文最核心的方法论贡献）
每个 persona 200 个任务，三个 persona 共约 600 个任务。关键机制是双向验证（with / without 对照）：对每个任务分别运行「带相关历史」与「不带相关历史」的 agent，要求前者成功、后者失败。
- 逻辑形式：任务 t 被接受 ⇔ (Agent(history_t, t) = 成功) ∧ (Agent(∅, t) = 失败)。
- 这一过滤把「记忆必要性」从假设变成可观测条件，形式上接近反事实对照（counterfactual control），也可视为一种针对任务集的消融筛选。
- 其代价是任务淘汰率可能很高：任何无需历史即可解的任务都被丢弃，这既提高了效度，也带来选择偏差（见下）。

三、评测输出：从单一分数到权衡前沿
要求报告总成本与延迟，使高准确率不再无条件等于「更好」。一个每轮重放 500k tokens 原文的系统与一个只检索少量片段的系统，即使准确率相同，在成本轴上会被清晰区分；反之，一个低成本的快速系统若准确率不足，也必须显式暴露其精度代价。Pareto frontier 的用处在于呈现「不存在同时优于另一系统的系统」这一不可比集合，而不是强行给单一排名。

四、与 QA 式记忆基准的机制对照（基于摘要的对比，属于结构化推断）
- 检索触发：QA 式由问题措辞触发 vs. DolphinBench 由任务需求隐含触发。
- 检索目标：QA 式通常暗示检索哪类事实 vs. DolphinBench 不提示。
- 成功判据：答案匹配 vs. 任务完成。
- 评价维度：仅准确率 vs. 准确率 + 成本 + 延迟。
- 任务有效性验证：通常无 vs. 双向 with/without 验证。

五、隐含假设与技术权衡
1. 验证与评测使用同一 agent harness 的双重身份问题：任务筛选所依赖的「可解/不可解」，本身来自某个具体 agent 的表现。换一个更强的 agent 后，原本「不带历史必失败」的任务可能变成可解，任务集的有效性会随时间衰减。论文是否讨论了任务集的时效性与抗污染性，摘要未提（信息缺口）。
2. 验证成本：每个任务至少两次 rollout，600 个任务即至少约 1200 次 agent 运行；若做多次重复取稳定性，成本线性上升。这本身就是一个「成本意识」的方法论示范，也可能限制社区复现的算力门槛。
3. 筛选偏差：只保留全有或全无依赖的任务，会排除需要跨多会话渐进整合、或历史与其他信息冗余的任务类型，任务集可能偏向记忆推理中的极端情形。
4. 500k tokens 历史的构造方式（合成、脱敏真实记录、还是模板生成）摘要未说明，这直接决定基准的真实性与隐私属性，是阅读原文时最先要确认的问题之一。

4. 检索与使用的两段式失败：即使检索器把正确片段放进上下文，agent 仍可能不使用它——这类失败无法从 QA 式基准中观测到，但在任务完成式评测中会表现为「有历史仍失败」。

一、基准本身的扩展
1. 领域扩展：当前是知识工作 persona，可延伸到生物信息学与科学工作流——例如长期实验记录、试剂批次、失败实验的隐性知识、跨月文献追踪。这与生物/科学应用型研究者的需求高度契合，但需要重新构造 500k tokens 级的真实科学历史与可验证任务。

二、评测协议的方法论加固
1. 双向验证的统计化：单次 with/without 运行有噪声，可引入多次重复 + 显著性检验，或报告任务的稳定性分级（稳定依赖 / 边界依赖 / 偶然依赖）。
2. 任务集时效性与抗污染：随基座模型变强，原本「不带历史必失败」的任务会失效，需要机制化的任务轮换与污染检测。
3. 依赖强度的连续化：把二值化的「必须依赖历史」升级为依赖强度评分（多少个历史片段必需、缺失其一是否仍可解），从而刻画记忆的冗余与鲁棒性。
4. 成本核算标准化：定义统一的计价口径（token、嵌入、检索、重排、缓存折扣、重试），否则跨系统比较的可比性会持续受质疑。
5. 反事实可解释性：在评测中记录「哪些历史片段实际被读取并进入最终决策」，把任务成败与检索轨迹对齐，从结果评测推进到机制诊断。

三、从评测走向训练与系统设计
1. 把成本与延迟作为训练信号的一部分（成本惩罚式 RL 或预算约束解码），直接优化 Pareto 前沿而非单点准确率。
2. 面向 Pareto 前沿的系统选择方法：给定部署预算自动选择记忆配置，而非固定一套检索策略。
3. 记忆写入侧的研究：何时写入、写什么粒度、如何遗忘与合并——当前多数工作聚焦检索侧。
4. 安全与鲁棒性：记忆投毒、越权检索、隐私删除请求（被遗忘权）在任务完成式评测下的表现。

Q7: 总结一下论文的主要内容

一、论文要解决的问题
DolphinBench 是一篇以评测协议为核心贡献的工作，瞄准的是 agent 长期记忆评测的两个结构性缺陷。第一，现有记忆 benchmark 大多采用对话式问答格式，而问题本身就是一个检索线索：它告诉系统「这里需要回忆」，很多时候还暗示了需要回忆哪一类事实。真实 agent 场景中没有这种提示——agent 必须自己决定此刻是否需要历史、需要历史中的哪一部分、以及回忆到的内容是否足以支撑当前动作。这种「检索决策」环节在问答式评测中被整体删除了。第二，现有 benchmark 很少要求准确率之外的任何东西，于是记忆系统可以用不合理的成本与时间代价换取分数：无限扩张每轮重放的上下文、对每次查询做昂贵重排、把全部历史原文塞进 prompt。这类策略在排行榜上有效，在部署中不可行。作者由此提出第三条隐含缺失（由验证协议反推）：很多任务可能根本不需要历史也能完成，因此分数上升未必来自记忆能力提升。

二、技术主线：用三个支柱重构记忆评测
第一根支柱是评估面的替换：DolphinBench 不通过问答，而是通过 agent 的任务完成情况来直接评测记忆。记忆从「被提问的对象」变成「完成任务的前提条件」，检索线索泄漏问题被从结构上消除。
第二根支柱是记忆负载的构造：三个知识工作（knowledge-work）persona，每个 persona 拥有约 500k tokens 的用户消息历史。这个数量级超出了常见上下文窗口，迫使系统必须在检索、压缩或分层管理之间做取舍，而不是简单地全量塞入。任务被设计为依赖这段历史中的信息。
第三根支柱是任务有效性的双向验证。每个 persona 有 200 个任务，三个 persona 合计约 600 个任务。作者对每个任务分别运行带相关历史与不带相关历史的 agent，要求带历史必须成功、不带历史必须失败。这个过滤条件把「记忆必要性」从一个假设变成可观测的对照结果，形式上接近反事实对照，也相当于对任务集做了一次消融筛选。
第四个（报告的）支柱是多目标评测：论文要求所有提交在准确率之外同时报告总成本与延迟。三者共同定义了记忆系统的可行域，论文标题中的 Pareto frontier 即指这一准确率—成本—延迟的权衡前沿。作者明确声称，此前没有记忆 benchmark 同时具备这三项。

三、实验主线
从摘要可见，论文的实验部分至少包含两条线。第一条是任务验证实验：对约 600 个任务逐个执行 with/without 双条件运行，这是一次规模可观的对照筛选实验，其副产品（淘汰率、任务类型分布）本身具有方法学信息量。第二条是系统评测：在通过筛选的任务集上评测若干 agent 记忆系统，并同时记录准确率、总成本、延迟三轴坐标，用于刻画 Pareto 前沿。摘要未披露具体被测系统清单、任何数值结果、消融设计、重复次数与成功判定方式，因此这三轴上的实际排序与权衡形状无法从本次可用材料中获知，必须回到原文的结果章节与 dolphinbench.ai 上的公开代码与数据。

四、贡献与边界
论文的贡献可以概括为：把记忆评测从「问答式准确率排名」推进到「任务完成度 + 记忆必要性验证 + 成本延迟联合报告」的三维框架。其价值主要在于构念效度与部署相关性的提升。边界同样清晰：任务集只保留全有或全无依赖历史的情形，可能低估渐进式记忆累积的价值；单次双向验证受采样噪声影响，任务集会随基座模型变强而失效；场景限于个人知识工作者的用户消息历史，未覆盖多用户共享、跨模态与对抗性写入；成本核算口径未在摘要中说明，跨系统比较的可比性有待核实。此外，本条目元数据发布日期为 2026-09-21，若早于当前时间，应视为预发布或占位元数据。
