# ContextPilot: Teaching Agents for Proactive Context Management via Fine-grained RL

> ★★★★☆ 推荐阅读 · 模型 openai-compatible/deepseek-v4-flash

🏷 关键词：long-horizon agent · context management · proactive memory · reinforcement learning

## 一句话总结

ContextPilot 通过扩展规划、长期记忆与软上下文卸载工具，并设计基于上下文变化与熵变化识别关键编辑决策、从分支轨迹估计动作级优势的细粒度强化学习算法，使长视界智能体在更紧凑的工作上下文下取得更强的长上下文问答与深度搜索性能。

## 摘要

> Long-horizon agentic tasks require large language models (LLMs) to iteratively retrieve, integrate, and maintain dispersed information across multi-turn interactions, but preserving all interaction histories leads to a continuously growing working context. Recent proactive context management methods allow models to edit their own working context with specialized tools, yet they still face three key limitations: (1) a limited toolset restricted to search, deletion, and summarization, with no support for global planning, long-term memory, and adaptive compression; (2) inefficient exploration that treats context management actions uniformly despite their heterogeneous impacts on final outcomes; and (3) coarse-grained credit assignment that assigns the final trajectory-level reward to all intermediate context editing actions during RL. To bridge these gaps, we introduce ContextPilot, a proactive context management framework for long-horizon agentic reasoning. Our approach systematically augments the toolset with planning, long-term memory, and soft context offloading tools. We further propose an RL method tailored for context management, which uses context and entropy variation to identify critical editing decisions for branch sampling and estimates action-level advantages from all branched trajectories that pass through the corresponding context editing action. Experiments on long-context QA and deep search tasks show that ContextPilot achieves stronger performance with a more compact working context, consistently outperforming existing baselines across various base models and benchmarks. Code is available at https://github.com/Tencent/ContextPilot.

Q1: 这篇论文试图解决什么问题？

长视界智能体任务（如长上下文问答与深度搜索）要求大语言模型在多轮交互中不断检索、整合并维护分散的信息。若将全部交互历史保留在工作上下文中，输入长度将随轮次线性增长，导致计算开销增大、相关信号被无关噪声淹没，最终损害推理质量。为此，最近的研究开始探索主动上下文管理范式：允许模型通过专用工具编辑自身工作上下文，例如删除无关内容、调用搜索工具获取新证据、对旧信息做摘要压缩。这一范式赋予模型一定的自我调节能力，但现有实现仍存在三个系统性缺陷。
第一，工具集过于狭窄，通常仅限于搜索、删除与摘要三类操作，缺少面向全局规划的机制（例如在任务开始前确定信息获取顺序）、长期记忆机制（跨回合保存结构化实体与事件关系）以及自适应压缩机制（根据内容重要性与任务阶段动态决定压缩程度）。这些缺失使得模型只能在局部做“修补”，难以在长视界中形成稳定的问题求解结构。
第二，上下文管理动作的探索效率低下。不同编辑动作对最终奖励的影响高度异质——一次关键信息保留可能决定最终答案，而多次无关删除可能影响甚微。现有方法常将所有上下文管理动作视为同等重要的训练信号，均匀采样或均匀分配奖励，导致模型难以区分关键决策与例行操作，样本效率低。
第三，信用分配粒度粗糙。在强化学习训练中，常见做法是将整条轨迹的最终奖励回传给轨迹内所有中间动作，包括每次上下文编辑。但上下文编辑通常有延迟后果：一次编辑可能在数轮之后才显现其价值或危害，而轨迹级奖励无法准确刻画这种时间延后且异质的因果贡献。
这三个问题相互叠加，使得现有主动上下文管理方法在长视界任务中性能受限：要么上下文不断膨胀，要么信息丢失严重，要么训练不稳定。ContextPilot 正是针对这三项缺口提出系统性方案。

Q2: 有哪些相关研究？

与本文相关的已有研究可分为几个脉络。第一类是面向长上下文的基础模型与推理技术，例如改进注意力机制以支持更长输入，或采用检索增强在需要时获取外部证据。这些方法通常把工作上下文视为静态的、一次性给定的输入，模型缺乏在运行过程中主动改变上下文的能力。
第二类是智能体系统中的显式记忆管理，例如使用外部数据库存储对话历史或知识，通过读写接口与模型交互。这类方法将记忆外置，模型需要学习何时写入与读取，但它们往往以某种固定协议运行，缺少对记忆内容的细粒度编辑和自主压缩。
第三类是近期出现的可学习上下文编辑方法，代表工作如 StateLM——在智能体运行中引入状态编辑工具，允许模型通过搜索、删除、摘要等操作改变自身工作上下文。ContextPilot 在方法上直接继承 StateLM 的基础工具集，并在此基础上扩展。本文的差异化贡献在于：其一，将全局规划与长期记忆纳入上下文管理动作空间，使其不再局限于即时的局部修正；其二，针对上下文管理任务的特点设计专门的强化学习训练范式，而不是套用通用的稀疏奖励 RL。
在强化学习用于智能体方向，相关工作包括基于轨迹级奖励的策略梯度方法、过程奖励模型、以及通过树搜索或分支采样改进信用分配的技术。这些工作通常面向通用 agentic 任务，而 ContextPilot 关注的是上下文编辑动作的特殊性——它们对最终结果的贡献具有强稀疏性、时间延迟与相互耦合。本文提出的基于上下文与熵变化的动作重要性识别，以及从多个分支轨迹中估计动作级优势的做法，可视为将过程奖励思想与蒙特卡洛分支采样结合的一种定制化方案。
此外，在长上下文问答与深度搜索这两个评测场景上，相关研究大多通过增大模型窗口尺寸或引入检索器来提升性能；本文则从 agent 的主动上下文管理视角切入，显示在相同或者更小的上下文预算下可以达到更好的效果。与纯粹的上下文压缩方法（如 token 剪枝或摘要）不同，本文允许模型根据任务需求动态调度保留、卸载与回忆动作，从而在信息可用性与上下文大小之间取得更优权衡。
总体而言，ContextPilot 处于“可编辑上下文 + 细粒度 RL 信用分配”的交叉点，对智能体自我管理能力的研究具有推进意义。需要说明：由于当前证据主要来自摘要与语义检索片段，上述组织基于通用领域知识进行归类，具体参考文献列表需查看原论文。

Q3: 论文如何解决这个问题？

ContextPilot 的解决方案分为工具扩展与强化学习算法定制两个层次。
第一层：上下文管理工具集。以 StateLM 的基础工具集为起点，系统性地加入三类新工具。（a）规划类工具：使模型能够在任务早期制定信息获取与处理计划，并根据执行进展更新计划，从而将长视界任务拆分为有序子目标，避免盲目检索。（b）长期记忆工具：核心是 memorize 工具。它从当前工作上下文或新增信息中提取结构化知识，包括实体、时间戳与事件片段，并在相关记忆之间建立边关系，形成图结构或类似图结构的长期记忆库。该记忆库可跨回合持久化，在后续需要时可被检索回工作上下文。这里的具体检索与遗忘机制，原论文未在摘要中展开，属于合理推断。（c）软上下文卸载工具：与硬性删除不同，软卸载保留信息的可恢复性，提供 summarizeContext、compressContext 与 foldHistory 三个操作。summarizeContext 对指定片段生成摘要，保留高层语义；compressContext 以更紧凑的表示压缩上下文；foldHistory 将较旧的历史折迭打包，减少对当前推理的干扰。这三者构成由浅入深、由细到粗的压缩梯度，模型可根据内容重要性与任务阶段选择合适粒度的压缩。
第二层：面向上下文管理的强化学习算法。作者指出已有的 RL 方法存在两个问题：均匀探索导致高效动作被稀释；轨迹级奖励全部赋给中间编辑动作，信用分配粗糙。为此提出两步机制。（1）关键编辑决策识别：利用上下文变化与熵变化来度量每个上下文编辑动作对系统状态的影响程度。上下文变化反映工作集被修改的比例或信息距离；熵变化反映模型预测不确定性的改变。高影响的动作——如大规模压缩或关键记忆写入——被判定为关键编辑决策，并围绕它们进行分支采样。（2）动作级优势估计：从所有经过同一上下文编辑动作的分支轨迹中聚合结果，估计该动作的优势值。由于分支共享该动作的前缀，其后续回报差异可归因于该动作的不同继任行为，从而得到比轨迹级奖励更细粒度的信用分配。具体实现细节（如分支数量、基线的选取、熵计算的具体形式）需要查阅原论文。
整体上将工具使用策略与 RL 策略联合优化，使模型学会在长视界推理中动态决定何时检索、何时压缩、何时保存记忆，从而用更紧凑的工作上下文完成更复杂的推理。训练过程还体现了渐进行为迁移：随着训练推进，检索工具使用占比下降，规划、记忆与卸载工具使用占比上升，说明 RL 有效引导模型从“拼命找信息”转向“经营好已有信息”。

Q5: 发现了什么实验现象？

围绕证据中的三个关键观察进行展开。
观察一：能力提升与上下文压缩同时发生。在表 2 中，ContextPilot 以 32K 上下文窗口运行，却在长上下文问答中超过使用 128K 上下文窗口的 backbone 模型。这说明主动上下文管理不仅能节省 token，还能通过移除噪声、保持关键信息来提升推理质量。这是反直觉的：传统观念中更大的上下文窗口总归是有益的，然而当上下文由多轮累积的冗余信息主导时，聚焦的上下文比无限膨胀的上下文更有效。
观察二：跨任务与跨基座的泛化。表 2 与表 3 分别覆盖长上下文问答与深度搜索，ContextPilot 在两类任务上都稳定优于 baseline；同时，优势在不同基座模型间保持。这说明该方法的收益不是对某一特定任务或某一大模型的过拟合，而是来自通用的上下文管理能力。
观察三：工具使用模式随训练演进。进一步分析显示，随着训练推进，信息检索工具的使用占比逐渐下降，而规划与感知、长期记忆、上下文卸载工具的使用占比呈上升趋势。这一现象解释了训练的动态：模型在初期依赖大量检索来获取信息，逐步学会将关键信息存入长期记忆、通过压缩释放工作上下文、并依靠规划减少不必要的检索，最终形成更“老练”的上下文管理行为。
除了上述被证据明确的观察，还可以从摘要中提取一些实验现象（标注为合理推断）：上下文更紧凑意味着更低的推理延迟与成本，即使在没有显式性能提升的任务上，token 效率也可以视为一项正面结果。另外，在深度搜索任务中，模型可能需要多次迭代搜索，长期记忆与卸载工具可以避免搜索历史把工作区占满，从而支持更深层搜索。
关于失败案例与负结果：现有检索证据未覆盖失败案例。一个可预期的挑战是过度压缩造成的不可逆信息丢失：如果模型在早期错误地折叠了关键证据，后续可能无法恢复。论文的软删除设计（soft-deletion）或许起到缓解作用，但具体鲁棒性未在证据中体现。
指标间张力：性能提升与上下文压缩之间的权衡——ContextPilot 的亮点是二者兼得，但我们应意识到其他方法可能为压缩而牺牲性能；本文认为这种反向张力是其技术优势所在，但需要更多数据验证。
总的来说，实验证据支持“主动、有选择地管理上下文优于被动地扩大窗口”这一核心结论。

Q6: 有什么可以进一步探索的点？

基于论文自身指出的局限与领域前沿，可探索的方向包括以下几个方面。
第一，更丰富的上下文管理操作。当前工具集虽已有规划、长期记忆与软卸载，但可能仍不覆盖所有形态，例如跨会话的上下文重构、按需解压/还原原始细节、基于用户意图的上下文过滤，以及多粒度混合压缩。可以将上下文管理视为一个可学习的程序合成问题，让模型动态生成新的管理操作。
第二，更精细的动态压缩时机。目前模型决定何时压缩，但压缩程度的自适应仍有空间，例如根据剩余任务长度、当前信息冗余度与错误恢复成本来调整压缩比例。
第三，长期记忆的图结构演化。memorize 构建实体-事件关系边，未来可以研究记忆的遗忘曲线、置信度更新、冲突消解，以及与外部知识库的互操作。
第四，核心的 RL 方法可进一步泛化。当前用上下文变化与熵变化识别关键动作，未来可以引入更多信号，如代表价值函数变化、信息论度量、或基于因果影响的指标；分支采样成本也可通过模型蒸馏或价值模型辅助的离线估计来降低。
第五，更复杂的任务与评测。长上下文问答与深度搜索仍有边界，可扩展到多智能体协作、工具调用密集的软件开发、科学文献综述等场景，验证上下文管理在更长视界（数百轮）下的可持续性。
第六，鲁棒性与安全性。过度压缩导致的信息丢失是潜在失败模式，需要设计可恢复性机制，例如软删除的撤销或重新查询；同时，允许模型自主修改工作记忆也带来了审计与可解释性挑战，需要建立监控与干预手段。
第七，与模型架构的协同。长上下文模型（如稀疏注意力或状态空间模型）与主动上下文管理可以互补——架构提供更大的原始容量，管理策略决定如何最优使用该容量，未来可联合设计。
对于 ai-for-science 场景，可将该框架用于科研文献的深度调研、多文档证据链构建、实验方案规划等，论文的开放代码便于在特定领域数据上二次开发。

Q7: 总结一下论文的主要内容

ContextPilot 是一项针对长视界智能体推理中工作上下文无限膨胀问题而提出的主动上下文管理系统。论文的论证主线是：现有主动上下文管理方法虽然允许模型通过工具编辑自己的工作上下文，但受限于工具集不全、探索效率低下和信用分配粗糙，无法在长视界任务中充分释放潜力。
技术主线上，ContextPilot 做了两层设计。工具层：在 StateLM 的基础工具集上，新增规划工具以支持全局任务拆分与执行顺序安排；新增长期记忆工具 memorize，从上下文中抽取实体、时间戳和事件片段，并在相关记忆间建立边，形成可跨回合持久化的结构化记忆；新增软上下文卸载工具 summarizeContext、compressContext 与 foldHistory，提供不同粒度的压缩和折叠，使模型可以在不彻底丢失信息的前提下释放工作空间。训练层：设计了面向上下文管理的 RL 算法。该算法首先用上下文变化量与熵变化量识别对最终结果影响显著的关键编辑决策，然后对这些关键决策进行分支采样，最后从所有经过同一编辑动作的分支轨迹中估计动作级优势，从而将信用分配到具体的编辑动作而非整条轨迹。两个层结合，模型得以学会在检索、规划、记忆写入和上下文压缩之间动态调度资源。
实验主线上，论文在长上下文问答和深度搜索两个任务上开展评测，并与多个基线及不同基座模型对比。关键结果包括：在表 2 中，ContextPilot 仅用 32K 工作上下文就超过了使用 128K 上下文的 backbone，证明了“紧凑上下文 + 智能管理”优于“庞大数据 + 被动读取”；表 2 和表 3 显示性能优势跨任务和基座一致成立；进一步分析表明训练过程中模型逐渐减少对检索工具的依赖，而增加对规划、记忆和卸载工具的使用，显示出 RL 训练塑造了更主动的上下文管理行为。
结论上，论文认为主动上下文管理是一条值得深入的方向，并指出当前工具集仍可能不完备，未来需要更丰富的上下文操作。同时，论文开放了代码，便于社区复现和扩展。本文的主要局限在于：工具集仍可能不覆盖所有场景，对压缩失当的鲁棒性以及 RL 训练成本未在现有证据中详细讨论。
